FREE SPACE
  vacuum::DiskSpace is an injected trait, matching todo 81's LivenessProbe and todo 82's
  RemoteUnshare. SystemDiskSpace calls rustix::fs::statvfs and computes
  f_bavail * (f_frsize or f_bsize). rustix 1.1.4 with feature "fs" was ALREADY in
  Cargo.lock (tempfile pulls it), so the manifest gained an edge and Cargo.lock gained
  ZERO packages. The syscall's unsafe stays inside the dependency, so oc-db still honours
  unsafe_code = "forbid". No subprocess, so a stripped PATH is fine (verified above).
  `cargo add fs4 --dry-run --offline` -> "could not be found in registry index";
  `cargo search` is unusable here (aliyun mirror replacement), as the worktree notes say.

WAL AND MEASUREMENT RELIABILITY
  Every size is read by re-stat'ing the file; nothing is cached. vacuum() issues
  PRAGMA wal_checkpoint(TRUNCATE) before it measures and again after the rewrite,
  because open.rs's PRAGMA_SEQUENCE puts every connection in WAL mode
  (database.ts:22-33) and a delete's pages land in -wal until a checkpoint. PASSIVE
  would leave -wal at its high-water mark. One test asserts main_bytes ==
  page_size * page_count after a truncating checkpoint, and another asserts an
  uncheckpointed prune shows up as wal_bytes > 0 with main_bytes unchanged.
