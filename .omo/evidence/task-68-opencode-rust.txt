SCOPE
-----
Only `crates/oc-goal/**` and the dependency edges recorded in `Cargo.lock` were
changed. No engine, generic tool, database-schema, or tools-crate source was
modified.

WHAT WAS BUILT
--------------
- `GetGoalTool`, `CreateGoalTool`, and `UpdateGoalTool`, with structured output,
  positive-budget validation, and model-correctable policy refusals.
- A model-facing update schema that exposes only `blocked` and `complete`.
- A persistent three-signal blocked audit: `blocked` is accepted only after three
  matching failure signals survive in `goal_1.db`.
- Hidden goal context regenerated from SQL for every request as a synthetic
  pseudo-user `TranscriptEntry`; it is XML-escaped and is never persisted in the
  conversation that compaction may discard.
- Guarded self-continuation requiring all of: no process-local concurrent start,
  no active engine turn, not in plan mode, no queued user input, no pending
  one-shot deferral, and an active goal.
- Persistent one-shot deferral and failure streaks in auxiliary tables in the
  existing goal database, without changing the existing `goal` table.
- Terminal provider/compaction failures immediately block an active goal so a
  failed terminal turn cannot spin forever.

PERSISTENCE
-----------
`GoalStore` creates two auxiliary tables in `goal_1.db`:

  goal_continuation_deferral
  goal_failure_streak

They deliberately have no session foreign key, for the same restart/compaction
survival reason as the `goal` table. Replacing or resuming a goal clears stale
auxiliary state.

GUARD AND AUDIT COVERAGE

three-matching-signal threshold, clearing mismatched streaks, and terminal-error

active-goal replacement refusal, and the blocked audit.
