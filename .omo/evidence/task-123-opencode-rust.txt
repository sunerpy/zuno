Task 123 — remove the intermittent allocation that breached G2
Measured: 2026-08-09

ROOT CAUSE

The suspected shared EventService was not the source. The intermittent roughly
164 MiB step came from startup compaction's owned transcript construction.
`transcript_owned` first let `project_history_owned_with_ids` aggregate every
complete provider-projected message, including all complete tool results, and
only the later compaction representation reduced those results. On the pinned
W-real session, that made the complete projected tool payloads coexist long
enough for the frozen two-second sampler to observe the extra allocation.

The fix adds `map_project_history_owned_with_ids`, which transforms each
projected message before projecting the next stored message. `transcript_owned`
estimates tokens from the complete provider-visible message first, then converts
that message immediately to the existing summary-safe representation. Therefore:

  * boundary selection still charges the complete provider-visible history;
  * no prompt-required history or token weight is dropped;
  * ordinary borrowed and owned provider projection remains complete and
    byte-equivalent; and
  * startup compaction retains at most one complete projected stored message
    before reducing its tool output.

REGRESSION AND MUTATION PROOF

`owned_compaction_transcript_charges_full_tool_output_before_truncating_it`
hydrates a 2 MiB completed tool result and pins both sides of the invariant: the
owned compaction entry has the same estimated token charge as the complete
borrowed transcript, while its retained tool result is exactly
`TOOL_OUTPUT_MAX_CHARS` plus the existing `\n[truncated]` marker.

Mutation proof was run before the final gate. Restoring the old aggregate-first
path made the test fail because the retained tool result had 2,097,152 chars
instead of 2,012. Restoring the fix made the test pass. A temporary 1 ms RSS
probe then measured projection increments of only 20, 16, and 20 KiB over
hydration in three runs, versus the prior 169,944–169,960 KiB increment. The
probe and its outputs were removed before final validation.

SCOPE CORRECTION AFTER MEASUREMENT

Final diff review found that the borrowed `transcript()` path had also been
changed to summary-safe messages even though the allocation only belonged to the
owned startup path. That unrelated semantic change was removed: borrowed
transcripts again retain complete provider projection, while the measured
`transcript_owned` optimization is unchanged. W-real startup compaction calls the
owned path. The complete validation below was run after this scope correction;
the expensive frozen measurement itself was not repeated because the measured
owned path did not change.
