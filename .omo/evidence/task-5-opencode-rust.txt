CONCLUSIONS DRAWN (each is enforced by a named test below):
  1. OPENCODE_LOG_LEVEL is uppercased then looked up in a 4-key map
     {DEBUG,INFO,WARN,ERROR}; anything else silently becomes INFO. TRACE is NOT
     accepted. The CLI --log-level offers the identical four choices.
  2. OPENCODE_PRINT_LOGS is compared with === "1" -- NOT via the truthy()
     helper at flag.ts:3-6 that most other OPENCODE_* booleans use. So
     OPENCODE_PRINT_LOGS=true does NOT enable printing.
  3. Printing is ADDITIVE: [fileLogger(), stderrLogger], never a replacement.
     The added sink is process.stderr. Never stdout.
  4. log dir = path.join(xdgData, "opencode", "log") = $XDG_DATA_HOME/opencode/log

# ORACLE-PARITY SPOT CHECKS (the semantics easiest to get subtly wrong)
################################################################################

-- OPENCODE_PRINT_LOGS === "1" only. flag.ts:3-6's truthy() would ALSO accept
   "true", but logging.ts:68 does not use truthy(). Matching truthy() here would
   be a silent divergence. Demonstrated on the real binary:

   OPENCODE_PRINT_LOGS="1"    -> stderr_records=1  file_records=1  stdout_records=0
   OPENCODE_PRINT_LOGS="true" -> stderr_records=0  file_records=1  stdout_records=0
   OPENCODE_PRINT_LOGS="TRUE" -> stderr_records=0  file_records=1  stdout_records=0
   OPENCODE_PRINT_LOGS="yes"  -> stderr_records=0  file_records=1  stdout_records=0
   OPENCODE_PRINT_LOGS="0"    -> stderr_records=0  file_records=1  stdout_records=0
   OPENCODE_PRINT_LOGS=""     -> stderr_records=0  file_records=1  stdout_records=0
   Only "1" turns the stderr sink on. The file sink is unconditional in every
   case (printing is additive, per logging.ts:68). stdout is always 0.

-- OPENCODE_LOG_LEVEL is uppercased then looked up in a 4-key map; anything else
   silently becomes INFO (logging.ts:57-64). TRACE is NOT one of the four.

   OPENCODE_LOG_LEVEL="DEBUG" -> resolved=DEBUG  file: trace=0 debug=1 info=1 warn=1 error=1
   OPENCODE_LOG_LEVEL="debug" -> resolved=DEBUG  file: trace=0 debug=1 info=1 warn=1 error=1
   OPENCODE_LOG_LEVEL="INFO"  -> resolved=INFO   file: trace=0 debug=0 info=1 warn=1 error=1
   OPENCODE_LOG_LEVEL="warn"  -> resolved=WARN   file: trace=0 debug=0 info=0 warn=1 error=1
   OPENCODE_LOG_LEVEL="ERROR" -> resolved=ERROR  file: trace=0 debug=0 info=0 warn=0 error=1
   OPENCODE_LOG_LEVEL="TRACE" -> resolved=INFO   file: trace=0 debug=0 info=1 warn=1 error=1
   OPENCODE_LOG_LEVEL="trace" -> resolved=INFO   file: trace=0 debug=0 info=1 warn=1 error=1
   OPENCODE_LOG_LEVEL="BOGUS" -> resolved=INFO   file: trace=0 debug=0 info=1 warn=1 error=1
   OPENCODE_LOG_LEVEL=""      -> resolved=INFO   file: trace=0 debug=0 info=1 warn=1 error=1
   TRACE resolves to INFO and records no trace line -- exactly the oracle's
   behaviour. TRACE is reachable only through LogConfig::directives, which is
   programmatic and so cannot diverge from a user's environment:
