Bound ownership decision
------------------------
- The existing transport cap and the requested retry deadline are both user-visible upper bounds on waiting for a provider, and both are exactly 180 seconds. FU-7 will define that duration once in the lowest shared crate (`oc-llm`) and derive both the compatible transport cap and engine retry deadline from it.
- Rejected: two private `Duration::from_secs(180)` constants. Although one is an idle-window cap and one is a total retry cap, duplicating the literal allows exactly the independent drift FU-7 is meant to prevent. The semantic call-site names remain local; the numeric policy has one owner.

Colour and TTY idiom
--------------------
- TUI views never name literal colours; `ViewContext::error()` resolves `palette.error` and is already used for failed tool rows. The retry notice will use that renderer while preserving rollback's mandatory clearing of attempt-local parts.
- The plain `run` surface has no styling dependency. The workspace already uses standard-library `IsTerminal` in `run.rs`, and `oc-observability` gates stderr ANSI with `std::io::stderr().is_terminal()` while forcing file output to `with_ansi(false)`.
- Decision: use the existing `IsTerminal` gate plus the minimal SGR red/reset sequences for this one stderr notice. Rejected: adding a styling crate for one message; it would enlarge the dependency surface without improving capability. The rendering seam will accept an explicit colour flag so tests can prove both TTY-red and non-TTY escape-free bytes.

Deadline implementation
-----------------------
- `oc_llm::sse::MAX_PROVIDER_WAIT` now owns the shared 180-second policy. `oc-provider-compatible` derives its override cap from it, and `oc-engine` derives `PROVIDER_RETRY_MAX_ELAPSED` from it; there is no second numeric literal to drift.
- `ProviderRetryPolicy` carries the elapsed budget independently of `max_attempts`. `retry_provider_with_sleep` records one Tokio `Instant`, applies one absolute deadline to provider operations, rollback emission, and backoff sleeps, and refuses a delay that cannot fit. A blocked event consumer or provider operation therefore cannot leak beyond the same total budget.
- Deadline expiry is typed as `ProviderRetryError::DeadlineExceeded { attempt, elapsed }` and maps to `TurnError::ProviderRetryDeadlineExceeded`; it is not mislabeled as attempt exhaustion and no error string is parsed.
- The paused-clock total test now covers three compositions: production attempts × 120s, ten times the production attempts × 120s, and production attempts × a 240s idle window. All finish at or below 180s. Focused result: 1 passed / 0 failed in 0.00s.
- Existing retry regressions remain green: all 10 `oc-engine/tests/retry.rs` tests and all 3 `loop_provider_retry*` production-path tests passed. The latter retain transient 503 replay/rollback, finite final-error propagation, and permanent-error no-replay behavior.

- On a TTY the exact bytes are `\x1b[31m...\x1b[0m\n`; off-TTY they are plain UTF-8 plus newline and the test asserts byte `0x1b` is absent. This follows the workspace's `IsTerminal` convention and adds no styling dependency.

Rendering uses `ViewContext::error()` (the theme's error/red colour), never a literal ratatui colour; the successful replay text becomes a separate later part and the discarded text cannot render twice.
