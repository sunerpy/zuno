Task 162 — carry advertised model endpoints into production surface selection
Closes F4's wave-10 provider blocker.

ROOT CAUSE AND UPSTREAM SHAPE
--------------------------------------------------------------------------------
Upstream's GitHub Copilot model hook maps `supported_endpoints` into
`api.endpoint`, and provider selection checks that explicit value before its
model-id heuristic. The Rust compatible provider already read the
`modelEndpoints` option, but production never supplied it: resolved `ModelApi`
contained only id/npm/url, and plugin model deserialization silently dropped
`api.endpoint`.

PRE-FIX REPRODUCTION
--------------------------------------------------------------------------------
Command:
  cargo test -p oc-cli --offline production_copilot_advertised -- --nocapture

Both new production tests failed before the implementation:
- `mai-code-1-flash-picker`, advertised `responses`, selected
  `/v1/chat/completions` instead of `/v1/responses`.
- `gpt-5`, advertised `chat`, selected `/v1/responses` instead of
  `/v1/chat/completions`.

IMPLEMENTATION
--------------------------------------------------------------------------------
- `ModelEndpoint::{Chat, Responses, Messages}` is a lowercase serde enum.
- `ModelApi.endpoint` is optional and omitted from serialized output when absent.
- Pinned catalog construction initializes it to `None`; model merge preserves an
  endpoint already supplied by resolved/plugin metadata.
- `model_spec` derives `modelEndpoints` using `model.api.id`, not the catalog key,
  and only when the endpoint is present. The existing model-id heuristic remains
  the fallback.
- The sole direct `oc_llm::ModelApi` test literal was updated with `endpoint: None`.

PRODUCTION REGRESSION AND MUTATION PROOF
--------------------------------------------------------------------------------

replace the provider's model map, call production `model_spec`, and replay the
selected provider request.
