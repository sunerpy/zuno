* Legacy `Model` uses `providerID` and omits internal/v2-only `family`, `release_date`,

the single-env and stored-API paths can populate `key`; `toPublicInfo` removes functions and
invalid models before plugin calls. Provider hooks and small-model hooks receive that public
provider shape, while `Auth.loader` receives a public provider clone.

IMPLEMENTATION AND STRUCTURAL CHECK
--------------------------------------------------------------------------------
`crates/oc-plugin/src/js/projection.rs` is now the one JavaScript model/provider codec.

* `model_value` emits exact legacy or v2 SDK models. Both use `providerID`; legacy strips the
  v2/internal-only fields, while v2 retains its declared fields. Both omit Rust's `api.endpoint`
  extension on egress.
* `provider_value` emits `id/name/source/env/key?/options/models` only and recursively projects
  every model at the requested generation. Source comes from `ProviderContext` for request hooks
  or canonical availability precedence for resource callbacks; an API/WellKnown credential
  supplies the optional key.
* `plugin_model` normalizes SDK `providerID` back to canonical `provider_id` before strict
  `ResolvedModel` decoding. It serves ProviderHook.models and small-model output.
* `plugin_provider` decodes Auth.loader's mutated legacy provider and recursively normalizes
  models. For models that existed before the call, it restores fields the legacy SDK cannot
  express (`family`, `release_date`, `variants`, `interleaved`, `limit.input`, `api.endpoint`),
  so a no-op loader remains byte-identical; newly inserted SDK models receive canonical defaults.
  Provider availability is likewise retained internally rather than trusting plugin input.

The ordinary-hook structural check is `HookModelBoundary::classify`, an exhaustive match over
the authoritative `HookInvocation` enum. Every current variant is classified as model selection,
legacy context, legacy model, v2 provider+model, or none; encoding branches assert the expected
classification and call only the typed `SdkValue` projectors. Adding a new hook variant cannot
compile until the author makes a reviewer-visible boundary classification. Resource callbacks
are not HookInvocation variants, so both call the same private `SdkValue`/plugin decoder API in
`bridge.rs`; there is no duplicate ad-hoc provider/model codec left there.
