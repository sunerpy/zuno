0. THE MEASUREMENT THAT CHOSE THE ROUTE
===============================================================================
The plan offered two routes: (a) omit `google` from the initial catalog if
production behaviour permits, or (b) assert a detail that exists only after
antigravity executes. Both were measured first, because F2-B1's own lesson is
that a mutation must be proven to change behaviour before it is trusted.

Probe: the real production CLI (target/debug/opencode-rust, freshly built),
`env -i` with exactly the test's environment, `models --verbose`, twice:
  WITH    plugin = [antigravity@1.6.0, kiro-auth@0.20.6]
  WITHOUT plugin = [kiro-auth@0.20.6]
Both runs: 2944 lines of stdout. `diff with-ag.txt without-ag.txt` -> EMPTY.
stderr identical (empty) in both runs.

  $ wc -l with-ag.txt without-ag.txt
    2944 with-ag.txt
    2944 without-ag.txt
  $ diff with-ag.txt without-ag.txt && echo IDENTICAL
  IDENTICAL: antigravity contributes NOTHING to models --verbose

Route (a) is therefore IMPOSSIBLE, and this is a correction to the todo's
premise. Omitting `google` from the catalog does not make antigravity's
contribution appear; it makes the `google` row disappear entirely. Measured:
  plugin=[antigravity,kiro], auth={"kiro-auth":...}   -> no google row at all
  plugin=[antigravity,kiro], auth={"google":{"type":"oauth",...},...} -> none
`models` never shows a google row unless the catalog declares one.

WHY (read from source, not guessed):
  * `crates/oc-cli/src/cmd/models.rs:92-127` dispatches exactly two hooks:
    `HookInvocation::Config` and `HookInvocation::Provider`.
  * kiro-auth registers BOTH (`dist/plugin.js:68` config, `:424` provider), so
    its models reach plain stdout — that is why the kiro half of the old test
    was a real guard.
  * antigravity registers `event`, `tool` and `auth` ONLY
    (`dist/src/plugin.js:1138-1143`). It has no config hook and no provider
    hook, so on the `models` surface it is inert by construction.
  * `models.rs:109-111` additionally requires the provider to already exist in
    the resolved catalog, so even a provider hook could not introduce one.

Route (b) was taken, with the evidence placed where antigravity actually acts.

1. WHAT CHANGED  (crates/oc-cli/tests/plugin_models.rs, test-only)
===============================================================================
* `production_plugin_specs()` — ONE definition of the plugin list, shared by
  all three tests, so removing a plugin from the product is a single edit that
  some assertion must notice.
* `PINNED_CATALOG` — the fixture hoisted into a const so a test can assert the
  evidence string is NOT in it.
* `real_auth_plugin_providers_reach_the_plain_models_surface` — kept, kiro
  assertion byte-identical. The `google` assertion is kept but its message now
  states the truth: it is a FIXTURE CONTROL, not evidence about antigravity.
  Nothing was weakened, skipped or deleted.
* NEW `the_real_antigravity_plugin_registers_a_google_auth_method_no_fixture_supplies`
  — loads `production_plugin_specs()` through the real production loader
  (`load_js_plugins_ordered` + the same `JsHostConfig` models.rs builds), then
  `HookBus::dispatch(HookInvocation::Auth)`, and asserts:
    - an auth resource exists for provider `google`, AND
    - its method labels contain "OAuth with Google (Antigravity)"
      (antigravity's own string, `dist/src/plugin.js:1965`), AND
    - that string is absent from `PINNED_CATALOG` (asserted in-test), so it
      cannot be fixture-supplied.
* NEW `without_antigravity_no_auth_resource_carries_its_evidence` — negative
  control: same loader, kiro-auth only. Asserts kiro-auth's own hook IS present
  first (so absence is not proven by loading nothing), then that no hook
  advertises provider `google` and no label carries the Antigravity string.

6. NEW SEAM FOUND WHILE DOING THIS (#17 candidate)
===============================================================================
`models` never dispatches `HookInvocation::Auth`, so a plugin's auth `loader`
never influences the user-visible catalog. Antigravity's loader zeroes the cost
of every google model (`dist/src/plugin.js:1190-1197`:
`model.cost = { input: 0, output: 0 }`) and returns provider options; upstream
runs auth loaders while listing providers, this port does not. Nothing in the
suite would notice. Likewise `HookInvocation::Tool` is dispatched by no
production path, so antigravity's `google_search` tool is unreachable. Both are
production gaps, out of scope for a test-only commit; recorded in the notepad.
