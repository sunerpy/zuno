§1 THE FIVE REJECTION MESSAGES, VERBATIM (rendered from TaskRejection's Display)

1. neither `subagent_type` nor `category`
Must provide either `category` or `subagent_type`. Add `subagent_type="worker"` naming one of the valid targets (explorer, librarian, advisor, worker), or `category="<preset shorthand>"` to run the `worker` agent at that preset's model.

2. both (mutually exclusive)
`category` and `subagent_type` are mutually exclusive; you sent `category="cheap"` and `subagent_type="explorer"`. Provide only one: keep `subagent_type="explorer"` to choose the agent, or keep `category="cheap"` to run the `worker` agent at that preset's model.

3. a coordinator as target
`orchestrator` coordinates delegations and cannot be a delegation target — targeting it would reopen the unbounded recursion the roster closes. Set `subagent_type` to one of the valid targets: explorer, librarian, advisor, worker.

4. depth exceeded
Subagent depth limit reached: this session is already 1 delegation hop(s) deep and `subagent_depth` is 1. Do this work in the current session, or raise `subagent_depth` in config to allow nested subagents.

5. permission denied (guidance on the PermissionAsk, key `guidance`)
`task` is not permitted for `worker`. Grant `task` for pattern `worker`, or set `subagent_type` to a target the current rules allow (explorer, librarian, advisor, worker).

Two further refusals, same discipline:
`load_skills` is not a parameter of `task`. Remove it: skills are permission-gated per agent, so choose the `subagent_type` whose permissions already grant the skill you wanted instead of naming skills in the call.
Unknown agent `cheap`. Set `subagent_type` to one of the valid targets: explorer, librarian, advisor, worker — or, if `cheap` is a preset shorthand, send it as `category="cheap"` instead.

§10 WHAT THE PLAN GOT WRONG, AND WHAT IS MISSING

1. `registry` is 8 tests, not 10 (see §2). `batch` is the 10.
2. omo's `dist/index.js` is NOT on disk in this repo — `.omo/refs/` holds only
   claw-code, codex, hermes-agent, jcode, omo-slim. The plan's citations
   `:136191-136258`, `:136040-136072`, `:136363-136372` could not be measured.
   The behaviour they describe was taken from the plan's prose plus the one omo
   artefact that IS on disk, `.omo/refs/omo-slim/src/hooks/delegate-task-retry/
   patterns.ts:7-51`, whose nine error/fixHint pairs corroborate every rule:
   'category OR subagent_type' (mutual exclusion), 'Must provide either category
   or subagent_type', 'Unknown category', 'Unknown agent', 'load_skills',
   'run_in_background', 'is not allowed. Allowed agents:'.
3. `oc-engine` exposes NO seam a tool can hold to spawn a child session.
   `run_turn` requires `&mut Connection`, a `&ProviderRegistry`, an
   `&dyn AgentModelResolver` and the `&dyn ToolDispatcher` that is itself calling
   the tool. Per the brief this was NOT worked around by editing oc-engine: the
   contract is declared in oc-tools as `task::ChildTurnHost`, exactly as
   `plan_exit::PlanExitHost` declares its session-message seam. Todo 66 (or the
   wiring todo) must implement it over oc-db's parent/child session store.
4. `ToolError::Denied` carries no `#[source]`, so a fix-naming message cannot ride
   on the permission refusal itself. The guidance travels on the `PermissionAsk`
   metadata under `task::GUIDANCE_KEY` instead, where it reaches the human
   deciding and is assertable by a recording asker. Changing `oc-error` was out of
   scope.
