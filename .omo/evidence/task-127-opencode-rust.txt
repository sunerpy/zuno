### Five things reading the source got wrong, and the live probe corrected

1. **`GET /api/integration/{unknown}` answers `data: null`, not an omitted key.**
   The schema is `Schema.UndefinedOr`, which reads as "the key may be absent", and
   that is what I first implemented. The oracle emits `{"location":…,"data":null}`.
   Measurement won; `OptionalEnvelope::data` no longer skips.
2. **`fs/list` sorts with `localeCompare`, which is not byte order.** In a directory
   holding `alpha.txt` and `Cargo.toml` the oracle lists `alpha.txt` first; byte
   order puts `Cargo.toml` first because `C` (0x43) < `a` (0x61). Found by the
   matrix, not by reading `filesystem.ts`.
3. **Integration names sort the same way**, so `openai` precedes `OpenCode`.
4. **V2 serves different prompt and template bytes than v1.** This port mirrors v1,
   and `oc-catalog`'s prompt/template files are byte-identical to
   `packages/opencode/src/**` — verified by diff. `packages/core/src/plugin/**` carries
   its own revision: V2's `title` prompt writes `->` and `<=50` where v1 writes `→`
   and `≤50`, V2's `review` template drops a sentence v1 has, and V2's built-in skill
   description lists `commands` where v1's does not. `oc-catalog` was left untouched
   (other differentials pin it) and the V2 bytes live in
   `crates/oc-server/src/api/v2/`.
5. **V2's command roster has three levels, not four.** v1 promotes every discovered
   skill to a command; V2 does not — only `plugin/command.ts` and
   `config/plugin/command.ts` transform the V2 roster. The oracle answers `init` and
   `review` where the v1 registry also offered `customize-opencode`, so the skill
   sources are not supplied to `/api/command`.

### A sixth finding about the oracle itself

**The released binary answers `[]` for `/api/agent`, `/api/command` and
`/api/provider` for the first moments after it reports "listening".** Measured: the
first request returned zero agents and zero commands, a later one returned seven and
two. Any differential that queries it cold reports differences that are the oracle
disagreeing with itself. `warm_oracle()` in `compat_suite.rs` polls until the
catalogue is populated and panics if it never is, so the warm-up is asserted rather
than assumed.

## 4. Path traversal — the security requirement

`api/fs.rs::Sandbox::resolve` is the only path through which a caller-supplied
component reaches `std::fs`, and it applies two stages, ported from
`core/src/filesystem.ts:66-72`:

1. lexical — fold `.`/`..`, resolve against the root, then `contains`. Catches `..`,
   an absolute path, and a root-relative path **before any syscall**.
2. real — `canonicalize`, then `contains` against the canonicalized root. Catches a
   **symlink** out of the root, which stage 1 cannot see.

`fs/find` takes no path; its walk uses `DirEntry::file_type`, which does not follow
links, so the search cannot leave the root either.

Attack shapes covered by
`api_fs_read_refuses_every_shape_of_escape_from_the_session_directory`, each asserted
to be refused **and** not to leak the out-of-root secret's bytes:

| shape | probe |
|---|---|
| relative parent traversal | `../outside/secret.txt` |
| traversal that escapes only after folding | `nested/../../outside/secret.txt` |
| percent-encoded traversal | `%2e%2e/outside/secret.txt` |
| fully percent-encoded traversal | `%2E%2E%2Foutside%2Fsecret.txt` |
| deep traversal to a real system file | `etc/../../../../etc/hostname` |
| symlink pointing out of the root | `escape-link.txt` → `<root>/../outside/secret.txt` |

Plus: `api_fs_list_refuses_to_leave_the_session_directory` (`..`, `/etc`, `/`,
`nested/../..`), `api_fs_read_names_the_violation_when_a_path_escapes` (403 /
`path_escaped_root`), `api_fs_read_folds_a_traversal_that_stays_inside_the_root`
(a contained `..` still works), and
`api_fs_find_stays_inside_the_session_directory_and_honours_its_limit`.

### Deliberately stricter than upstream, and why

Upstream turns a containment failure into `Effect.die`, which the HTTP layer renders
as an opaque `500 UnknownError` with a random ref — measured live. This port answers
**403 `path_escaped_root`** and names the violation. That is stricter, not looser:
the refusal is identical, only the diagnosis improves. Recorded here and in the
`api/fs.rs` module docs as the one intentional divergence in the group.

A second, narrower divergence: `/api/integration` reports only
environment-derived connections, not stored credentials. An unauthenticated loopback
endpoint enumerating which providers the user holds credentials for is a disclosure
this port does not add silently. The availability decision that matters still
consults the auth store through `Catalog::resolve`.

## 5. Matrix accounting

`crates/oc-testkit/tests/compat_suite.rs`:

| quantity | before | after |
|---|---|---|
| compared dimensions (status + body + side effect) | 15 | **51** |
| exempted dimensions | 159 | **123** |
| operations returning `503 backend_unavailable` | 45 | **33** |
| operations with a local backend | 13 | **25** |
| operations compared exactly against the released binary | 5 | **17** |

Exemption count drops by **36 dimensions = the required twelve operations × three
dimensions**. The matrix still rejects a `501`
(`api_behaviour_matrix_rejects_a_501_only_operation`) and still refuses to count a
`503` as parity (`assert_subject_operation_is_accounted`).

The important structural change: a row declared `Compared` now **runs
`compare_api_observation` against the oracle** inside
`api_behaviour_matrix_compares_live_status_body_and_side_effects`. Before, the loop
only asserted that non-exact rows carried exemption reasons, which is exactly the
accounting the Final Wave reviewers rejected — a claim of parity backed by an
invocation. Now a `Compared` row that disagrees fails the test.

Two supporting changes both matrix servers needed:
- they serve a `work/` subdirectory rather than the state root, because the oracle
  creates `home/`, `data/` and `cache/` inside its root and `/api/fs/list` would
  otherwise disagree about a difference the harness itself created;
- they run under `matrix_env()` — the same isolated world, the same pinned
  models.dev document, the same single credential. Without this the subject would
  read the developer's real `HOME` and `auth.json`, and the responses would depend
  on the machine.

`fs/read` is exempted from the "body must be JSON" assertion only, because its
declared success type is raw bytes.

## 9. What is not claimed

- `fs/find`'s **ranking** is not byte-parity with upstream. Upstream ranks with
  `fff` when the native module loads and `fuzzysort` otherwise, so it does not agree
  with itself across hosts. This port uses a deterministic subsequence score. The
  differential compares `fs/find`'s rejected-request body (a missing `query`, which
  both answer `400` with an identical tagged body), not a ranking neither upstream
  build shares.
- An MCP-backed command's template is reported as `client/prompt` rather than fetched,
  because a read-only GET should not perform an MCP round trip. No fixture in this
  repo exercises an MCP command over HTTP.
- `/api/agent`'s `permissions` reproduces the V2 ruleset for the seven native agents
  and appends the user's config rules. A **non-native** agent's ruleset is the config
  rules only; upstream's V2 roster contains only natives plus config/markdown agents,
  and the differential's world declares none of the latter, so that path is
  implemented but not compared.
