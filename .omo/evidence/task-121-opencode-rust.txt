SCOPE AND DESIGN
================

Unix keeps the separately killable payload process group. The exec guard first
calls setpgid as before. For an inherited controlling terminal whose foreground
group belongs to the supervisor, an explicit exec-foreground handshake then:

1. stops the newly grouped exec guard before the payload exec;
2. lets the monitor observe that stop with waitpid(WUNTRACED);
3. transfers the terminal foreground group to the payload group with tcsetpgrp;
4. resumes the exec guard, which execs the real payload in that same group.

Non-terminal pipe launches retain the original exec path. terminate_process_group
still targets the payload group, so containment remains independently killable.

Windows remains on process-wrap =9.0.1. Its std JobObject does not set
JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE. When try_wait reports the top-level process
has exited, supervise now saves that status, explicitly calls start_kill() on
the Job Object, and calls wait() so live descendants are terminated and the
job completion is observed before the saved top-level status is returned.
