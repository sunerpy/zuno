## ALIAS DECISION — AWAITING USER
- Investigation: the manifest declares exactly one executable, `zuno`; Clap's root command is `zuno`; Makefile, release/CI workflows and `oc-testkit::SUBJECT_BIN` all name `zuno`. No `opencode` executable, Clap alias, wrapper, symlink, or packaging alias exists. Therefore this change preserves the current no-alias behavior rather than silently deciding the open question.
- Recommendation: do **not** add an `opencode` alias. The project is unreleased and Z-1 deliberately made a hard cut; an alias would also shadow the installed TypeScript oracle used for differential testing and side-by-side operation. If the user values drop-in command replacement more than unambiguous coexistence, implement that later as an explicit packaging decision with a dedicated test.
- Reasoning: aliasing cannot be expressed as a Clap subcommand alias because it is the executable name; it requires shipping a second binary, symlink, or installer wrapper. That changes packaging and collision behavior, so it must not be inferred during a user-facing rename.
