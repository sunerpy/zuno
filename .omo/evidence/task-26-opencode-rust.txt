NOTE ON A THING THAT WOULD HAVE SILENTLY BROKEN PARITY
=======================================================
`models.ts:38` and `:56-62` sort with JavaScript `localeCompare`, which is ICU
collation, not byte order. They disagree on real catalog data:
  localeCompare:  "glm-5-turbo" < "glm-5.1"      byte order: the reverse
  localeCompare:  "Gemma-4-31B-DarkIdol" < "glm-5"  (case-folded primary)
catalog/collate.rs ports it. Derivation: every provider and model id in the whole
180-provider catalog is ASCII over exactly 68 characters; against that alphabet
localeCompare is reproduced by a primary level (punctuation `_ - : . @ / ~`, then
digits, then case-folded letters, prefix-first) plus a tertiary case level
(lowercase before uppercase). Checked EXHAUSTIVELY: all 4,753,986 pairs of the 3,084
distinct ids, against Node's localeCompare — zero disagreements. Two rejected models
(plain byte order; and a UCA-style variable-weight model with punctuation ignorable
at the primary level) produced 25,161 and 75,289 mismatching pairs respectively.
Parity is proven only for that 68-character alphabet; ids outside it fall back to
code point order after the in-alphabet levels, and no test claims that is ICU.
