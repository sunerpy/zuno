2. WHY THE HARD-CODED PATHS EXISTED — the fact the fix had to accommodate
================================================================================
Not laziness: `Oracle::discover()` resolves `opencode` on PATH, and on this host PATH
entry #1 is /config/.local/share/mise/shims/opencode, a symlink to `mise` itself.
Measured directly:

  cwd=<inside this repo>, env_clear + redirected HOME:
    shim            -> "mise ERROR ... Config files in /config/.config/mise/config.toml
                        are not trusted", stdout EMPTY
    1.18.15 install -> "1.18.15"
  cwd=<a temp dir outside the repo>, same env:
    shim            -> "1.18.15"     (works!)

So the launcher's failure depends on the *working directory*, and `Oracle::run` always
executes in the ScriptedEnv's temp dir where the shim works — while the differentials
below build their own `std::process::Command` and inherit the test process's cwd, which
is inside the repo, where it does not. `Oracle::discover_pinned` alone therefore cannot
serve these callers: it would accept a launcher that then fails in every one of them.
That asymmetry is what the nine paths were working around, and why the fix is a screen
rather than a rename.

================================================================================
3. THE FIX
================================================================================
crates/oc-testkit/src/oracle.rs — new capability beside Oracle::discover_pinned:

  pub enum PinnedOracle { Found(PathBuf), Absent(String), Disagrees(String) }
  pub fn pinned_oracle() -> &'static PinnedOracle            // OnceLock, once per process
  pub fn pinned_oracle_or_skip(test, untested) -> Option<&'static Path>
  pub const ENV_ALLOW_MISSING_ORACLE = "OC_TESTKIT_ALLOW_MISSING_ORACLE"

  Discovery: OC_TESTKIT_ORACLE if set (then it is the ONLY candidate — an operator who
  names the wrong release must be told, not routed around), else every `opencode` on
  PATH via which::which_all, in PATH order. No path and no release is written down.

  Screen: each candidate is EXECUTED with --version under a ScriptedEnv **from this
  process's own working directory** — the condition a differential actually runs in —
  and its stdout must equal PINNED_RELEASE via the existing check_pin. A launcher that
  prints nothing is refused as unusable; a binary that reports another release is
  refused as a mismatch; the next candidate is tried. Refusals accumulate into the
  Disagrees message, so a failure names every candidate and why each lost.

  Skip contract: Absent -> prints "SKIPPED {test}: {reason}; {untested}" and returns
  None. Disagrees -> PANICS. Absence and disagreement get opposite treatment because
  they are opposite facts: a machine without opencode can verify nothing, while a
  machine with the wrong opencode produces artifacts naming a build that never ran.
  No call site can silently pass: every skip prints what was not measured.

Call sites converted (10 files, 6 crates). Each keeps its differential; none was
deleted, ignored, or weakened:
  oc-cli/tests/differential.rs        const ORACLE -> fn oracle() (panics on absence,
                                       matching its previous behaviour of dying in
                                       Command::output) + 3 skip-gated tests via helper
  oc-cli/tests/rollback.rs            1 test
  oc-db/tests/schema.rs               2 tests
  oc-db/tests/session.rs              3 tests
  oc-db/tests/message_export.rs       1 test
  oc-llm/tests/catalog_differential.rs  14 tests via fn oracle()

  oc-paths/tests/differential.rs      6 tests; the broken version walk deleted; its
                                       vacuous `assert!(!reported.is_empty())` replaced

Cargo.toml: oc-testkit added as a dev-dependency of oc-db, oc-lsp, oc-paths (a legal

New structural guard, crates/oc-testkit/tests/no_pinned_oracle_paths.rs, two tests:
  no_test_file_selects_an_oracle_by_package_manager_path
    walks every crates/*/tests/**/*.rs (asserts it found >20 files, so a broken walk
    fails instead of vacuously passing) and rejects any NON-COMMENT line containing
    "installs/opencode" or "opencode/1." — i.e. the task's grep constraint, executable.
  every_installed_binary_differential_still_routes_through_the_oracle
    an inventory of the 10 files above; each must still exist and still mention
    pinned_oracle. This is the anti-deletion guard: it makes "remove the differential"
    or "drop the oracle call" fail instead of reading as closure.

Run 1's failure is NOT caused by this change and is NOT the transient the brief names.
Diagnosis: oc-auth was not touched, nor was anything in its dependency graph. The test
captures a WARN through a thread-local `tracing::subscriber::with_default`; it panicked
at store.rs:501 with an EMPTY captured buffer, while store.rs:498 (`is_permissive`) had
already passed — so `read_json` did produce the warning and the event never reached the
scoped writer. Three sibling tests in the same binary call `read_json` on permissive
files concurrently with no subscriber installed, which is the shape that poisons a
tracing callsite's cached Interest to `never` and starves a subscriber installed later.
Reproduction attempts: 8x isolated (66/66 each), then 48 and 72 runs of the test binary
at 8- and 24-way self-concurrency — 120 runs, 0 failures. It needs whole-workspace load.
Recorded in issues.md as a latent load-correlated flake in the documented family; not
fixed here, because oc-auth is outside this task's scope and a speculative fix to
another crate's test plumbing is worse than a named finding.
