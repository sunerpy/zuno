7. DELIBERATE DIVERGENCES FROM THE ORACLE (all documented in-source)
=======================================================================
(a) A FAILED FORMAT RESTORES THE PRE-FORMAT BYTES.
    format/index.ts:96-113 logs and keeps whatever is on disk. That loses the
    edit when a formatter truncates before failing (mutation proof (a) shows the
    file going to ""). Cost of restoring: a formatter that exits non-zero AFTER
    useful work (`rubocop --autocorrect` returns 1 while any offence remains)
    has its partial work discarded — the file ends up exactly as it would be if
    rubocop were not installed. Smaller harm than a mangled file.

(b) A 30s PER-FORMATTER CEILING. The oracle has none, so a hung formatter hangs
    the edit forever. Reported as `TimedOut`, edit intact.

(c) NODE-HOSTED FORMATTERS RESOLVE FROM THE PROJECT'S node_modules/.bin, NOT
    `Npm.which`. `core/src/npm.ts:192-241` INSTALLS the package when missing.
    This port will not install anything to satisfy a format. A project with the
    package installed still formats; one without is skipped rather than
    triggering a download. The declared-dependency check itself is exact.

(d) NOT DIVERGENT, but worth recording: `htmlbeautifier` claims ".html.erb"
    (formatter.ts:271), which `path.extname()` can never produce — it returns
    ".erb". Carried verbatim; silently "fixing" the oracle's table would be a
    divergence hiding inside a port. Asserted in
    `the_extension_is_the_final_segment_with_a_leading_dot`.

RISK GATE: a formatter does NOT go through crates/oc-tools/src/risk.rs.
`risk` exists because `bash` executes a string the MODEL composed. A formatter
command comes from the compile-time table or the operator's config, and is
spawned as argv with no shell — there is no model-authored text and no word
splitting, so `rm -rf` cannot appear as a side effect. What IS borrowed from
shell.rs is the hygiene: stdin closed, both streams captured, kill_on_drop,
`process_group(0)` on Unix, hard ceiling.

IN-PLACE, NOT TEMP-FILE: every built-in command mutates the file it is given
(-w, -i, --write, --fix), and several resolve config by walking up from the
file's own directory (.clang-format, .ocamlformat, biome.json). A temp copy
would break those and would lie to the formatter about where the file lives.
Restoring the pre-format bytes buys the property that matters (the EDIT
survives) without that lie.

8. A REAL LOAD-CORRELATED FLAKE FOUND AND FIXED (ETXTBSY)
=======================================================================
tests/format.rs failed 1-in-N under `cargo test -p oc-tools` while passing
100% when run alone:
  ---- a_node_hosted_formatter_needs_both_the_declaration_and_the_binary ----
  assertion failed: runtime.format_all(&script).await.changed
Root cause: `cargo test` runs a target's tests as THREADS in one process.
`execve` fails with ETXTBSY while any process holds the target write-open. A
sibling test's `fork` — every test here spawns processes — snapshots the fd
table while this thread's write fd to the freshly-written stub is still open, so
the forked child holds a copy until its own execve.

MEASURED with a standalone harness (/tmp/oc-t79/etxtbsy, since deleted):
  6 writer+exec threads x 2000 stubs + 6 concurrent /bin/sh forkers
      -> attempts=12000  ETXTBSY=1342  (11%)  other_spawn_errors=0
  1 writer, NO concurrent forkers
      -> attempts=2000   ETXTBSY=0
  same load, with the bounded retry
      -> attempts=12000  transient_ETXTBSY_retried=1063  UNRECOVERED=0

FIX: `wait_until_executable()` — every stub is probed with a `--probe-executable`
argument until execve succeeds, bounded at 8 x 5ms. This is a real fix, not a
mask: the condition is SELF-LIMITING (nothing write-opens the inode again after
the probe returns), and 8x5ms is three orders of magnitude past a fork-to-execve
window. All stubs go through one `script()` helper so no site can skip it.
Production is untouched — opencode does not write the formatter it then executes,
so it cannot lend out an fd to one.

9. HOW THE FORMATTERS WERE STUBBED (no download, no PATH mutation)
=======================================================================
Nothing is downloaded or installed (holding todo 41's ripgrep line). Each test
writes its own /bin/sh script into a per-test `tempfile::tempdir()`:
  rewriting_stub    rewrites the file to a byte-exact known value, exit 0
  failing_stub      leaves the file alone, known stderr, exit 3
  destructive_stub  TRUNCATES the file then exits 1   <- the decisive case
  recording_stub    appends every path it was handed to a log, then rewrites
  hanging_stub      sleep 600, for the ceiling
Stubs target the LAST positional argument (`for target in "$@"; do :; done`),
because a built-in command like `clang-format -i $FILE` puts the flag in $1.
Fixtures always change the file's LENGTH as well as its content, so "the bytes
changed" cannot be true by coincidence (habit borrowed from the oc-snapshot
stat-cache flake).
`ProgramLocator` is injected so no test reads or mutates PATH — mutating the
environment is `unsafe` and forbidden in this workspace. A CONFIGURED command is
taken verbatim (format/index.ts:154 replaces the probe with
`async () => info.command ?? false`), so those fixtures pass an absolute path;
the locator governs the BUILT-INS, which is what the availability tests drive.
