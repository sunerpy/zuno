The repository-wide scan found these actual first-party `allow` attributes:

  crates/oc-engine/src/compaction.rs
    clippy::too_many_arguments — required compaction invariants stay explicit;
    optional state already uses builders.
  crates/oc-server/src/api/maintenance.rs
    clippy::too_many_arguments — preview and mutate deliberately share one policy
    path mirroring request inputs plus execution context.
  crates/oc-tool/src/schema.rs
    dead_code — fixture fields are consumed only by the JsonSchema derive.
  crates/oc-pty/tests/common/mod.rs
    dead_code — each integration-test binary compiles the shared helper module
    separately and uses a different helper subset.
  crates/oc-tui/src/views/editor.rs
    clippy::too_many_lines — already had a local `reason`: one arm per binding;
    splitting the table would hide it.
  crates/oc-tui/src/theme.rs
    missing_docs — already had a local `reason`: fields mirror theme JSON keys.
  crates/oc-testkit/tests/memory.rs
    clippy::too_many_arguments — the file is frozen and prohibited from edits;
    `release_surface.rs` pins this exact line/attribute as the sole externally
    justified exception because refactoring the immutable artefact writer would
    change the measured harness/cache fingerprint after the run.

`every_first_party_lint_suppression_has_a_reason` scans every Rust file under
`crates/`, including integration tests. Any new `#[allow(...)]` or
`#![allow(...)]` without `reason = ...` fails. The frozen memory-harness exception
is exact by relative path, line, and attribute text, and the test also fails if
that exception moves or disappears without deliberate reconciliation.
