3. OLD AND NEW HINT TEXT
================================================================================

OLD (one string, every route, stale):
  "the route is measured and registered; its backend lands in todos 57-62"

NEW (V1Route::hint(), derived per route from api_alternative):

  with an alternative (10 routes), e.g. POST /session/{sessionID}/abort:
    "this pre-/api route is registered but has no local backend; call
     `POST /api/session/{sessionID}/interrupt` instead, which serves the same
     capability in this build"

  without one (9 routes), e.g. PUT /auth/{providerID}:
    "this pre-/api route is registered but has no local backend, and
     `client.auth.set` has no served /api equivalent here; there is no alternative
     call that works today"

The 501 body also gained structured fields, all derived:
  "backing": "not-implemented"
  "apiAlternative": "POST /api/session/{sessionID}/interrupt" | null
  "surfaceCoverage": "19 of 20 measured pre-/api routes have no local backend
                      (10 of those can name a served /api alternative); 1 served locally"

surfaceCoverage is computed by v1_coverage() on each response rather than stored as
a &'static str. That choice is deliberate: a `&'static str` restating a runtime
count is one of the five prose-drift defects fixed in waves 53-57, and writing one
here would have re-created the class of bug this todo removes.

4. WHERE THE GAP IS RECORDED, AND WHY IT CANNOT DRIFT
================================================================================

Classified as a GAP, not a divergence. docs/divergences.toml:11-14:

  # An entry belongs here only when the difference is a DECISION. A surface that is
  # merely unimplemented is a gap, not a divergence: it is reported by the suite's
  # `not_compared` / `known_gaps` sections and must never be laundered into an
  # entry here.

docs/divergences.toml is therefore UNTOUCHED and DECLARED_COUNT stays 17.

Recorded in the existing executable inventory, not in prose:

  crates/oc-testkit/src/compat_report.rs
    + V1_SURFACE_GAP_ID   = "v1-surface-unbacked"
    + V1_SURFACE_WITNESS  = "compat_v1_declared_backing_matches_what_the_router_answers"
    + V1SurfaceCoverage { measured, served, unbacked, redirected }  (unbacked derived)
    + v1_surface_gap(coverage) -> KnownGap
    + known_gaps(api_gap_count, upstream_api_operations, v1) now returns it

This follows the turn_part_gap() precedent exactly (id constant + witness constant +
standalone constructor + entry in the shipped list). The coverage arrives as a
parameter for the same reason the API counts do: oc-testkit has oc-server as a
DEV-dependency only, so restating the numbers inside oc-testkit would put a second
copy one edit away from disagreeing with the router.

Why it cannot go stale — four independent derivations:

  a) crates/oc-server/tests/compat_v1.rs::
     compat_v1_declared_backing_matches_what_the_router_answers
     drives all 20 routes and asserts backing.is_served() == (status != 501), then
     re-derives (served, unbacked, redirected) from the observed run and compares to
     v1_coverage(). A route gaining or losing a backend fails here.

  b) crates/oc-cli/tests/docs.rs::docs_compatibility_matrix_matches_every_code_table
     regenerates the `known-gaps` and `v1-routes` blocks of
     docs/compatibility-matrix.md from v1_coverage() and V1_SURFACE. Any count change
     makes the committed page stale and the test red.

  c) the same test's new assert_v1_alternatives_are_really_served() splits each
     api_alternative into verb+path and asserts it is in the PROBED served set and
     NOT in the probed 503 gap set — so a redirect target losing its backend fails,
     and an alternative can never point at another dead end.

  d) the matrix prose numbers are asserted via contains_all against v1_coverage()
     ("19 of the 20 answer `501 not_implemented`", "10 of those 19 name a served",
     "the other 9 have no served"), so the sentence a human reads cannot drift from
     the table either.

Also fixed, same defect class:
  docs/v1-surface-capture.md   "Those backends land in todos 57-62." -> states that
    no plan todo owns them, names the gap id, cites the divergence rule, and names
    the nine stranded methods; asserted by (b) via the capture-document test.
  compat_v1.rs ToastForwarder doc -> now records that no entry point attaches a
    forwarder, with both callsites.
  diagnostics JSON: "implementedRoutes": 20 was itself dishonest (only 1 is
    implemented). Replaced with registeredRoutes / servedRoutes / unbackedRoutes /
    unbackedWithApiAlternative / coverage, and "backend" now reads route.backing
    rather than re-deriving from the path.
