2. WHAT CHANGED
====================================================================

crates/oc-server/src/compat_v1.rs
  `v1_session` now emits `"slug": session.slug`, read straight off `SessionInfo`
  (which already carried it — crates/oc-server/src/api/session.rs:86). It is NOT
  synthesised from `id`: `slug` is a caller-supplied column of its own
  (crates/oc-db/src/session.rs:248,257), so the two are free to differ and
  recomputing would be a guess that happens to hold today.
  The doc comment states the projection's contract — a rename of the ID-suffixed
  keys, nothing dropped — and names the test that enforces it.

crates/oc-server/tests/compat_v1.rs
  New: compat_v1_session_projection_satisfies_the_published_session_schema

  It validates against the PUBLISHED SCHEMA, not against a hand-written key list:

    * fetches /doc through the router (the same document the live process serves)
      and reads components.schemas.Session.required off it;
    * reads the same set off the committed oracle;
    * asserts the two AGREE first — that agreement is what makes an omission a
      defect rather than something declarable, so the test proves its own premise
      instead of assuming it;
    * maps the published camelCase ID keys through `v1_session_key`, the one
      rename the projection is allowed to make;
    * then asserts every derived required key is present AND non-null on all
      three v1 session bodies: POST /session, GET /session/{id}, and every element
      of GET /session.

  Because the required set is derived, a required field added to `SessionInfo`
  later is covered on the day it is added, with nobody editing this test. Two
  anti-vacuity guards: the derived set must hold >= 5 keys, and the session list
  must be non-empty (an empty array satisfies any schema).

  New helpers: `v1_session_key` (the /api -> v1 rename) and
  `required_session_keys` (the required set in v1 spelling, from either document).

3. THE /agent OBSERVATION F3 RECORDED — different class, recorded not fixed
====================================================================

Measured, not assumed:

  v1 GET /agent keys     : builtIn color description maxSteps mode model name
                           options permission prompt tools
  oracle Agent props     : color description hidden mode model name native options
                           permission prompt steps temperature topP variant
  extra (not in oracle)  : builtIn, maxSteps, tools
  missing optional       : hidden, native, steps, temperature, topP, variant
  missing REQUIRED       : (none) — all of name, mode, permission, options served
  /doc components.schemas: Session, SessionActive, SessionActiveResponse,
                           SessionCreate, SessionListResponse, SessionPruneMutation
                           -> NO `Agent` schema is published

DISPOSITION: not the same class as the `slug` defect. Three checkable reasons.

  1. No required key is dropped. The slug defect denied a caller a field two
     contracts promised; here every promised field arrives.
  2. There is nothing for the body to contradict. The port publishes no `Agent`
     schema, so the "build rejects its own response" property that made slug a
     defect is absent.
  3. It is not decidable with what is in the tree. The only committed capture is
     .omo/fixtures/oracle-openapi-1.18.12.json while the port targets a later
     release, so the optional-key drift cannot be classified as upstream-corrected
     or genuinely missing. Choosing an answer would be inventing the capture — the
     project's signature defect.

So it is RECORDED IN THE FROZEN GAP INVENTORY, per docs/divergences.toml:11-14
which forbids declaring an undecided difference as a decision:

  crates/oc-testkit/src/compat_report.rs
    V1_AGENT_GAP_ID = "v1-agent-projection-unverified"
    v1_agent_projection_gap()  — added to known_gaps(), so it renders into both
    the compatibility report and docs/compatibility-matrix.md (regenerated via
    OC_DOCS_REGENERATE=1; the docs gate then passes clean).

The recording is not inert prose. Its named witness

  crates/oc-server/tests/compat_v1.rs::
    compat_v1_agent_projection_drift_is_recorded_and_drops_no_required_key

measures the served key set against the oracle schema and FAILS if either reason
expires:
  * a required Agent key is ever dropped -> it becomes the slug class and must be
    fixed, not recorded;
  * this build starts publishing an `Agent` schema -> the body must then be checked
    against it the way Session now is.
It also pins the measured extra/absent sets, so the gap text and the projection
cannot drift apart silently. A unit test in compat_report.rs asserts the gap is
actually shipped in known_gaps() and names its witness.

F3's other two minor observations are untouched and remain accurate: the v1 routes
are absent from /doc (52 /api paths only), and an unknown route 404s with an empty
body while registered-but-unbacked routes 501 with a diagnostic. Neither is a
required-field omission.
