- the `complete` checklist item was edited to `[x]`, but the checklist is the system's to set, not the document's; the goal database still says `[ ]`.

the objective, when the document owns it but the value is unstorable:
- `objective` was edited to ``, but a goal objective must not be empty; the goal database still says `keep me`.

an unparsable document:
This document could not be parsed, so it was rebuilt from the goal database. Your version was kept at `<path>.bak.<unix-seconds>`.

Each message names four things: what was edited, what it was set to, who owns it,
and what the goal database actually says. Singular/plural is carried by
`Refusal::SystemOwned { noun, plural }`, built only via `Field::owner()`, after the
first draft emitted "the counters IS the system's to set".

7. HOW THE RENDER IS STOPPED FROM RE-INGESTING ITSELF
================================================================================

`GoalProjection` retains the exact bytes of its last render plus the `Goal` they
were rendered from (`Mutex<Option<LastRender>>`). An ingest that finds the file
byte-identical to those bytes returns `Ingest::OwnRender` and does nothing: no SQL
write, no rewrite.

Chosen over the two alternatives:
  * an mtime+len stamp (oc-memory's approach) — exact byte equality is available
    here because the projection just produced the bytes, so a stamp only adds a
    same-size-within-one-timestamp-tick false negative, and it would misread a
    no-op editor autosave as an edit;
  * an ignore-next-event token — oc-watch coalesces, so one token can be consumed
    by the first of N merged events and let the rest through.

Tested by:
  a_render_does_not_trigger_a_re_ingest                        (6 consecutive
    ingests all OwnRender; also asserts the file bytes and `updated_at_ms` are
    unchanged, so no SQL write followed)
  the_re_render_that_follows_an_adopted_edit_is_also_recognised_as_our_own
  a_save_that_changed_nothing_is_not_an_edit
  a_hand_edited_objective_over_the_cap_spills_...              (the pointer
    sentence round trips as OwnRender)

Related, and the subtler half of the same mechanism: the rejection baseline is the
**last render**, not live SQL. SQL moves on between render and save (`record_usage`
changes tokens_used, tokens_remaining and updated_at_ms in one statement), so
diffing against current SQL would report three edits the user never made. Guarded by
`an_untouched_field_is_not_reported_when_sql_moved_on_since_the_render`.

8. NO SECOND WATCHER, NO SECOND ATOMIC-WRITE HELPER
================================================================================

Watcher: none built. `oc-goal` depends on `oc-watch` only to consume its
`FileEvent`/`ChangeKind`; `GoalProjection::ingest_event` is the seam and whoever
already runs a `Watcher` routes matching events in. Two reasons this is not a
shortcut:
  1. `oc-watch`'s default flag resolution is `Decision::VcsOnly` — the project
     directory is NOT watched unless OPENCODE_EXPERIMENTAL_FILEWATCHER is set — so
     a Watcher built inside oc-goal would be silently inert by default, and forcing
     the flag from here would override the user.
  2. `oc-watch` has no suppression API (no per-event token, no ignore-next-event),
     so the self-render problem had to be solved on this side regardless.
Recorded in issues.md as a resolved design question rather than a request to change
`oc-watch` (which this task may not edit).

Atomic write: the same technique as `oc-memory/src/store.rs`'s `write_atomic`
(temp in the destination's own directory, then rename) rather than a second design.
That helper is private to `oc-memory` and returns a private `FileStamp`, so it is
not callable; `oc-memory` is also not a dependency of any crate. Two deliberate
deltas, both documented in the source:
  * `with_file_name(format!("{name}.tmp.{nanos}"))` instead of `with_extension`.
    `with_extension` REPLACES the extension, so `ses_1.md` -> `ses_1.tmp.<nanos>`;
    a session id containing a dot could then collide with another session's target.
  * nanos in the temp name, so two concurrent renders cannot share a temp file.
Neither implementation calls `sync_all`; for derived state that is the right trade
(regenerated from SQL on the next material change).

  and never mentions `.opencode/plans`. Per the prompt's instruction the
  recommendation is `projection::GITIGNORE_SNIPPET` plus a module-docs section
  saying why; no new file was invented.

* "watch the file" cannot be satisfied inside this crate — see section 8.

* Additions the plan did not name but the conflict rule requires:
  - a hostile session id must not become a path (`..` -> `.opencode/goal/...md`);
  - an objective edited to whitespace is document-authoritative but unstorable, so
    it needs its own refusal shape (`Refusal::Unstorable`);
  - an unparsable document must be preserved before being rebuilt, or a user's
    prose is destroyed by the very mechanism meant not to lose their edits;
  - `## Rejected edits` renders even when empty (`_Nothing has been rejected._`),
    because an absent section is ambiguous between "nothing rejected" and "this
    build does not report rejections".
