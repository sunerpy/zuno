RULES DERIVED (each one traceable to a probe case above)

COMMENT-SKIP RULE (exact):
  Applies to {file:...} ONLY. For a token at byte offset i in the env-expanded
  text: line_start = (index of last "\n" before i) + 1, else 0.
  Skip the token iff js_trim_start(text[line_start..i]) starts with "//".
  A skipped token is emitted verbatim and its file is NEVER read.
  Consequences, all measured:
    skipped      : "  // {file:x}", "/// {file:x}", "\uFEFF// {file:x}",
                   "\u00A0// {file:x}", "\t\t// {file:x}", CRLF comment lines,
                   and EVERY token on such a line (probe2 comment-then-real-same-line)
    substituted  : "{\"a\":1} // {file:x}"    trailing comment, not a comment line
    substituted  : "{\"a\":\"// {file:x}\"}"  // inside a JSON string value
    substituted  : "/* {file:x} */"        block comments are NOT recognized at all
    substituted  : "{\r  // {file:x}\r}"    lastIndexOf("\n") ignores a lone CR
    substituted  : " / {file:x}"            a single slash is not a comment
  {env:...} IS SUBSTITUTED INSIDE COMMENT LINES. probe1 env-in-line-comment,
  env-in-trailing-comment and env-in-block-comment all expand. probe2
  env-then-file-in-comment shows both halves at once: "// {env:OC_X}{file:./rel.md}"
  becomes "// E{file:./rel.md}". The task brief said "tokens inside comment lines
  are not substituted"; that is true of {file:} and false of {env:}, and the
  oracle behaviour is what is implemented. Todo 8 (JSONC) and Todo 12 must agree
  with the asymmetry, not with the simpler rule.

ESCAPE RULE:
  content = js_trim(lossy_utf8(bytes)); emitted as JSON.stringify(content)[1..-1]
  i.e. the BODY of a JSON string, no surrounding quotes, so it lands between the
  quotes already in the document. Escapes: \" \\ \b(08) \t(09) \n(0A) \f(0C)
  \r(0D), any other c < 0x20 as \u00xx lowercase hex. NOT escaped: "/", U+007F,
  U+0085, and every non-ASCII character (probe2 slash-not-escaped, probe3
  stringify-DEL). Proven equal to serde_json for all strings by a proptest.

TRIM SET (String.prototype.trim, NOT char::is_whitespace):
  09 0B 0C 20 A0 FEFF 1680 2000-200A 202F 205F 3000 0A 0D 2028 2029
  Two deltas against Rust, both observable:
    U+FEFF  JS trims it, Unicode White_Space does not -> a BOM-prefixed prompt
            file loses its BOM, and "\uFEFF// {file:x}" IS a comment line.
    U+0085  Unicode White_Space does, JS does not -> NEL survives at the edges.

PATH RESOLUTION (three shapes, deliberately inconsistent in the oracle):
  "~/rest"   -> path.join(os.homedir(), rest)   NORMALIZES (probe3 tilde-dotdot:
                {file:~/../nope3.md} with home=/config reports /nope3.md)
  absolute   -> used VERBATIM, unnormalized (probe3 abs-unnormalized and
                abs-double-slash report ".." and "//" back unchanged; the kernel,
                not path.resolve, resolves them, so ".." is symlink-aware here)
  otherwise  -> path.resolve(dirname(configFile), spec)   NORMALIZES
  A bare "~" is NOT special: {file:~} resolves to <configdir>/~ (probe1).
  os.homedir() is the REAL home, not Global.Path.home: OPENCODE_TEST_HOME does
  not reach variable.ts.

MALFORMED TOKENS (regex /\{env:([^}]+)\}/g and /\{file:[^}]+\}/g, nothing more):
  {env:} and {file:} are not tokens ([^}]+ needs a character) -> left literal.
  An unterminated {env:FOO / {file:x -> left literal.
  A token may span a line break, a quote, anything but "}" (probe2
  env-token-spans-newline; probe1 env-malformed-noclose swallows the closing quote).
  Nested {env:{env:A}} resolves the variable literally named "{env:A" (probe1).
  Missing env var -> "". Missing {file:} -> error (or "" under missing:empty).
  A non-ENOENT read failure (a directory) omits the "does not exist" suffix.
  The env pass runs FIRST over the whole text, so an env value can supply a
  {file:} token or part of a file path (probe1 env-value-makes-file-token,
  probe3 env-in-file-token). A file BODY is not rescanned.
