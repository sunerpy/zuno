# Task 45 evidence — MCP stdio transport with spec NDJSON framing

## Scope

Implemented `crates/oc-mcp/src/stdio.rs` and public exports/dependencies for:

- newline-delimited UTF-8 JSON-RPC over child stdin/stdout (no `Content-Length`)
- concurrent numeric id → `oneshot` response demultiplexing
- independent notification delivery and unknown-response-id handling
- `initialize`, `notifications/initialized`, paginated `tools/list`, and `tools/call`
- `notifications/tools/list_changed` cache refresh
- per-server timeout, workspace-relative cwd, environment layering, stderr drain, and child kill/reap
- JavaScript-compatible UTF-16 MCP tool-name sanitization

## Real-server proof

Command:

```sh
cargo test -p oc-mcp stdio_live_codegraph_handshake_lists_and_calls_a_real_tool --offline -- --nocapture
```

Result: 1 passed, 0 failed, using real `codegraph 0.42.9 serve --mcp`.

Observed initialize fields:

```json
{"protocolVersion":"2024-11-05","serverInfo":{"name":"codegraph","version":"0.42.9"},"capabilities":{"tools":{}}}
```

Observed `tools/list`: four non-empty real tool definitions (`codegraph_search`, `codegraph_callers`, `codegraph_node`, `codegraph_explore`).

Observed successful real call:

```json
{"id":3,"jsonrpc":"2.0","result":{"content":[{"text":"No results found for \"task45-no-symbol\"","type":"text"}],"isError":false}}
```

Every wire message was one JSON object terminated by a newline; no LSP-style header appeared.

## Oracle decision

The executable TypeScript MCP path uses a 30,000 ms default timeout, while schema prose says 5 seconds. The Rust implementation follows observable executable behavior (30 seconds) and records the disagreement in the shared issues notepad; explicit server configuration still overrides the default.
