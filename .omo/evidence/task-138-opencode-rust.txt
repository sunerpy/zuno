Task 138 evidence — stale subject binaries can no longer report a false green
Date: 2026-08-10

BOTTOM LINE

`Subject::discover_or_build` now asks Cargo to refresh `oc-cli` before a
source-coupled test process uses the subject. The refresh is serialized and
cached once per test process, so parallel cases do not rebuild repeatedly.
`OC_TESTKIT_SUBJECT` remains a deliberate caller-owned override: it bypasses the
workspace build, is honoured exactly, and is named in subject provenance.

DESIGN AND COST

- Automatic workspace subject: run
  `cargo build -p oc-cli --bin opencode-rust`, locate the resulting candidate,
  and report `cargo build -p oc-cli --bin opencode-rust` as its source.
- Repeated calls in one test process: one Cargo invocation, guarded by
  `Mutex` + `OnceLock<PathBuf>`.
- Explicit subject: use `OC_TESTKIT_SUBJECT` without invoking Cargo and report
  `explicit environment OC_TESTKIT_SUBJECT` in the provenance label.
- Why Cargo rather than mtime/revision: Cargo already owns the complete
  dependency graph, including dirty source and the shared worktree target.
  Comparing one timestamp or Git revision would miss content states Cargo knows
  about and would recreate an incomplete build system in the harness.
- Warm no-op Cargo freshness checks, measured five times after the workspace was
  built: 0.29, 0.28, 0.27, 0.27, 0.26 seconds; median 0.27 seconds, range
  0.26–0.29 seconds. The old path did no Cargo check, so the steady-state added
  cost is 0.27 seconds per source-coupled test process, not per test case.
  The first cold build in this worktree took 27.00 seconds because it compiled
  dependencies; a real source edit necessarily pays the corresponding rebuild
  cost to make the tested binary truthful.

The stale-candidate test uses an isolated child test process and a fake Cargo
executable. It starts with stale bytes, requires Cargo to replace them, calls
`discover_or_build` twice, and asserts the fake Cargo build count is exactly one.
The explicit-override test points `CARGO` at a nonexistent path, proving the
override is respected rather than rebuilt, then asserts the environment variable
is present in the provenance label.

ANALYSIS CHECK

The reported false-green mechanism and `hydrate_retained_history` reproduction
were correct. The only refinement is that “binary older than source” should not
be implemented as a raw timestamp comparison: dirty trees, dependency sources,
and shared target directories make that proxy incomplete. Letting Cargo decide
whether rebuilding is necessary satisfies the intent with a measured 0.27-second
warm cost and avoids inventing a second dependency graph.
