1. THE ASSET DECISION
================================================================================

Upstream imports six .mp3 files from the excluded @opencode-ai/ui package
(packages/tui/src/attention.ts:17-22), declared by packages/tui/src/audio.d.ts:6.
The six imports, verbatim, with the slot each fills (attention.ts:47-56):

  default        @opencode-ai/ui/audio/bip-bop-01.mp3
  question       @opencode-ai/ui/audio/bip-bop-03.mp3
  permission     @opencode-ai/ui/audio/staplebops-06.mp3
  error          @opencode-ai/ui/audio/nope-03.mp3
  done           @opencode-ai/ui/audio/bip-bop-01.mp3   (same file as `default`)
  subagent_done  @opencode-ai/ui/audio/yup-01.mp3

Six imports, FIVE distinct files (bip-bop-01.mp3 serves both `default` and
`done`). The plan says "four mp3 files"; it is five. See discrepancies below.

DECISION: ship silence by default with a documented path to supply a pack.
Sanctioned option 2 of the two the plan offers.

LICENCE STATEMENT: none can be made for these assets, which is why they are not
vendored.
  - packages/ui/package.json declares `"license": "MIT"` and packages/ui/LICENSE
    is the MIT text, "Copyright (c) 2025 opencode".
  - That covers the package. It does not establish that opencode holds
    redistributable rights in the 90 audio files under
    packages/ui/src/assets/audio/ (45 .mp3 + 45 .aac). Measured: that directory
    contains no LICENSE, no NOTICE, no README, no attribution file of any kind
    (`find packages/ui/src/assets -name '*.md' -o -name '*.txt'` -> empty).
  - The filenames (alert-01..10, bip-bop-01..10, nope-01..12, staplebops-01..07,
    yup-01..06, each in two encodings) are the numbered-variation naming of a
    purchased UI-sound library. Such libraries are commonly licensed to the
    buyer for use in a product while forbidding redistribution of the assets
    standalone or as part of another asset pack.
  - So the honest position is: provenance unknown, licence unstatable. Shipping
    bytes whose licence cannot be stated is worse than shipping silence.

WHAT SHIPS INSTEAD: builtin_pack() is registered under upstream's own id
`opencode.default` and is EMPTY. Out of the box the audio half of every cue is
unavailable and notify() returns AttentionDiagnostic::MissingSound naming the
pack and the slot. The notification half is unaffected. The six slot NAMES are
kept verbatim (SoundName::ALL), because the names are the compatibility surface
even though the bytes are not — a user supplying a pack needs to know which six
files to provide.

NOTHING WAS DOWNLOADED, VENDORED, OR PULLED INTO THE BUILD. Enforced by a guard
test rather than a convention:
  attention_no_audio_asset_is_compiled_into_this_crate
walks the whole crate directory and fails on any file with an audio extension
(mp3/aac/wav/ogg/opus/flac/m4a) or any `include_bytes!` in a Rust source. Floor
assertions per .omo/WORKTREE.md: >= 40 files walked, >= 6 Rust sources read, so
a scan pointed at the wrong directory fails loudly instead of passing vacuously.
Measured on this tree: 79 files walked, 10 sources read, 0 audio, 0 embedders.
The one exclusion (attention_tests.rs, which must name the macro it forbids) is
justified inline and is #[cfg(test)], so it cannot reach a shipped binary.

2. THE FIVE EVENT CLASSES AND THEIR CUES
================================================================================

Derived from the event handlers in
packages/tui/src/feature-plugins/system/notifications.ts:35-86, not invented.

| event class      | upstream event                  | sound slot      | message                 | notification | sound_when |
|------------------|---------------------------------|-----------------|-------------------------|--------------|------------|
| PermissionNeeded | permission.asked (:49-53)       | permission      | "Permission needs input"| blurred      | always     |
| QuestionAsked    | question.asked (:35-39)         | question        | "Question needs input"  | blurred      | always     |
| Error            | session.error (:80-86)          | error           | "Session error"         | blurred      | always     |
| Done             | session.status idle, no parent  | done            | "Session done"          | blurred      | always     |
| SubagentDone     | session.status idle, has parent | subagent_done   | "Session done"          | (suppressed) | always     |

SubagentDone has no notification channel by construction, not by config:
notifications.ts:15 passes `notification: isSubagent ? false : { when: "blurred" }`
for every event, so a subagent finishing is sound-only. A desktop notification
per finished subagent would be the loudest thing in the app.

`Error`'s message is the fallback from sessionErrorMessage (:20-27); the caller
supplies "Session aborted" / "Model stopped responding" via with_message().

`default` is the sixth slot and is NOT an event class — it is the slot a caller
reaches when it names none (attention.ts:200).

Test: attention_each_event_class_resolves_to_its_configured_cue — table-driven,
one row per class, asserts slot + message + notification availability + that the
resolved cue actually reaches the recording player with the file the slot names.
Row count is asserted against EventClass::ALL.len(), so adding a class without a
row fails.

3. THE enabled / notifications / sound MATRIX
================================================================================

Three switches: `enabled` (master, default FALSE per config/index.tsx:103),
`notifications` (default true), `sound` (default true).

| enabled | notifications | sound | notification fired | sound fired | cue delivered |
|---------|---------------|-------|--------------------|-------------|---------------|
| false   | false         | false | no                 | no          | no            |
| false   | false         | true  | no                 | no          | no            |
| false   | true          | false | no                 | no          | no            |
| false   | true          | true  | no                 | no          | no            |
| true    | false         | false | no                 | no          | no            |
| true    | false         | true  | no                 | yes         | yes           |
| true    | true          | false | yes                | no          | yes           |
| true    | true          | true  | yes                | yes         | yes           |

All eight rows asserted by
attention_the_channel_matrix_is_two_independent_switches_under_one_master,
which also asserts the CALL COUNTS on both fakes — so "did not fire" means the
channel was never reached, not that it was reached and returned false.

attention_disabled_produces_no_cue_at_all runs all five classes with everything
else saying yes (both channels on, a full pack, a blurred terminal) so only the
master switch can account for the silence, and asserts
(notifier.count(), player.count()) == (0, 0).

8. THE TWO TEST SEAMS — no display server, no audio device
================================================================================

`cargo test` has neither, and this crate acquires a dependency on neither.
Both channels are traits with inert defaults, following the TerminalLifecycle
precedent from todo 73 rather than inventing a third pattern:

  trait Notifier    { fn notify(&self, title: &str, message: &str) -> bool; }
  trait SoundPlayer { fn play(&self, file: &Path, volume: f64) -> bool; }

  NullNotifier  — the default. Shows nothing, returns false.
  OscNotifier<W> — the REAL notification path. Writes an OSC 777 sequence to any
                   std::io::Write, so a test sink is a Vec<u8> and the exact
                   bytes are asserted. Why OSC 777: upstream delegates to
                   OpenTUI's renderer.triggerNotification (attention.ts:30,185),
                   which is not vendored here; its SYNCHRONOUS boolean return is
                   the tell, because every platform's native notification API is
                   asynchronous. What a synchronous boolean can be doing is
                   writing an escape sequence. OSC 777 carries a title and a body
                   and is understood by kitty, WezTerm, foot, and urxvt;
                   emulators that do not understand it ignore it, which is the
                   correct failure for a courtesy channel.
  SilentPlayer  — the default AND, today, the only real player. A decoding
                   backend would pull a device-level dependency and its system
                   libraries into a crate that ships no audio to decode. It is
                   deliberately deferred behind the trait; adding one later
                   changes no caller.

  RecordingNotifier / RecordingPlayer (test-only) record every call with its
  arguments and answer a configured bool, which is what makes "the channel was
  never reached" distinguishable from "the channel said no"
  (attention_a_notifier_that_declines_is_not_a_delivered_notification).

No test opens an audio device, requires a display server, spawns a process, or
touches the filesystem outside CARGO_MANIFEST_DIR (the guard test reads it).

10. WHAT THE PLAN GOT WRONG
================================================================================

(a) "it is four mp3 files, not code" — it is FIVE distinct files across six
    imports; bip-bop-01.mp3 fills both `default` and `done`
    (attention.ts:47,55). The "four" also appears in the MUST-NOT
    ("Must NOT pull the excluded UI package into the build for four assets").
    The constraint is honoured regardless of the count; the count is wrong.

(b) The task title says "with bundled audio assets", and the body then offers
    ship-silence-by-default as a sanctioned alternative and its own acceptance
    criterion requires "a missing sound pack degrades to notification-only".
    Those cannot both hold: if assets were bundled the third criterion would be
    untestable without deleting them. Read the body, not the title. (Same shape
    as todo 97's title-vs-body contradiction recorded in .omo/WORKTREE.md.)

(c) "map event classes — permission needed, question asked, error, done,
    subagent done — to desktop notifications and audio cues". Four of the five
    map to both channels; SubagentDone maps to audio ONLY, and not by
    configuration — notifications.ts:15 hardcodes `notification: false` for any
    subagent event. The plan's phrasing implies five notification mappings.

(d) The config surface has SIX sound slots, not five: `default` exists
    alongside the five event classes (config/index.tsx:8-15,
    packages/plugin/src/tui.ts:235). A user's `attention.sounds` table can set
    it, so it had to be modelled even though no event class resolves to it.

11. WHAT WAS NOT DONE, AND WHY
================================================================================

- No real audio playback. SilentPlayer is the shipped player. Deferred
  deliberately: there is nothing to play until a user supplies a pack, and
  adding a device-level dependency now would be paying for a capability the
  crate cannot exercise. The trait is the seam; no caller changes when one lands.
- No key-value persistence of the active sound pack. Upstream persists the
  soundboard selection in its KV store (attention.ts:171-177, KV_SOUND_PACK);
  that store is not in oc-tui. activate_pack() lives for the process and the
  configured `sound_pack` remains the durable answer. A crate owning the KV
  surface can layer persistence on top without changing this module.
- No renderer focus wiring. set_focus(FocusState) is the seam; the focus/blur
  events upstream subscribes to (attention.ts:126-131) come from a renderer
  event stream that todo 73's loop does not yet surface. FocusState::Unknown is
  the honest default and declines focus-conditional channels rather than
  guessing, which is exactly what upstream does (attention.ts:109).
- `renderer_destroyed` skip reason omitted: it is a fact about the renderer's
  lifetime, not attention policy. The equivalent here is not calling notify().
- No live QA against a terminal emulator. The OSC 777 bytes are asserted exactly;
  whether a given emulator raises a tray notification for them is outside what
  this environment can observe, same boundary todo 73 recorded for TTY state.
