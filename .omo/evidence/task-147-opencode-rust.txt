1. Production path and permissive sink

The exercised path is:
  oc-cli PluginRuntime::apply_catalog
  -> AuthLoader::load
  -> JsHost::call_mutating
  -> shim.mjs "call"
  -> encode callback value and mutated arguments
  -> bridge.rs deserializes arguments[1] as ResolvedProvider
  -> provider write-back

ResolvedModel::variants is BTreeMap<String, JsonMap>. JsonMap is an open
serde_json::Map, so {"$truncated":true} is valid data and deserialization does not
detect that the encoder replaced a real object.

3. Design selected

Selected: distinguish host-supplied mutating arguments from arbitrary plugin
graphs, while refusing any still-lossy provider write-back.

  * shim.mjs encodes every mutated argument separately from depth 0. The transport
    args array no longer consumes one of the eight levels belonging to provider data.
  * MAX_DEPTH remains 8. Callback return values and every individual mutated
    argument still stop at that depth.
  * A generated truncation marker now carries a JSON Pointer in $path.
  * bridge.rs searches arguments[1] for a marker before deserialization. It returns
    BridgeError::TruncatedProvider with plugin and path and never assigns provider.

Rejected alternatives:

  * Raising MAX_DEPTH merely relocates the cliff and was explicitly forbidden.
  * Removing/exempting the bound for all mutated arguments permits a plugin to
    attach an unbounded internal graph, violating the bounded-memory requirement.
  * Refusal alone, while still charging the args transport wrapper, is safe but
    rejects provider data one level earlier for a framing detail. The selected
    hybrid preserves all provider objects below their own bound and refuses at it.
  * Tightening ResolvedProvider/ResolvedModel was rejected. variants, options, and
    related bags intentionally accept arbitrary upstream JSON; a closed schema
    would reject valid providers and still would not generally identify encoder loss.
