1. Production composition

Selection is driven by ResolvedModel.api.npm, never by a model-id allow-list.
The production composition root registers these keys:

  @ai-sdk/openai-compatible       -> openai-compatible
  @openrouter/ai-sdk-provider     -> openai-compatible
  @ai-sdk/anthropic               -> anthropic
  @ai-sdk/openai                  -> openai
  @ai-sdk/amazon-bedrock          -> amazon-bedrock
  @ai-sdk/amazon-bedrock/mantle   -> amazon-bedrock/mantle
  @ai-sdk/google                  -> google
  @ai-sdk/google-vertex           -> google-vertex
  @ai-sdk/google-vertex/anthropic -> google-vertex/anthropic

Unknown npm transports are rejected explicitly instead of being guessed to use
the compatible protocol. The compatible transport alone requires a configured
endpoint. Anthropic and Vertex Anthropic use the Messages surface; Bedrock
receives region metadata; Vertex receives project and location metadata.

TurnPlan keeps Option<Credential> until factory construction. This preserves the
Anthropic/OpenAI OAuth-versus-API-key distinction; factories whose existing API
accepts a token string receive only the projected secret value.

No dependency was added. plugin_runtime.rs and hooks.rs were not touched.
