SESSION READ BOUNDS

`/message` uses keyset pagination over the persisted `session_message`
projection. It defaults to 50 rows, caps requests at 200, defaults to descending
order, and returns a base64url JSON cursor containing the boundary message ID,
order, and direction. Supplying both a cursor and a separate order is rejected.

`/history` reads finite durable-event pages. It defaults to 50 events, caps at
100, treats `after` as an exclusive sequence cursor, and reports `hasMore`.

`/context` returns the provider-visible session-message projection and respects
the persisted compaction/baseline boundary rather than returning unbounded stale
history. All four session read routes return 404 for an unknown session.

REQUEST STATE

The process-local permission and question request readers return the upstream
`{location,data}` envelope. Saved permissions return `{data}` and deleting an
unknown saved-permission ID is the upstream-compatible idempotent 204 no-op.

PTY ATTACH SECURITY AND TRANSPORT

The connect-token endpoint requires `x-opencode-ticket: 1`, verifies the PTY,
and mints a scope-bound ticket through the existing bounded ticket store. Tickets
expire after 60 seconds, are single use, and are bound to PTY, directory, and
workspace scope. Missing, wrong-scope, expired, and replayed tickets are refused;
error bodies never include the credential.

The connect endpoint performs a real RFC 6455 upgrade and attaches to the real
PTY service. It sends replay in at most 64 KiB frames, emits cursor metadata,
forwards live output, accepts text/binary/continuation input with a 1 MiB client
frame bound, and handles ping and close frames. A real TCP regression test mints
a ticket, upgrades, writes to `/bin/sh`, and observes terminal output.

No new package was added to Cargo.lock. `oc-server` directly declares the
already-locked `hyper`, `hyper-util`, and `aws-lc-rs` packages needed to access
Axum's underlying upgrade I/O and the RFC 6455 SHA-1 handshake without adding a
new WebSocket stack.
