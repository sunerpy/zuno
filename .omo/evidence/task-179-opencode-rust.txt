TODO 179 — COMPILE-TIME GENERATED-CLIENT ARRIVAL BINDING
========================================================

SOURCE FINDINGS AND BINDING DECISION
------------------------------------
- F4 Round 2 correctly rejected the handwritten `GeneratedClientArrival`: its variants were
  not derived from generated SDK responses, and the server route registrations used unrelated
  string literals. Exhaustiveness therefore applied only after a human remembered to edit the
  enum.
- The requested `@opencode-ai/sdk@1.18.18` declaration package is not present in the Bun cache.
  Todo 176 already recorded that environmental fact and audited the closest complete 1.18.16
  declarations. Todo 178 supplies the stronger build input: it launched the screened 1.18.18
  release and proved its 478,747-byte `/doc` response byte-identical (sha256
  c3a9f94af0c3324d97b482b14c692e810ce7ccac3136319ba46334de972b4cf1) to the committed
  `.omo/fixtures/oracle-openapi-1.18.12.json`. The JavaScript declarations are generated from
  that OpenAPI contract.
- Chosen mechanism: `oc-plugin-sdk/build.rs` traverses every 200-response schema transitively
  from that pinned OpenAPI document and generates `GeneratedClientArrival` for every operation
  reaching `Model`, `ModelRef`, `ModelV2Info`, `Provider`, or `ProviderV2Info`.
  `JsModelArrival::projection` exhaustively matches that generated enum without a wildcard.
  The concrete `/provider`, `/api/model`, `/api/provider`, and
  `/api/provider/{providerID}` registrations now take their paths from those same generated
  variants instead of disconnected literals.
- Why regeneration cannot bypass it: adding a Model/Provider-bearing 200 response to the
  generated-client OpenAPI input makes the build script emit a new Rust variant before
  `projection.rs` is compiled. Rust then rejects the non-exhaustive projection match. A route
  serving an existing generated operation is bound to that operation's generated path; a new
  generated route first has to exist in the same OpenAPI input and therefore creates the same
  compile-time obligation. There is no handwritten `ALL` list to forget and no runtime assertion
  in the enforcement path.
