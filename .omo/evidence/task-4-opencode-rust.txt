SUPPORTING PROBES — the oracle behaviours that shaped the port
=============================================================

Node path.join normalizes; PathBuf::join does not. Measured `data` row per
XDG_DATA_HOME value, straight off the 1.18.12 binary:
  XDG_DATA_HOME=/tmp/x/data    -> /tmp/x/data/opencode
  XDG_DATA_HOME=/tmp/x//data   -> /tmp/x/data/opencode
  XDG_DATA_HOME=/tmp/x/data/   -> /tmp/x/data/opencode
  XDG_DATA_HOME=/tmp/x/../y    -> /tmp/y/opencode
  XDG_DATA_HOME=..             -> ../opencode
  XDG_DATA_HOME=./x            -> x/opencode
  XDG_DATA_HOME=a/../../b      -> ../b/opencode
  XDG_DATA_HOME=x/y/..         -> x/opencode
  XDG_DATA_HOME=relx           -> relx/opencode

Empty XDG falls back (|| semantics) but empty OPENCODE_TEST_HOME does not (?? semantics):
  XDG_DATA_HOME=      -> /config/.local/share/opencode
  OPENCODE_TEST_HOME= -> home=[]

os.tmpdir() ladder (TMPDIR || TMP || TEMP || /tmp, one trailing slash stripped).
Paths must be writable: the oracle mkdirs <tmpdir>/opencode during import.
  TMPDIR=/tmp/t4-tmp-FksV3J/a                                -> /tmp/t4-tmp-FksV3J/a/opencode
  TMP=/tmp/t4-tmp-FksV3J/b                                   -> /tmp/t4-tmp-FksV3J/b/opencode
  TEMP=/tmp/t4-tmp-FksV3J/c                                  -> /tmp/t4-tmp-FksV3J/c/opencode
  TMPDIR=/tmp/t4-tmp-FksV3J/slash/                           -> /tmp/t4-tmp-FksV3J/slash/opencode
  TMPDIR + TMP + TEMP all set (TMPDIR wins)                  -> /tmp/t4-tmp-FksV3J/a/opencode
