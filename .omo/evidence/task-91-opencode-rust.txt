  1. --version   the binary loads and its linkage resolves on this platform;
                 asserts stdout contains an x.y.z token, not just exit 0

6. DECISIONS THIS TASK OWNED
================================================================================

WHAT SHIPS: `opencode-rust` only. NOT `oc-server`. `opencode-rust serve` wraps
  `oc_server::ServerBuilder` as a library rather than spawning that binary
  (oc-cli/src/command.rs:552-554), and decisions.md records oc-server's binary
  as "Task 51's executable QA surface". Shipping both would invite users to run
  the wrong one. Also not shipped: oc-example-plugin, oc-acp-conformance,
  oc-log-probe, ts-baseline — the workspace has SIX binary targets, not two.

WHEN IT RUNS: release.yml on `v*` tags plus `workflow_dispatch`. NOT on every
  push — six builds plus six smokes is far too slow for a per-commit gate. The
  gap the prompt flagged is closed two ways: (a) `workflow_dispatch` runs the
  full matrix with `publish` skipped, so the whole pipeline is exercisable
  before any tag exists; (b) ci.yml's `artifact` job runs the same
  package-unpack-smoke path on the host leg for every push and PR, so a break
  in the smoke driver or the cassette surfaces on the PR that caused it.
  No release-please: this project has no release process yet and inventing one
  is todo 92's territory, not mine. A `version` job cross-checks the tag against
  oc-cli's manifest version and fails on a mismatch.

CASSETTE: committed at packaging/smoke/cassettes/, sha256
  fab3c2b9991544004e02a101c4bbe5843f887d2084d96353a684fba4f0e5acd4, byte-identical
  to the oracle's copy. A CI runner has this repo and nothing else, so
  `oc_testkit::recordings_root()` (which walks up looking for a sibling opencode
  checkout) cannot work there. The drift test compares the two whenever an
  oracle tree is reachable and prints a named skip otherwise.

CARGO-DENY: offline in `make ci` (so the local gate needs no network), online in
  the CI `supply-chain` job (so the advisory database is current). `make deny`
  prints a named skip if cargo-deny is absent; the CI job does not skip.

OFFLINE: every Makefile cargo invocation passes `$(OFFLINE)` = `--offline`,
  overridable with `OFFLINE=`. `make ci` runs entirely offline; verified.

WHAT CI WOULD FETCH THAT THIS ENVIRONMENT CANNOT: nothing unusual — the
  toolchain, the crate index, the RUSTSEC database, Zig 0.13.0 (mlugg/setup-zig),
  and cargo-zigbuild / cargo-deny (taiki-e/install-action). All are ordinary
  network fetches on a hosted runner. Locally, `cargo fetch --locked --target
  x86_64-apple-darwin` was needed once to pull `mach2 v0.6.0` so
  `cargo deny check advisories` could resolve all targets offline; that is the
  same Windows-only-transitive-dep hazard learnings.md already records.

7. WHAT THE PLAN GOT WRONG OR LEFT OPEN
================================================================================

1. "each passes its smoke test" for six targets is achievable, but not by
   executing all six on one runner. It needs six runners; the aarch64-musl
   artifact is the only cross-compiled one and needs ubuntu-24.04-arm.
2. codegraph-rust uses `macos-latest` for BOTH darwin targets. `macos-latest` is
   now Apple Silicon, so an x86_64-apple-darwin binary built there is
   cross-compiled and cannot be executed on it. This pipeline uses
   `macos-15-intel` for the x86_64 leg so that leg is native and executable.
   Copying codegraph's matrix verbatim would have produced an unexecutable
   artifact — the precise failure this todo forbids.
3. The plan says "a test asserts the default feature set pulls no OpenSSL and no
   wasmtime". `oc-plugin` is not in `oc-cli`'s graph at all, so those are two
   different questions with two different positive halves; both are asserted.
4. No unsafe-grep test existed to reuse (the plan suggested one might). The
   workspace lint table existed; the missing piece was proving all 34 crates
   inherit it, which is where the real hole was.
5. The plan's five Makefile targets (fmt, lint, test, ci, release) do not include
   fmt-check, which is what CI actually needs; both exist.
