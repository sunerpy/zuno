Defect and authority decision
-----------------------------
- `PluginRuntime::transform_messages` already serialized and copied back both
  `info` and `parts`.
- `run_turn` then extended the provider history with only `message.info`, silently
  discarding every canonical `parts` mutation.
- Upstream's hook contract exposes `{ info, parts }`, invokes the hook before
  `MessageV2.toModelMessagesEffect`, and that projection builds provider content
  from `parts`.
- Therefore `info.role` remains the role/projection selector and canonical `parts`
  is authoritative for provider-bound content after the hook.

Implementation
--------------
- `run_turn` now rebuilds every transformed provider message from canonical parts.
- Existing owned user and assistant projection helpers remain the only content
  conversion logic.
- User/system messages project user-compatible parts and retain the transformed
  role. Assistant/tool projections filter the existing assistant/tool split by
  `info.role`, preventing duplicate halves.
- No dependency, plugin payload schema, JavaScript host, provider, database, TUI,
  or `chat.message` change was made.
