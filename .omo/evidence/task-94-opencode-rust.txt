  *** CORRECTION TO THE TASK BRIEF ***
  The brief calls this "Azure's own model selector" and the acceptance
  criterion asks that it "pick the documented endpoint per model id".
  The oracle's function ACCEPTS modelID AND NEVER READS IT. Azure's rule is
  a surface-availability walk gated by one provider option; it is NOT a
  model-id rule. Implementing it as one would invent behaviour the oracle
  does not have. crates/oc-provider-compatible/src/surface.rs::azure_surface
  therefore takes no model_id parameter, and the test
  azure_picks_the_same_endpoint_for_every_model_id asserts the ABSENCE of
  that dependency across 6 model ids. Only Copilot is per-model.

### NOT VERIFIED / OUT OF SCOPE

    only through the Transport trait, and oc-testkit has no HTTP client.
    The ReqwestTransport code path is therefore compiled and clippy-clean but
    NOT exercised end-to-end against a real server by this task.
  * Request bodies are not byte-compared to the recorded requests. Those were
    produced by the Vercel AI SDK and carry fields this profile does not
    originate (stream_options.include_usage, its own max_tokens default), so
    request parity would be a false claim. Recorded URLs ARE compared, wherever
    the recorder did not redact them (both Cloudflare URLs carry {account}
    placeholders and are excluded, which the test states explicitly).
  * Catalog integration (todo 26) is not wired here: capabilities arrive via
    Spec.options.capabilities / .modelCapabilities. The composition root (todo
    30's registration site) has to populate them from the catalog.
  * Effort resolution is not re-implemented: oc_llm::effort writes into a Map
    that arrives as Spec.options.extraBody.
  * Cargo.lock gained 98 lines. 10 are this crate's own dependency list; the
    rest are oc-tool's async-trait/schemars closure, which its manifest already
    declared at d7af235 while the committed lock had no deps recorded for it.
