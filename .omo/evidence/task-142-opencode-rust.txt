1. What F4 found, and what was actually wrong
---------------------------------------------

`.omo/evidence/F4-REPORT-wave5.md` judgment 1, verbatim:

    its parity-row witness currently asserts only that both sides fail; unlike the other
    three additions, it does not directly assert the documented stderr texts.

Confirmed at base. `Witness::BothFail` (`cli_parity.rs:138` at `68bdfed`) evaluated exactly
one predicate (`:728`):

    verdict.oracle.exit != Some(0) && verdict.subject.exit != Some(0)

Its two users were the two diagnostics probes (`:260`, `:286`). So the entry that exists to
protect this port's *message content* was guarded by a check that never read a message.

Two facts I measured that the todo description did not state:

  a. The divergence declares **three** surfaces (`docs/divergences.toml:143`): `serve` on an
     unavailable port, `run` with no message, `run` with an unresolvable model. The table had

     weakness was worse than "witness too weak on two probes": one third of the declaration
     was measured by nothing.
  b. The entry's own closing prose was already stale for a second reason: it said the harness
     "exempts those two stderr streams" and "still asserting both sides refuse", which after
     this change describes neither the count nor the check. Corrected in the same commit and
     `docs/divergences.md` regenerated through the existing `OC_DOCS_REGENERATE=1` path.

3. What changed
---------------

`crates/oc-cli/tests/cli_parity.rs` only, plus the two divergence-doc corrections.

  * `Witness::BothFail` **removed**, replaced by
    `Witness::DocumentedDiagnostics { oracle_form, subject_form }`. Removed rather than left
    reachable-by-nothing: its only two users were the probes being upgraded, so keeping it
    would have left a weaker tier available for the next probe to reach for.
  * `Witness::OracleStderrContains` **untouched**; the `tui` probe that uses it is unchanged.
  * A third probe added for `run --model bogus/model hi`, closing the surface that had none.
    `PROBE_COUNT` 15 → 16, and the module doc's "Fifteen probes" updated with it.
  * `documented_diagnostics_hold()` checks **four** facts per probe:
      1. both sides still refuse (the old fact, kept — nothing was weakened);
      2. every `oracle_form` fragment is in the oracle's raw stderr;
      3. every `subject_form` fragment is in this port's raw stderr;
      4. **and neither side carries the other's form.**
    Fact 4 is why one direction alone is not enough: asserting only (2) passes if this port
    degrades to the same opaque text; asserting only (3) passes if a future release starts
    naming the cause, at which point the divergence is closed and the entry must go.
  * `DIAGNOSTICS_SURFACES` freezes the three argvs **by name**, and the new test
    `every_declared_diagnostics_surface_carries_a_two_sided_witness` compares it against the
    table. It runs **no process**, so a downgrade fails even on a host with no oracle — where
    the process-driven half of `every_exemption_states_a_reason_and_keeps_a_witness` skips.
    It also asserts the declared reason quotes every fragment expected *of upstream*, because
    that half is the one no code here controls.
  * `witnesses_observed` 3 → 4, plus a new `diagnostics_witnesses_observed == 3`.

Port number and OS error string (the todo's explicit "must not"):
  * the address is asserted through `BUSY_PORT_TOKEN`, resolved to the port the run actually
    holds — `SUBJECT_BIND_FAILURE = "could not bind HTTP server to 127.0.0.1:<BUSY_PORT>"`.
    No literal port number anywhere.
  * `Address already in use (os error 98)` is deliberately **not** pinned. `98` is Linux's
    `EADDRINUSE` and the strerror text is the platform's, so pinning it would fail on a
    healthy macOS or Windows host for a reason unrelated to the divergence. Recorded in the
    rustdoc on `SUBJECT_BIND_FAILURE`. Everything the witness does pin — the `127.0.0.1:<port>`
    prefix, the argv refusals, upstream's `Unexpected error`/`ServeError`/`UnknownError` — is
    platform-independent.

7. Corrections to the task's own analysis
-----------------------------------------

  * "恰好 2 个 BothFail probe 就是 diagnostics 相关的" — accurate, but the framing "升级两个
    probe" understates the fix: the divergence declares three surfaces and only two had probes.
    Upgrading the two would have left `run --model <bogus>` declared and unmeasured, so a third
    probe was required to satisfy the stated intent.
  * The task said upgrade the existing `OracleStderrContains` tier. I did not reuse it: it holds
    a single `&'static str` and observes only the oracle, so it cannot express "and ours says
    something else". A sibling variant carrying both sides was the smaller change than
    contorting that one, and `OracleStderrContains` stays exactly as `tui` needs it.
  * The task did not mention `docs/divergences.toml`'s stale closing clause ("those two stderr
    streams … still asserting both sides refuse"). Left alone it would have been a fresh
    instance of the prose-versus-executable drift the same review blocked in two other places,
    so I corrected it and regenerated the page.
