================================================================================
§5  THE UNKNOWN-ROUTE ACCOUNTING
================================================================================

A request to a pre-/api path that is NOT in V1_SURFACE but sits under a v1
top-level prefix gets:
  - HTTP 404
  - a body naming the exact path and instructing the operator to re-run the
    capture and extend V1_SURFACE
  - an increment of a process-local counter

SURFACED TWO WAYS, deliberately:
  1. GET /compat/v1/diagnostics — implemented surface (with each route's SDK
     method, callers and callsites), the exact total, the bounded per-path
     breakdown, the overflow figure, and the toast sink's state.
  2. stderr, ONE LINE PER DISTINCT PATH on first sighting. An operator watching
     the server learns about a gap without polling. Repeats are counted but not
     re-logged, so a path scanner cannot flood the log. Real output in §7 §11.

VERB-LEVEL ACCOUNTING: a measured path called with an unmeasured verb answers
  405 (not 404 — the path does exist) with the same actionable body, keyed
  "VERB path" in the breakdown. Without this, axum's bodiless default 405 would
  hide a mis-measured operation. Live proof: DELETE /auth/anthropic in §7 §5.

BOUNDED: the per-path breakdown caps at 64 distinct paths, each truncated to 256
  bytes at a char boundary. The TOTAL stays exact regardless, and sightings past
  the cap are reported as overflowedSightings, so the mechanism cannot be
  defeated by a caller-controlled unbounded key space.
  Test: 200 distinct paths -> total 200, breakdown 64, overflowed 136.

SCOPE — WHY IT DOES NOT SHADOW /api/*, /event, /health, /doc:
  V1_PREFIXES is exactly the oracle's 25 pre-/api top-level segments MINUS
  `event` (the SSE stream owns /event exactly; a second route there panics at
  assembly) = 24. A test derives that set from the committed OpenAPI document
  and asserts equality, so the list cannot drift, and asserts it never contains
  "api".

MECHANISM — two dead ends and what actually works:
  (a) A single Router::fallback is GLOBAL. It would answer for unmatched /api/*
      too, claiming the API surface's misses as v1 gaps. Also, merging two
      routers that both have a fallback panics.
  (b) A /{prefix}/{*rest} wildcard per prefix LOOKS scoped but panics at
      runtime. Measured, not guessed:
        Invalid route "/auth/{*rest}": Insertion failed due to conflict with
        previously registered route: /auth/{providerID}
      matchit treats a wildcard and a named parameter at the same depth as
      CONFLICTING, not as one outranking the other. 12 of 16 tests failed on
      this before it was corrected.
  (c) WHAT WORKS: one Router::nest per prefix, each inner router carrying its
      own fallback. axum grafts an inner fallback into the outer router AT THE
      NEST PREFIX (axum-0.8.9/src/routing/mod.rs:227-229), which is exactly the
      scoping required. Prefixes with no measured root route also get an
      explicit bare route, because a nest at /foo matches /foo but the grafted
      fallback sits one segment deeper.
      Consequence: the nest strips its prefix before the fallback runs, so the
      handler reads OriginalUri — reporting a path the caller never sent would
      make the 404 useless to the operator it is written for.
      method_not_allowed_fallback must be applied AFTER the routes it covers;
      axum retrofits it onto already-registered MethodRouters only.

KNOWN EDGE, not covered: a trailing-slash v1 path such as `/session/` matches
  neither the nest nor the bare route and falls through to the plain outer 404
  with no body and no counter bump. No SDK method generates a trailing slash, so
  nothing in the capture reaches it. Recorded rather than hidden.


================================================================================
§6  /tui/show-toast WITH NO TUI  (todo 73 has not landed)
================================================================================

It is a RECORDING SEAM. Each accepted toast is appended to a bounded 64-entry
ring, counted, and reported by diagnostics; the call returns 200 `true`, which
is what upstream returns. A toast nobody sees is degraded UX; a 500 is a broken
plugin — so the seam never fails on a well-formed toast.

When a TUI attaches it registers a forwarder via
CompatV1State::with_toast_forwarder and the SAME route forwards as well as
records. No route change, and diagnostics do not go blind after attach.
Test: compat_v1_attached_display_receives_the_toast_without_a_route_change.

TWO DELIBERATE LENIENCIES vs the oracle, both protecting the toast mandate:
  - oracle marks `variant` REQUIRED; this seam defaults a missing variant to
    "info".
  - oracle sets additionalProperties:false; this seam ignores unknown fields.
  Rejecting either would turn a cosmetic mismatch into the exact breakage the
  plan warns about, across all three installed plugins.
STILL STRICT: a missing or non-string `message` is 400 invalid_request. There is
  then nothing to display.

The other 19 routes are registered, structured 501 not_implemented seams, each
naming its SDK method and the plugins that call it — following the precedent
todo 52 set for the /api surface. Backends land in todos 57-62.

HONEST STATEMENT OF WHAT THE PLUGINS CAN DO against this surface alone: every
request the installed auth plugins issue reaches a REGISTERED route and receives
a DEFINITIVE answer (no hangs, no 404s), and their toasts are delivered to the
sink. They cannot yet AUTHENTICATE, because auth.set and the OAuth pair have no
credential backend here. The plan's happy-path QA scenario is satisfied at the
call-lifecycle level, which is the level this todo owns.
Test: compat_v1_installed_auth_plugin_lifecycles_are_answered_without_a_single_404
replays both auth plugins' ordered call sets and asserts no 404, no 405, no 500,
counter == 0, and both toasts delivered.

CREDENTIAL SAFETY: client.auth.set carries a secret. The seam never reads the
body, CompatV1Error has no field that could hold one, and
compat_v1_auth_set_seam_never_echoes_the_credential_it_was_sent posts
"sk-do-not-echo-me" and asserts it appears nowhere in the response.

================================================================================
§10  WHAT THE PLAN GOT WRONG
================================================================================

1. "the two auth plugins together use six SDK methods" — THREE plugins are
   installed (the config lines the plan itself cites, :88/:90/:91), and the
   measured set is 20 methods across them. The plan anticipated this ("plus
   anything a re-run of the capture adds"), which is why the re-run was
   mandatory; the magnitude, 3.3x, is the finding.

2. "client.provider.oauth" IS NOT A METHOD. It is a namespace object with two
   callable children. Taken literally it would have produced a route
   (/provider/{id}/oauth) that does not exist in the oracle, while leaving both
   real KIRO calls unrouted.

3. The plan's acceptance criterion is `cargo test -p oc-server compat_v1`, whose
   literal reading is satisfied (17 ran). Worth noting the filter matches by
   test NAME as well as target, so every test in the new target is prefixed
   `compat_v1_` — otherwise the filter could have silently run a subset.

4. Not wrong, but under-specified: the plan says "any request to an unimplemented
   v1 path returns a 404". A request to an implemented PATH with an unimplemented
   VERB is the same class of mis-measurement and would otherwise have escaped
   with axum's bodiless 405. That case is accounted too, at 405, keyed
   "VERB path". DELETE /auth/{providerID} is the live instance.
