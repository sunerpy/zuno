ORACLE DEFECT FOUND — `agent list` truncates its own stdout under load
===============================================================================
cli/cmd/agent.ts:248-251 writes each agent with process.stdout.write and lets the
process exit. On a pipe those writes are async, so under load the runtime exits
before the tail flushes. Three distinct losses observed on 1.18.12 with four
copies of this suite running concurrently:
  * 5 of the 7 built-ins — 'summary' and 'title' dropped (the last two printed)
  * all 7 built-ins but the user's 'collide' dropped (non-natives sort last)
  * a listing cut off mid-way through build's permission JSON
Every loss was a SUFFIX. Reproduction rate before the fix: 2 failures / 8 runs
under 4-way concurrency; 0 / 18 runs serially.

Handling: NOT a normalizer. One loose enough to absorb missing agents would also
absorb this crate failing to define them — the exact failure this task prevents.
Instead oracle_agent_headers() requires two consecutive runs to agree AND each to
be well-formed (ending with the ']' that closes the last ruleset). Agreement alone
was proven insufficient: a mid-block truncation repeated identically. If the output
never stabilizes in 8 attempts the test FAILS and says so.

Post-fix stress: 12 concurrent suite runs (4-way parallel x3) -> 12/12 ok, 0 failed.
