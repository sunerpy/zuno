Task 159 — give the chat.message hook its full upstream user-message shape
Closes F2's wave-9 blocker F2-B3 (escalated from a wave-8 non-blocking finding).

--------------------------------------------------------------------------------

THE DEFECT
--------------------------------------------------------------------------------
The production `chat.message` adapter supplied a reduced message object without
upstream's `id`, `sessionID`, `agent` and `model`. A dispatch witness proved the
hook fired, so todo 149's wiring measurement passed — but a real upstream plugin
could not rely on the payload it received. This is todo 147's rule again:
proving a path works is not proving the data crossing it is usable.

THE FIX
--------------------------------------------------------------------------------
`OutputChatMessage.message` changed from the reduced `Message` to the real
`oc_db::message::MessageRecord`, serialized through `MessageRecord::to_json()`
(`crates/oc-plugin/src/payload.rs:29`, `crates/oc-plugin/src/jsonrpc.rs`).

Notably the fix **removed** 77 lines net from `crates/oc-cli/src/cmd/turn.rs`,
deleting `message_from_parts` / `parts_from_message` and the code that synthesized
`prefixed_id("prt")` part ids and re-stitched a session id by hand. The real
record already carries all of it, so supplying the true shape was less code than
faking a reduced one — which is the healthy sign for this class of fix. No
placeholder values were introduced, as the task required.

TEST SHAPE
--------------------------------------------------------------------------------
The guard is a real JS plugin that checks the payload itself
(`crates/oc-cli/tests/tool_turn.rs`): it compares `output.message[field]` against
`input.messageID` / `input.sessionID` / `input.agent` / `input.model` and, on any
missing or mismatched field, appends `:missing-chat-message-<fields>` or
`:wrong-chat-message-<field>` to the assistant text. The Rust side then asserts on
that text, so a field regression surfaces as a visible difference in the turn
rather than as a silently absent key.
