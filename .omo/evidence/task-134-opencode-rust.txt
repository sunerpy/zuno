Task 134 — fail closed when no client remains to answer a request
Date: 2026-08-10
Branch: task-134

Implementation
==============

(a) Last observer disappears
- `crates/oc-server/src/events/route.rs` acquires a session-scoped
  `SessionRequestObserver` for both session SSE routes and retains it in the stream.
- `crates/oc-server/src/request_broker.rs` counts observers per session. Dropping
  the last guard removes that session's pending permissions and questions and sends
  only `ReplyKind::Reject` / `QuestionDecision::Rejected`.

(b) Subscriber-independent watchdog
- Each brokered permission/question starts an independent five-minute watchdog.
- It holds a `Weak` broker reference and rejects only the original
  `(session_id, request_id)` if it is still pending. It never grants permission.

Tests and what they prove
=========================

1. `disconnected_only_session_observer_rejects_permission_without_running_the_tool`
   opens the only session SSE observer, parks a real HTTP bash tool call, drops the
   observer, and proves `/wait` returns, the completion arrives, the forbidden
   `touch` side effect does not exist, and the provider completes its two turns.

2. `permission_without_an_observer_is_rejected_by_the_deadline`
   creates a request without any observer, advances Tokio's paused clock by 24
   hours, and proves the asker resumes and the pending request is removed.

3. The same deadline test asserts the exact result is `ReplyKind::Reject`, proving
   timeout is denial rather than authorization.

4. Existing guards still pass:
   - `disconnected_permission_reply_fails_closed_without_running_the_tool`
   - `api_reply_routes_validate_bodies_before_rejecting_cross_session_requests`
   The latter also covers permission and question cross-session reply rejection.

Analysis corrections
====================

No factual error was found in the task's distinction between reply-client and
observer-client disconnects, nor in the need for both cleanup mechanisms. One
implementation clarification was necessary: observer awareness is attached at the
session SSE route/stream lifetime and reported into `RequestBroker`; the broker
cannot infer an HTTP response-body disconnect by itself.
