REUSE IS IN PLACE, NOT A REBUILD
  a_continuation_appends_to_the_session_and_never_reopens_or_replays_it pins the
  full operation log the child-session seam received:

    [ Open   { parent: "ses_root", agent: "explorer" },

  Exactly one Open. Exactly one Append per turn. `first` is written once, so a

5. THE RENDERED BOARD (all five states in one render)
===============================================================================
### Background Job Board
Claiming reuse in prose reuses nothing: a call whose `task_id` is absent or empty starts a NEW session, whatever the surrounding text says. To continue a job, pass its alias or its session id as `task_id`.
A job under Active is still running or still owes a result, and cannot receive another `task` call even with its `task_id` — a re-dispatch is refused, not queued. Wait for it to report, then continue it once it appears under Reusable.
Only a job under Reusable may be continued. Closed jobs are terminal: start fresh.

#### Active
- exp-1 / ses_child_0001 / explorer / active
  Job: bg_000001
  Objective: explorer: map the loader
- wor-1 / ses_child_0002 / worker / unreconciled
  Job: bg_000002
  Objective: worker: rename the field

#### Reusable
- lib-1 / ses_child_0003 / librarian / reconciled
  Job: bg_000003
  Objective: librarian: find the default

#### Closed
- adv-1 / ses_child_0004 / advisor / failed
  Job: bg_000004
  Objective: advisor: review the migration
- loo-1 / ses_child_0005 / looker / cancelled
  Job: bg_000005
  Objective: looker: read the screenshot

  Per job: alias / session id / agent / state, plus the job id and the objective —
  slim's four fields (board-injection.ts consumers, background-job-board.ts:755-769)
  plus the job id, which slim cannot show because it does not have one.
  Pinned byte-for-byte by the_board_renders_in_one_pinned_shape.
  Nothing time-dependent renders (slim excludes ages for the same cache reason,
  background-job-board.ts:839-841).

11. WHAT REMAINS FOR THE WIRING TODO
===============================================================================
  oc-tools' `task` tool is NOT wired to this board — deliberately. Its
  `ChildTurnHost::dispatch` already takes `resume_session_id` and returns
  `background_id`, which is the right seam, but oc-tools was out of scope this wave.
  The implementor of that host should:
    - call JobBoard::dispatch and map ContinuationError onto ToolError
      (ActiveLane / NotReusable / VanishedSession -> Failed, since none is fixable by
       reissuing the same arguments; UnknownTaskId / ForeignParent / AgentMismatch ->
       InvalidArgs, since a different task_id fixes them),
    - return Dispatched::job_id as ChildTurn::background_id (it already satisfies the
      tool's "never the session id" check — every job id is `bg_NNNNNN` from the
      board's own sequence, asserted by no_job_id_is_ever_a_session_id),
    - call JobBoard::settle on completion and JobBoard::reconcile once the parent has
      read the result — two events, not one; a lane is addressable only after the
      second,
    - inject JobBoard::render(parent) into the coordinator's context each turn.

  HONEST LIMIT: RunState defers to SessionRunRegistry, which is in-process
  (oc-engine/src/status.rs:1-6). This board refuses a collision it can see inside one
  process. It is NOT a cross-process lock and nothing here claims to be one.
