2. Real TypeScript/Zod fixture
import { z } from "zod";

export default {
  description: "Return fixture weather.",
  args: {
    city: z.string().describe("City to inspect"),
    unit: z.enum(["c", "f"]).optional().describe("Temperature unit"),
  },
  async execute(args, context) {
    context.metadata({ title: "Weather lookup", metadata: { agent: context.agent } });
    return `${args.city}:${args.unit ?? "c"}`;
  },
};

Observed schema fields (asserted literally by the integration test):
{
  "type": "object",
  "properties": {
    "city": { "type": "string", "description": "City to inspect" },
    "unit": {
      "type": "string",
      "enum": ["c", "f"],
      "description": "Temperature unit"
    }
  },
  "required": ["city"]
}

Observed execution: {"city":"Oslo","unit":"f"} -> title "Weather lookup",
output "Oslo:f", metadata.agent "build". "kelvin" is rejected by JS safeParse and
arrives in Rust as ToolError::InvalidArgs.
