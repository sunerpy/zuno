Implemented behavior
--------------------
1. `migration::apply_only` reads the journal and rejects its greatest id when that
   id is lexicographically above the greatest id compiled into `MIGRATION_IDS`.
2. The ceiling is derived with `MIGRATION_IDS.iter().max()`; no production literal
   can drift from the migration set.
3. `DbError::MigrationTooNew` names both the known ceiling and observed id and is
   non-retryable.
4. Unknown journal ids below the ceiling remain tolerated.
5. The check runs before migration SQL and before the production `db` command can
   serve the caller's query.
