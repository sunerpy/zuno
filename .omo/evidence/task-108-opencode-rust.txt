0. SUMMARY
----------
A user whose config fully specifies its own provider and model could not start
this binary at all when OPENCODE_DISABLE_MODELS_FETCH was set with an empty
cache — the air-gapped / private-gateway case. Ours exited 1; the released
1.18.12 exited 0 and listed the config-only model. Fixed by porting upstream's
third fallback (`models-dev.ts:222` returns `{}`, not an error) and moving the
fail-fast to where its own doc comment always meant it: a model nothing defines.

4. NO SNAPSHOT WAS EMBEDDED, AND WHY
------------------------------------
Decision: implement rungs 1 and 3 (on-disk cache, empty-catalog fallback) and
deliberately NOT rung 2 (the bundled snapshot).

Measured reason: the oracle's snapshot is not a copy of models.dev. It contains
exactly the seven `opencode/*` models of that release's hosted gateway — six of
them `-free` preview names that rotate between releases. Embedding a frozen copy
would make this binary advertise models on someone else's gateway from a list it
can never refresh, which is worst for exactly the air-gapped user this todo
serves, and would require a committed blob to keep current forever. Fetching one
at build time is forbidden (this workspace builds --offline throughout).

The empty-catalog fallback alone satisfies every acceptance criterion: the
config-only case works (section 1), unknown models still fail (section 3), and
parity holds for anything the user's own config declares (section 2). The cost
is a listing-only difference under the disabled flag with no cache: upstream
lists its seven gateway models, we list none. Recorded in
`crates/oc-llm/src/catalog/source.rs` module docs under "Rung 2 is deliberately
absent".


5. THE FIXTURE CLEANUP — THE REASON FIVE WAVES MISSED THIS
----------------------------------------------------------
`crates/oc-cli/tests/tui_turn.rs` and `tests/tool_turn.rs` both injected
OPENCODE_MODELS_PATH pointing at `oc-llm/tests/fixtures/models-dev-pinned.json`.
That injection is why the seam tests never saw the defect: they handed the
binary the very catalog the product should not have needed.

Both injections removed, along with the now-unused `models_fixture()` helper in
tui_turn.rs. Both still pass, and they now execute genuinely:

    HAPPY_QA submission=Flag  pty_requests=3
    HAPPY_QA submission=Typed pty_requests=3

    test a_prompt_typed_into_the_pty_drives_the_same_turn_as_the_flag ... ok

`crates/oc-testkit/src/env.rs:218` (OPENCODE_DISABLE_MODELS_FETCH=1) was left
untouched, as required. The product now works under that invariant rather than
around it.

8. WHAT CHANGED
---------------
crates/oc-llm/src/catalog/source.rs
  - `load()` now returns `LoadedCatalog` (document + `CatalogProvenance`) and
    succeeds with an empty document under a forbidden fetch, tagged
    `FetchForbidden { origin, cache }`.
  - New `CatalogProvenance` enum: ExplicitPath / Cache / Fetched /
    FetchForbidden. It exists because the *same* empty document means two
    opposite things, and a caller with no way to tell them apart must either
    fail on both (breaking the air-gapped user) or on neither (letting an
    unknown model surface as an empty picker).
  - New `CatalogProvenance::unresolved_model(requested)` -> Option<CatalogError>:
    Some only under FetchForbidden. Called only AFTER the resolved-catalog
    lookup fails, which is the whole ordering constraint of the fix.
  - Module docs rewritten: the old "The divergence, stated precisely" section
    argued for the error and is now "Fetching disabled with nothing on disk is
    not a failure" plus "Rung 2 is deliberately absent".
  - `refresh()` now returns the new `CatalogError::RefreshDisabled`, keeping the
    unconditional fail-fast where it is still correct.

crates/oc-llm/src/catalog/error.rs
  - `FetchDisabled` gains a `requested` field; its message leads with the model
    id and names the `provider` config block as the first fix.
  - New `RefreshDisabled` variant for `models --refresh`.
  - Module docs rewritten to describe the case the variant now covers, per the
    task's requirement that a stale rationale is worse than none. The original
    argument is preserved and credited; what changed is where it applies.

crates/oc-llm/src/catalog.rs
  - Re-exports `CatalogProvenance` and `LoadedCatalog`; pipeline stage 1 doc now
    records that the document may legitimately be empty, citing models-dev.ts:222.

crates/oc-cli/src/cmd/turn.rs
  - `select_model` takes the provenance and consults it only after the lookup
    fails; the no-request branch also names the policy so "no available model"
    cannot read as "you configured nothing".

crates/oc-cli/src/cmd/models.rs
  - unwraps the new `LoadedCatalog` into its document.

crates/oc-cli/tests/{tui_turn,tool_turn}.rs
  - OPENCODE_MODELS_PATH injections removed, with a comment recording why the
    absence is deliberate (an absence cannot be self-documenting).


9. WHAT THE PLAN GOT WRONG
--------------------------
Nothing material. Two refinements worth recording:

(a) The plan says the bundled snapshot is what makes upstream work for the
    config-only case. Measured, that is not the mechanism: the snapshot supplies
    the seven `opencode/*` gateway models, and `test/test-model` comes from the
    config being merged over whatever the load returned. Skipping the snapshot
    therefore costs nothing for the case the todo is about — which is why the
    "empty-catalog fallback alone satisfies every criterion" note in the prompt
    is correct.

(b) `~/.cache/opencode/models.json` does exist on this machine (3.6 MB) and
    could have been copied. It was not, for the reason in section 4.
