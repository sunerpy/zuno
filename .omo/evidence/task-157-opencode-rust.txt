Task 157 — show edit permission subject and diff in collapsed/fullscreen TUI
================================================================================

Defect and root cause
--------------------------------------------------------------------------------
- Worktree: `/config/workspace/ProdDir/AI/oc-wt/t157`, branch `task-157`.
- F3-W9-D1 reproduced in the real TUI: an edit permission prompt displayed only
  `Edit`; both the normal dialog and Ctrl+F fullscreen omitted the file path and
  the change being approved. F3-W9-O1 also reproduced: the footer advertised
  `⇆ select`, although only Up/Down changed the selection.
- The production dispatcher already stores the complete decoded call input under
  `PermissionAsk.metadata.arguments`, and the edit path is also present in
  `patterns`. `PermissionBridge` passed those arguments after todo 150.
- The remaining loss was in `permission.rs`: edit read only the legacy top-level
  `metadata.filepath`, while `PermissionPrompt::new` waited only for a top-level
  `metadata.diff` that production edit dispatch does not write. Fullscreen had no
  independent data source, so it expanded an already-empty view.

Implementation
--------------------------------------------------------------------------------
- `PermissionBridge::pump` uses `request_arguments`, accepting only an object and
  falling back to an empty object. This preserves the production argument shape
  while keeping every description helper safe on malformed or missing metadata.
- `edit_path` resolves `filePath`, `file_path`, or `path`, then the legacy
  `metadata.filepath`, then the request's first pattern. The subject and a `Path`
  detail therefore identify the resource being approved.
- `edit_patch` prefers an existing metadata diff or explicit patch argument. When
  edit supplies the production `oldString`/`newString` pair, `replacement_patch`
  emits a unified replacement hunk consumed by the existing `DiffView`.
- The same `PermissionPrompt` subject and `DiffView` render in collapsed and
  fullscreen layouts. The footer now advertises `↑↓ select`, matching the actions
  the dialog actually handles.
- A table-driven audit covers every permission branch handled by `describe()` and
  renders each non-empty subject, including the pattern-derived external-directory
  case. No HTTP permission path or dependency changed.
