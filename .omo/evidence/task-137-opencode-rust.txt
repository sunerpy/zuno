task 137 — crates/oc-plugin: three-tier coexistence against the two REAL auth plugins
=====================================================================================

F1 blocking finding 5. Criterion 7 required a Rust plugin and a WASM plugin to
load alongside the two real auth plugins named by criterion 6.
`three_tiers_follow_configuration_order` previously used the synthetic
`integration-js` fixture, so nothing proved the real packages coexist.


1. THE TWO REAL PLUGINS — ACTUAL ON-DISK PATHS AND VERSIONS
-----------------------------------------------------------
Confirmed by `find /config/.cache /config/.local/share/opencode -maxdepth 5
-type d -name "*kiro-auth@*"` and by loading them in-process:

  opencode-antigravity-auth@1.6.0
    /config/.cache/opencode/packages/opencode-antigravity-auth@1.6.0/
      node_modules/opencode-antigravity-auth

  @sunerpy/opencode-kiro-auth@0.20.6
    /config/.cache/opencode/packages/@sunerpy/opencode-kiro-auth@0.20.6/
      node_modules/@sunerpy/opencode-kiro-auth

Only 0.20.2 and 0.20.6 of kiro-auth exist on this host; 0.20.1 is gone, as the
plan states. `SUPPORTED_JS_PLUGINS` names 0.20.6, so `supported_spec()` derives
both specs rather than typing a version — the same anti-drift device
`tests/js.rs` uses. The structure matches the old layout
(`packages/<pkg>@<ver>/node_modules/<pkg>`), so no path change was needed.

Measured runtime manifests (throwaway probe, since deleted):
  antigravity  id=opencode-antigravity-auth@1.6.0  hooks=[Event, Tool, Auth]
               auth.provider="google"   sdk=<its own @opencode-ai/sdk>
               diagnostic: Compatibility "plugin declares @opencode-ai/plugin
               ^0.15.30; host reports 1.18.13"  (a warning, still serves)
  kiro         id=kiro-auth  hooks=[Config, Auth, Provider, ChatHeaders]
               auth.provider="kiro-auth" sdk=<its own @opencode-ai/sdk>
  rust example id=integration-rust hooks=[ChatParams, ShellEnv, TextComplete]
  wasm example id=integration-wasm  (only ChatSystemTransform is mutable)

The four tiers therefore share NO mutating hook. That is a property of the real
packages, not a convenience, and it dictated the assertion design below.


2. DELIVERABLE — REAL THREE-TIER COEXISTENCE IN CONFIGURATION ORDER
-------------------------------------------------------------------
`crates/oc-plugin/tests/integration.rs::three_tiers_follow_configuration_order`
now loads all four real tiers in the order
[antigravity, rust-example, kiro, wasm-example] and asserts order three
independent ways:

  a. the bus's own identity sequence ==
     ["opencode-antigravity-auth@1.6.0", "integration-rust", "kiro-auth",
      "integration-wasm"]
  b. one TextComplete dispatch reaches all four in that order
     (`TrackedPlugin` records position; the test also asserts no hook is shared
     by all four, so the position log cannot be redundant)
  c. the two REAL `auth` hooks compose into an order-sensitive vector
     == ["google", "kiro-auth"]  — a real mutation by both real plugins
  d. text output "x!|x!": the Rust example's real suffix lands BEFORE the WASM
     tier doubles it, because that is the configured order
  e. the real kiro `chat.headers` hook still injects
     x-opencode-kiro-request-kind=compaction from inside the four-plugin bus,
     and injects nothing for a non-compaction turn
  f. Dispose reaches every tier in configuration order

`reversing_configuration_order_reverses_real_plugin_dispatch` runs the reverse
order and asserts the dispatch log, the text ("x|x!" — doubling now precedes
the suffix) and the auth vector ["kiro-auth", "google"] all flip. A single
order cannot satisfy both tests.

The old synthetic test is preserved verbatim as
`three_synthetic_tiers_follow_configuration_order` — no coverage was removed.


3. DELIVERABLE — KILLING ANY ONE TIER DEGRADES ONLY THAT TIER
-------------------------------------------------------------
Three new tests, one per kill mechanism, each asserting the OTHER THREE tiers
still produce their real effects:

  killing_the_rust_tier_leaves_the_real_auth_plugins_serving
    SIGKILL the JSON-RPC child → rust drops out of dispatch, one
    PluginDiagnosticKind::Crashed, text loses only the "!" ("x|x"), and BOTH
    real auth providers plus kiro's real header still serve.

  a_runaway_wasm_tier_leaves_the_real_auth_plugins_serving
    an infinite-loop component → PluginDiagnosticKind::TimedOut, the wasm tier
    is disabled and absent from the second dispatch, text stays "x!", both real
    auth providers and kiro's real header still serve.

  starving_one_real_auth_plugin_leaves_its_javascript_sibling_serving
    kiro gets an empty runtime search path → JsDiagnosticKind::MissingRuntime,
    kiro absent from the bus, antigravity's real "google" provider still
    registers, the other three tiers still dispatch, and NOTHING injects kiro's
    header (so the positive assertions elsewhere are not vacuous).

----------------------------------------------

  the kiro model/provider id changed from "kiro-auth" to "not-kiro"

So the order claim, the real-kiro-liveness claim and the real-auth-composition

6. HONEST SCOPE — WHAT IS DELIBERATELY NOT ASSERTED
---------------------------------------------------
`effort` is NOT asserted, for the reason already recorded at
`tests/js.rs`'s real-kiro header test: it is selected inside the plugin's own
AWS client on a live outbound Kiro request, which needs credentials and network
this suite forbids.

The `config` hook is NEVER dispatched. Kiro's real `config` hook calls
`bootstrapAuthIfNeeded` (`dist/plugin/auth-bootstrap.js:44`), which WRITES a
placeholder credential entry into the user's
`~/.local/share/opencode/auth.json`. Dispatching it would mutate real user
data. Verified untouched: auth.json mtime 2026-08-07 09:41:12, unchanged across
every run in this task.

`TrackedPlugin`'s only synthetic element is the position log. It forwards hooks
solely to hooks the wrapped plugin's own manifest declares; every behavioural
claim (text suffix, doubling, auth providers, kiro header, diagnostics) comes
from the real plugins.

8. CORRECTION TO THE TASK BRIEF
-------------------------------
The brief said to replace the synthetic fixture. I kept it, renamed to
`three_synthetic_tiers_follow_configuration_order`, and added the real-plugin
test beside it. Reason: the synthetic JS fixture is the only tier that pins the
JS host's own dispose-to-file and PID-reaping path with a mutating
`experimental.text.complete` hook, which NEITHER real auth plugin implements.
Deleting it would have traded one coverage gap for another — and weakening
existing tests is forbidden. Both now run.
