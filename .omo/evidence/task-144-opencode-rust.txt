WHY THIS EXISTED
--------------------------------------------------------------------------------
`HookInvocation::Auth` and `HookInvocation::Tool` appeared only in the hook
dispatcher's own definition (`oc-plugin/src/hooks.rs:198,208`) and in the JSON-RPC
transport enums. There was no production caller in `oc-cli` or `oc-engine`.

This is the inverse of the project's usual defect: `hooks.rs`'s own tests DID
dispatch both, so every suite stayed green while production was missing a wire.
Test doubles more complete than production, rather than friendlier than reality.

WHERE THEY ARE NOW DISPATCHED
--------------------------------------------------------------------------------
  crates/oc-cli/src/cmd/plugin_runtime.rs:82   HookInvocation::Auth
  crates/oc-cli/src/cmd/plugin_runtime.rs:137  HookInvocation::Tool

Plugin tools join the governed set through the same `tools.extend` path that
config-directory tools and MCP tools already use (`oc-tools/src/registry.rs:285`),
so they inherit the existing projection and permission handling rather than
getting a parallel route.
