Retry-path inspection (before reproduction)
-------------------------------------------
- `TurnHost::drive_input` calls `oc_engine::loop::run_turn` once and maps its error through `describe_turn_failure`.
- `run_turn` reads `provider.stream(...)` directly and returns the first `ProviderError` (`let event = next?`); it does not call `retry_provider`.
- `ProviderRetryPolicy` exists in `oc-engine::retry`, but repository search found no production call from `run_turn` or `oc-cli`; compatible-provider translation also returns a transport error once and terminates.
- Therefore a stalled compatible-provider response is attempted exactly once. Worst-case production wall time attributable to this idle gap is one effective idle window (the compatible transport's bounded default is 120 s, capped at 180 s for explicit transport overrides) plus scheduler/error-rendering overhead, not N × timeout. The shared compatible-provider SSE wait is a second outer guard, but no retry follows either guard.
- Mutation-design warning: setting `OPENCODE_STREAM_IDLE_TIMEOUT_SECS` shortens both the transport and the compatible provider's outer SSE guard. Removing only the transport timeout under that setup is an equivalent mutant. The durable test must inject a short timeout into `ReqwestTransport` while leaving the provider's outer timeout longer.

Mutation results (each restored immediately)
--------------------------------------------
1. Removed the actual `ReqwestTransport` per-chunk `tokio::time::timeout`, changing the unfold to await `body.next()` without a bound. The provider-level timeout in the test is deliberately 2 s, so this was proven non-equivalent before interpreting the result. Command:
   `cargo test -p oc-cli a_stalled_provider_ends_a_real_turn_with_partial_text_and_a_visible_idle_error --offline`

   Result: the named test failed after 1.03 s at its outer turn budget:
   ```text
   test cmd::turn::tests::a_stalled_provider_ends_a_real_turn_with_partial_text_and_a_visible_idle_error ... FAILED
   the real turn must finish inside its one-second test budget: Elapsed(())
   test result: FAILED. 0 passed; 1 failed; ... 100 filtered out
   ```
   This proves the new turn-level test guards the transport bound itself, not the compatible provider's second SSE guard.

2. Made the bound fire too eagerly by changing the transport wait from `idle.duration()` to `idle.duration() / 3`. With the progressing fixture's configured 150 ms allowance this yields 50 ms, less than each intentional 60 ms gap. Command:
   `cargo test -p oc-cli a_slow_but_progressing_real_turn_outlives_one_transport_idle_window --offline`

   Result: the named test failed after the premature close (the fixture observed `Broken pipe` while sending the next valid progress chunk):
   ```text
   test cmd::turn::tests::a_slow_but_progressing_real_turn_outlives_one_transport_idle_window ... FAILED
   write turn response chunk: Os { code: 32, kind: BrokenPipe, message: "Broken pipe" }
   test result: FAILED. 0 passed; 1 failed; ... 100 filtered out
   ```
   This proves the progress test is sensitive to a timeout that does not preserve the full per-chunk allowance.

Both mutations were restored in `crates/oc-provider-compatible/src/transport.rs`; no production timeout value or cap is part of the intended diff.
