## Upstream precedence (2026-08-14)

Two independent legs establish the last-source-wins policy.

**Leg 1 — mechanism, read from source.** The sources read were the upstream `1.18.16` tree at
`/tmp/opencode-src`, commit `d470434` (dated 2026-08-11), verified in place:

```console
$ grep -m1 '"version"' /tmp/opencode-src/packages/opencode/package.json
  "version": "1.18.16",
$ git -C /tmp/opencode-src log --oneline -1
d470434 refactor(console): simplify go usage response
```

All `file:line` citations below are verbatim-true for that `1.18.16` tree and are attributed to it:

- `packages/opencode/src/tool/registry.ts:178-190` appends config-directory tools to `custom`.
- `packages/opencode/src/tool/registry.ts:194-198` appends plugin tools after config-directory tools.
- `packages/opencode/src/tool/registry.ts:224-253` returns `builtin` before `custom` from `all()`.
- `packages/opencode/src/session/tools.ts:92-99` iterates those registry tools in order and assigns
  `tools[item.id] = ...`; a later config/plugin implementation therefore replaces an earlier
  builtin implementation with the same id.
- `packages/opencode/src/session/tools.ts:390-489` assigns MCP tools to the same keyed object after
  registry tools, so an MCP implementation replaces any same-named builtin/config/plugin tool.

The resulting precedence is therefore **MCP > plugin > config-directory > builtin**. JavaScript
property reassignment retains the key's original insertion position, so the compatible Rust
projection must keep one entry at the first occurrence's position while replacing its implementation
with the last source's tool. The Rust assembly chokepoint before this fix is
`crates/oc-tools/src/registry.rs:267-287` at pre-fix commit `24b64510`: it appends all four sources
to a `Vec` without keyed replacement, allowing duplicate provider-facing ids through. Those line
numbers do not describe HEAD after the fix and therefore always carry that revision.

**Leg 2 — behaviour at 1.18.18, confirmed empirically rather than from source.** The installed
`1.18.18` binary runs the identical plugin configuration successfully:

```console
$ /config/.local/share/mise/installs/opencode/1.18.18/opencode run \
    --model myopenai/global.anthropic.claude-haiku-4-5-20251001-v1:0 "hi"
你好！我是 Sisyphus…      (a real answer, same plugins active)
```

**Stated limitation.** The `1.18.18` install ships only a compiled binary with no TypeScript
sources, so its sources could not be read. `git fetch --tags` to compare `v1.18.16..v1.18.18`
timed out on the network and was not completed, so the two patch versions were not diffed. The
mechanism above is therefore verified at `1.18.16` and only behaviourally confirmed at `1.18.18`.
