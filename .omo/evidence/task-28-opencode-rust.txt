FIVE DISTINCT REASONING REPRESENTATIONS
1. ContentBlock::Reasoning: unsigned/plain reasoning retained in the transcript; generic outbound conversion excludes it because replaying unsigned thinking can be rejected.
2. ContentBlock::ReasoningTrace: history/debug-only trace retained in storage; generic outbound conversion excludes it to prevent permanent token cost.
3. ContentBlock::SignedThinking: thinking and provider signature travel together and are replayable.
4. ContentBlock::ProviderEncryptedReasoning: native id, summaries, encrypted_content and status survive storage and replay for providers such as OpenAI Responses with store=false.
5. ThoughtSignature on ContentBlock::ToolUse: a distinct newtype tied to one tool call so Gemini 3 multi-turn function calls replay the matching signature.

TYPE-LEVEL REPLAY BOUNDARY
TranscriptMessage stores Vec<ContentBlock>. Message, the Provider::stream request type, stores Vec<RequestContentBlock>. RequestContentBlock has no Reasoning or ReasoningTrace variant. TranscriptMessage::to_request filters both forms before creating the provider-bound type; signed thinking, encrypted reasoning, and per-tool thought signatures are preserved.
