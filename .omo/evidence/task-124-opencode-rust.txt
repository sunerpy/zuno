2. WHAT WAS ADDED
--------------------------------------------------------------------------------
`crates/oc-cli/tests/surface.rs` only.

a) `surface_every_implemented_command_reaches_its_handler_through_the_production_dispatcher`
   The guard. Runs the shipped binary once per implemented command, in a private
   temporary root with the same isolation `tests/differential.rs` uses (HOME and
   all four XDG dirs redirected, OPENCODE_DB redirected, autoupdate / models
   fetch / default plugins / LSP download disabled). For each probe it asserts
   two things about the combined stdout+stderr the user would see:
     - neither of `PendingCommandDispatcher`'s two sentences appears, anchored on
       the command name so a handler that legitimately says "is not available"
       about something else cannot trip it (`run --fork` does exactly that);
     - a fragment ONLY THAT COMMAND'S HANDLER emits does appear.
   The second assertion is what makes the test non-vacuous. Absence-only
   checking would pass against an arm replaced with `Ok(())`; see section 4.

b) `surface_failure_scenario_the_binary_prints_a_pending_marker_for_a_stub`
   The negative control for (a), driven through the binary rather than by
   calling `PendingCommandDispatcher` directly. Proves "no probe printed a
   pending marker" is a live observation and not a string nothing can produce
   any more. `completion` is the one command legitimately routed to the stub.

c) `IMPLEMENTED_PROBES` became a struct with an `evidence` field. Each probe's
   argv is chosen to reach the handler and return promptly without network or
   writes outside the temporary root. Two arms are entered through a flag the
   handler itself refuses — `serve --mdns`, `run --fork` — because that refusal
   is produced INSIDE the handler, after routing; a bare `serve` would block on
   a listening socket and a bare `run` would want a provider.

d) The two pre-existing guards were KEPT, not deleted, and one was RENAMED to
   its true scope: `surface_no_implemented_disposition_routes_to_the_pending_handler`
   -> `surface_no_implemented_disposition_parses_into_the_pending_variant`.
   It still catches something the new guard does not: a command registered
   straight onto `DispatchArguments::Pending`, which is `completion`'s shape.
   Its doc comment now states the limit F2 found instead of overstating reach.
   `surface_every_implemented_command_actually_has_a_handler` is unchanged in
   substance and is load-bearing for the new guard: it makes `IMPLEMENTED_PROBES`
   a bijection with the implemented dispositions, which is what turns the new
   guard from a sample into full coverage.

No dependency was added: `tempfile` was already a dev-dependency of `oc-cli`.
