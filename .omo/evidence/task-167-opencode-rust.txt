Thus `providerID` is the only spelling difference, but `family` and `variants`

DECISION
--------------------------------------------------------------------------------
Convert at the JavaScript plugin boundary rather than adding a global serde alias.
`ResolvedModel` remains one canonical snake_case internal/serialized shape, while
`HandleModelLoader` normalizes the SDK's `providerID` before deserialization. The
two SDK-optional fields receive serde defaults on the resolved type because their
empty internal values are already the catalog's canonical meaning. This avoids
letting SDK spellings drift into pinned-catalog/internal consumers while preserving
the existing internal `provider_id` path.

IMPLEMENTATION AND RESTORED CONTROL
--------------------------------------------------------------------------------
The bridge now clones each JavaScript model at the boundary and renames
`providerID` to canonical `provider_id` only when the canonical key is absent.
`ResolvedModel.family` and `.variants` have serde defaults, matching the two
optional SDK fields without changing serialized internal field names. All other
fields continue through the existing strict `ResolvedModel` decoder. The original
per-model error branch is unchanged.
