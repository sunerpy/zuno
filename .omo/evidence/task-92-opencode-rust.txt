EVERY TABLE IS DERIVED FROM CODE, NOT TRANSCRIBED
=================================================

The prohibition is "must NOT hand-maintain any table the code also asserts", and a
docs test that reads its own prose proves nothing. Each generated block therefore
takes its EXPECTED side from a live code artifact and its ACTUAL side from the
committed Markdown, delimited by `<!-- generated:BEGIN/END name -->`:

| block                | source of truth                                            |
|----------------------|------------------------------------------------------------|
| divergence-detail    | oc_testkit::DivergenceList over docs/divergences.toml       |
| divergence-index     | same list, cross-checked vs divergence::DECLARED_COUNT      |
| cli-disposition      | oc_cli::dispositions()  (23 rows)                           |
| api-operations       | oc_server::api::openapi() minus the committed 1.18.12       |
|                      | oracle capture, then each served route PROBED through the    |
|                      | real router for a 501                                       |
| v1-routes            | oc_server::V1_SURFACE  (20 routes)                          |
| rejected-inputs      | messages RENDERED BY oc_config::legacy's inspect_* fns      |
| plugin-hooks         | oc_plugin::HookName::ALL  (21 hooks)                        |
| prune-tables         | oc_db::prune::DELETE_ORDER  (10 tables)                     |
| migration-journal    | oc_db::migration::MIGRATION_IDS  (38 ids)                   |

`OC_DOCS_REGENERATE=1 cargo test -p oc-cli --test docs` rewrites each block from
the code and re-asserts. Prose outside the markers is never touched.

The api-operations block is the strongest of these: it does not read the route
registration source, it drives the assembled axum router with a request per
operation and records which answer 501. So "registered (501 stub)" cannot be
claimed for a route that gained a handler, or withheld from one that lost it.

A RACE THE FIRST DRAFT HAD, AND THE STRUCTURE THAT FIXES IT
===========================================================

The first version had one test per generated block. Under regeneration, two tests
writing two blocks of the SAME page each did read-modify-write and silently
discarded the other's write — observed as `has no <!-- generated:BEGIN
divergence-index --> marker` on a file that did have it. Consolidated to one test
per file (docs_compatibility_matrix_matches_every_code_table checks all four
matrix blocks). The constraint is recorded in a doc comment on that test, because
splitting it back into four is the natural refactor and would reintroduce the bug.

THINGS THE BRIEFING OR THE PLAN GOT WRONG
=========================================

1. "soak.rs and G6 are #[ignore]d". Only one test in the workspace carries
   #[ignore]: crates/oc-testkit/tests/soak.rs:683, the 500-turn real-driver soak.
   G6 (crates/oc-process/tests/containment.rs) is NOT ignored — both its tests
   run in the ordinary suite. Documented as measured: G5 and G6 run, G1/G2 need
   OC_MEMORY_GATE_MODE=run, G3/G4's real-driver soak needs --ignored.

2. "G4 | no trip | 120 s / 1800 s". Those are two separate bounds, not a value
   and a limit: a 120 s meaningful-progress timeout and an 1800 s per-turn hard
   deadline (crates/oc-testkit/src/perf/methodology.rs:58-59,
   docs/perf-methodology.md:149). The README states both.

3. "todo 10's rejection list" is not a table. There is no const array of rows;
   there are 10 DeprecatedForm variants whose messages are CONSTRUCTED per input
   by Deprecation::message(), embedding the offending file's path. So a
   documentation test cannot compare a documented table against a code table —
   it has to RUN the detectors and compare rendered output, which is what
   docs.rs does. This is a better outcome than the plan's framing: the assertion
   is against behaviour rather than against a literal.

4. The CLI disposition table has no `Renamed` disposition. `providers` keeps
   upstream's `auth` alias and `TuiThreadCommand` gains the explicit spelling
   `tui`; both are expressed through the command and reason fields. The matrix
   therefore documents three states for CLI commands, not four.

5. "docs/ currently holds divergences.toml, perf-methodology.md,
   v1-surface-capture.md" — correct, and v1-surface-capture.md was left alone.
   It is a capture record, not a compatibility page; the matrix links to
   V1_SURFACE's generated table instead so the two cannot disagree.
