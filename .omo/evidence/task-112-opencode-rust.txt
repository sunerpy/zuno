THE DESIGN, AND WHY ONE SEAM
============================
`TurnError` and `ProviderError` classify a failure and hang the detail off a
`#[source]`. `describe_turn_failure` rendered `error.to_string()`, which renders
exactly one level, so every connection-level failure printed its category and
discarded the detail that was sitting one `source()` call away.

Todo 109 fixed that for a missing endpoint and todo 110 for a rejected
credential, each by composing a better message for one variant. Both fixes are
correct and neither generalises — which is why the third instance still reached a
user. The fix here is one walk:

  oc-error/src/source.rs   `pub fn describe(&dyn Error) -> String`
                           walks `source()`, appends each cause after `": "`,
                           innermost last; skips a cause the message already
                           carries; caps at MAX_CAUSES = 8 and ends in `…` when
                           it truncates.

  oc-cli/src/cmd/turn.rs   `describe_turn_failure(&TurnError, Option<&str>)`
                           calls `describe`, appends the auth advice todo 110
                           added, then scrubs the turn's own credential.

Checked before writing it: `oc-error` had no chain helper — `source.rs` declared
only the `BoxSource` type alias, and the only chain walk in the workspace was a
`while let` loop inside a test (`oc-error/tests/taxonomy.rs:369`).

Per-variant handling was rejected on the evidence of 109 and 110: a variant-by-
variant answer requires an author to remember, at every new `#[source]` site,
that rendering exists. Walking once at the rendering seam means a variant added
later gains its cause with no edit. `describe_turn_failure` is the only place in
the workspace where a `TurnError` is rendered for a user (verified by grep), so
"one seam" is a fact about the code and not an aspiration.

Depth, separator and duplicate suppression were each decided rather than
defaulted:
  - depth 8, because a real transport failure is already 3-4 links deep
    (reqwest error -> hyper client error -> connect error -> io::Error) and the
    walk follows pointers a foreign crate owns, so a bound beats trusting them.
  - `": "`, matching how the errors already read; without it two causes fuse.
  - duplicate suppression, so an `#[error(transparent)]` wrapper and a variant
    that interpolates its own source do not say the same words twice. A skipped
    link does *not* end the walk — the detail may be beneath it.

BEFORE / AFTER, THREE DISTINCT FAILURE KINDS
============================================
Real binary, isolated HOME/XDG, `run --model test/test-model hi`.

1. unset `${GW_HOST}` in `provider.test.options.baseURL`

   before: transient provider failure (status=None)
   after:  transient provider failure (status=None): builder error for url
           (http://${gw_host}/v1/chat/completions): Parsed Url is not a valid Uri

   The variable name is now legible. It arrives lowercased because the `url`
   crate folds a host; the case is gone before the error value exists, so the
   seam cannot restore it. The integration assertion is therefore
   case-insensitive, and says so.

2. typo'd hostname (`gatway.example.com`)

   before: transient provider failure (status=None)
   after:  transient provider failure (status=None): error sending request for
           url (http://gatway.example.com/v1/chat/completions): client error
           (Connect): dns error: failed to lookup address information: No
           address associated with hostname

3. dead port (`127.0.0.1:9`)

   before: transient provider failure (status=None)
   after:  transient provider failure (status=None): error sending request for
           url (http://127.0.0.1:9/v1/chat/completions): client error (Connect):
           tcp connect error: Connection refused (os error 111)

   Kinds 1-3 were byte-identical before this change. They are now

4. auth rejection from a gateway that echoes the key it rejected

   after:  authentication rejected by provider test: provider `test` returned
           HTTP 401: {"error": {"message": "Incorrect API key provided:

           `opencode auth login test`

   Todo 110's two key locations survive. The advice is joined with `;` rather
   than `:` now that everything before it is a chain of causes.

NO CREDENTIAL LEAKS — WHY THIS NEEDED ENFORCING, NOT ASSUMING
=============================================================
Todo 110's guarantee held structurally: its message was built from the provider
id, so no secret had a channel to travel down. Walking the chain opens one — the
innermost link on the auth path is the vendor's own 401 body, and
`Incorrect API key provided: sk-…` is how real gateways word it. The notepad
flagged this as "probably not" a leak; "probably" is not the standard.

Measured against a local listener that echoes the `Authorization` header it
received, with `provider.test.options.apiKey = sk-SUPERSECRET-DO-NOT-ECHO`:

  rendered failure:                        contains `<redacted>`, not the key
  key occurrences in stdout+stderr:        0
  key occurrences anywhere under the
    isolated HOME/XDG/TMPDIR after the run: 0 (grep -rl SUPERSECRET)

The scrub removes the exact credential the turn presented, taken from the same
value the provider factory closes over, so it covers both sources
`resolved_credential` can pick (`options.apiKey` and the auth store) — the
integration test runs both. It is an exact removal rather than a
credential-shaped pattern search: the one secret that matters is known here, and
a pattern guess would be both weaker and prone to redacting a user's prose. An
empty credential is skipped, because `str::replace` with an empty pattern
inserts its replacement between every character and `apiKey: ""` is a documented
legitimate configuration.

WHAT THE TASK BRIEF GOT RIGHT, AND ONE THING IT DID NOT
=======================================================
Right: the diagnosis, the seam, the three-instances-is-the-signal call, and the
warning that "it contains the URL" is not the same as "the user can act on it".

Not quite right: the brief expected the unexpanded literal to surface as
`${GW_HOST}`. It surfaces as `${gw_host}` — reqwest reports the URL through
`url::Url`, which lowercases the host. The intent (a user can see which variable
went unexpanded) is satisfied; the exact casing cannot be, at this seam, because
the information is destroyed upstream of the error value. The test asserts
case-insensitively and documents the reason rather than asserting a spelling the
code cannot produce.
