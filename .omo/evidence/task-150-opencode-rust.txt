Task 150 — TUI permission arguments and keyboard resolution evidence
=====================================================================

Baseline and root cause
-----------------------
- Worktree: `/config/workspace/ProdDir/AI/oc-wt/t150`, branch `task-150`.
- The existing debug binary reproduced F3-W8-D2 in a real 170x44 tmux terminal:
  the bash prompt rendered `# Shell command` followed by an empty row, and sending
  `Right` then `Enter` left the dialog open and the sentinel absent.
- The request already carried decoded input in `PermissionAsk.metadata.arguments`.
  `PermissionBridge::pump` discarded it by constructing `PermissionPrompt` with
  `Value::Null`.
- `KeyDispatcher` resolved only the static session scopes (`input`, `prompt`,
  `messages`, `app`). Therefore the editor's bindings consumed Enter, arrows and
  Ctrl+F before the open dialog could receive `dialog.select.*` or
  `permission.prompt.fullscreen` actions.

Implementation
--------------
- `PermissionBridge::pump` clones `metadata.arguments` and passes it to
  `PermissionPrompt::new`, retaining `Value::Null` only as the missing-metadata
  fallback.
- `ActionComponent::focused_scopes` lets the focused overlay prepend scopes at
  dispatch time. `PermissionBridge` exposes permission/dialog/session scopes only
  while its `DialogHost` is open, so normal input still owns Enter and arrows when
  no dialog is present.
- `PermissionPrompt` treats the Escape binding produced by the session scope
  (`session_interrupt`) exactly like `app_exit`: reject at the choice stage and
  cancel an intermediate confirmation/message stage.
