CRITERION 2: batched hydration, no N+1
================================================================================
Shape from message-v2.ts:98-123: collect message ids, one `IN (...)` pass over
part, group by message_id, zip. HYDRATION_CHUNK = 900 ids per statement.

  test hydrating_500_messages_costs_two_statements_not_501 ... ok

Measured, not inspected, and measured TWICE by independent mechanisms:
  - MessageStore::query_count() - every statement in the module is prepared
    through one private fn that increments a Cell; 500 messages x 3 parts
    hydrates in 2.
  - SQLite's own SQLITE_TRACE_STMT hook (rusqlite feature "trace", added to
    oc-db only) counts statements as the engine begins them; it also reports 2.
    A statement that escaped the wrapper would make the two numbers disagree and
    fail the test.
The counter is reset immediately before hydration so the 1500 setup writes are
excluded from the measurement.

  test message_hydrating_nothing_costs_one_statement_and_no_part_lookup ... ok
    (an empty message set issues no part lookup at all - 1 statement)
  test hydration_orders_messages_by_time_then_id_and_parts_by_id ... ok
    (messages ORDER BY time_created, id per message_session_time_created_id_idx;
     parts ORDER BY message_id, id per message-v2.ts:107; a message with no
     parts hydrates to an empty vec, matching `?? []` at line 120)
