3. EXEMPTIONS — NAMED PER COMMAND, WITH REASON AND WITNESS
-----------------------------------------------------------
Three streams on three commands are exempt. Each carries (a) a reason in the
table, checked to be substantive (> 120 chars) by
`every_exemption_states_a_reason_and_keeps_a_witness`; (b) a `Witness` — a
weaker fact that test OBSERVES against both running processes, so no exemption
is total blindness; (c) at least one still-compared observable on the same probe.

  run / stderr
    Reason: the refusal is the same refusal in different words — upstream
      "You must provide a message or a command", this port "a message is
      required" — covered by the declared `diagnostics-name-their-cause`
      divergence. The command's real work is not comparable at all: MEASURED on
      1.18.15 under this cleared environment, `run --agent nosuch hi` ANSWERED
      from the bundled `opencode/big-pickle` gateway model with no credential
      present, so comparing a turn means a live provider call. `oc-testkit` has
      no HTTP client in its dependency graph and `tests/no_http_client.rs` keeps
      it that way; the turn is compared against recorded traffic in
      `crates/oc-cli/tests/tool_turn.rs`.
    Witness: BothFail — observed oracle exit 1, subject exit 1.
    Still compared: exit status, stdout.

  serve / stderr
    Reason: upstream reports a failed bind as the opaque two-line
      "Unexpected error" / "ServeError", naming neither address nor cause; this
      port emits "could not bind HTTP server to 127.0.0.1:<port>: Address
      already in use (os error 98)". Declared `diagnostics-name-their-cause`.
      The port's message embeds the address, so the two texts cannot be made
      equal without deleting information a user needs. The probe binds an
      occupied port because a bare `serve` never exits (measured: 1.18.15 hit a
      60s timeout while listening on 0.0.0.0:4096).
    Witness: BothFail — observed oracle exit 1, subject exit 1.
    Still compared: exit status, stdout (both print the same unsecured-server
      warning; verified equal).

  tui / exit status AND stderr
    Reason: `tui` is this port's spelling for the command upstream registers as
      `$0` with no name of its own, so this argv does not ask the two binaries
      the same question. MEASURED: upstream reads `tui` as the positional
      DIRECTORY and fails with "Failed to change directory to <PROJECT>/tui"
      while still exiting 0; this port routes it to the terminal application,
      which refuses a piped stdout and exits 1. No argv asks both binaries to
      start an interactive session, and an interactive session has no comparable
      streams. Terminal behaviour is covered by `tests/tui_turn.rs` and oc-tui's
      lease tests.
    Witness: OracleStderrContains("Failed to change directory") — observed in
      the oracle's real stderr, which is what proves the spellings differ rather
      than the behaviour.
    Still compared: stdout (both empty).

`COMMANDS_WITH_EXEMPTIONS = ["run", "serve", "tui"]` freezes the exempt set BY
NAME, so one exemption cannot be traded for another while a count stays put.
`every_cited_divergence_is_declared` resolves every cited divergence id against
the loaded `docs/divergences.toml`.

5. NORMALIZATION — FIVE NAMED RULES, EACH WITH A NEGATIVE CONTROL
------------------------------------------------------------------
`crates/oc-testkit/src/cli_normalize.rs`, pinned by `cli_rule_names_are_pinned`:
  sgr-colour, error-prefix, prompt-chrome, self-program-name, json-key-order

Four map to `plain-cli-presentation`; `self-program-name` is not a divergence at
all (the two binaries have different names, so a sentence in which each names
ITSELF is the same sentence) and is an exact-literal replacement of
"<program> " — never a pattern.

Volatile paths are masked by exact literals taken from the ScriptedEnv the
process actually ran under, longest-first, proven by
`root_masking_is_literal_and_longest_first` (a neighbouring directory the run
did not create still diverges).

`canonicalize_json` follows todo 116's model: decode with serde_json, re-encode
with sorted keys, respelling integral floats as integers. It cannot add, drop or
change a key or value. Negative control
`canonicalization_does_not_make_unequal_json_equal` proves a renamed key, a
changed value, a dropped key, an extra key and a reordered array all survive as
differences. `the_pipeline_collapses_presentation_and_keeps_every_other_
difference` does the same for the whole pipeline on the real 1.18.15 shapes, and
`carriage_returns_are_not_forgiven` proves "\r\n" vs "\n" still fails.

Explicitly NOT normalized: line endings, interior whitespace, interior blank
lines, durations, numbers in general, non-SGR escape sequences.

Note on the plan's reference to todo 116's "58,011 bytes, JSON key ordering
ignored": that figure is from `.omo/WORKTREE.md:1895`, not from
`.omo/evidence/task-116-opencode-rust.txt`, whose seeded export measured
2225 bytes on both sides (`:160-164`). The MECHANISM the plan names —
canonicalise, ignore JSON key order — is real and is what this task reuses; only
the byte count belongs to a different measurement. Recorded so a later reader
does not attribute 58,011 to the task-116 evidence file.

11. CORRECTIONS TO THE TASK BRIEF
----------------------------------
Two numbers in the brief do not survive checking, and neither changes what was
built:

  * "套件比的是 29 个 help surface" — `.omo/evidence/F1-REPORT-wave4.md`
    contains no count of 29 and no phrase "help surface". What it counts is 23
    upstream commands (`:52`). The substance of the finding — that only selected
    families received oracle output comparison, and no matrix compared every
    implemented command's normalized streams — is exact and is what this task
    addressed.
  * "todo 116 ... 58,011 字节完全一致" — see section 5. The figure is from
    `.omo/WORKTREE.md:1895`, not from the task-116 evidence file, which records
    2225 bytes for its seeded export. The mechanism the brief points at is
    correct and was reused.

One brief instruction was met in spirit rather than literally: it asked for the
work in `crates/oc-testkit`. The comparison lives in
`crates/oc-cli/tests/cli_parity.rs` because it needs `oc_cli::dispositions()` to
form the bijection with the twelve implemented commands, and `oc-testkit` cannot
depend on `oc-cli` — `oc-cli` already dev-depends on `oc-testkit`, so the
reverse edge would be a cycle. The reusable half (the five normalization rules)
is in `oc-testkit` where it belongs; the half that must see the disposition table
sits beside `tests/surface.rs`, which is also where todo 124's dispatcher guard
lives, so the two guards a reader must compare are in the same directory.
