The table records the SDK wire shape, not an invented replacement. “API adapter” means
the v1 handler calls the existing /api handler and only translates the request/response
envelope or field spelling. “Local adapter” means it calls an existing lower-level store
or resolver already used by the product; it does not duplicate that business logic.

01 PUT /auth/{providerID} — client.auth.set
   request: path provider id; body Auth union: oauth{refresh,access,expires,enterpriseUrl?},
            api{key,metadata?}, or wellknown{key,token}; optional directory query.
   response: 200 bare boolean.
   backing: LOCAL ADAPTER over oc_auth::AuthStore::set; secrets remain Secret values.

02 POST /log — client.app.log
   request: {service,level:debug|info|warn|error,message,extra?}; optional directory query.
   response: 200 bare boolean.
   backing: LOCAL ADAPTER to the server diagnostic sink; body is validated and rendered
            without credentials or arbitrary Debug output.

03 GET /agent — client.app.agents
   request: optional directory query.
   response: 200 bare Agent[] (v1 name/mode/model/prompt/tools/options spelling).
   backing: API ADAPTER over GET /api/agent; unwrap {location,data} and project the
            resolved v2 Agent.Info values into the generated v1 Agent wire shape.

04 GET /config — client.config.get
   request: optional directory query.
   response: 200 bare Config.
   backing: LOCAL ADAPTER over oc_config::discovery::discover_with, the same resolver
            used by the catalogue and CLI; no /api/config route exists.

05 GET /provider — client.provider.list
   request: optional directory query.
   response: 200 {all:Provider[],default:Record<string,string>,connected:string[]}.
   backing: API ADAPTER over GET /api/provider plus GET /api/model; unwrap both
            location envelopes and assemble the v1 provider/model projection.

Scope correction recorded before implementation
-------------------------------------------------
The 18/2 expectation above was too broad: it treated available lower-level stores as permission
to invent new v1 semantics. Todo 165 permits shape adapters only where a genuine served `/api`
equivalent already exists. The implemented scope is therefore the following 10 adapters:
- GET /agent -> GET /api/agent
- GET /provider -> GET /api/provider plus GET /api/model
- GET|POST /session -> GET|POST /api/session
- GET /session/{sessionID} -> GET /api/session/{sessionID}
- POST /session/{sessionID}/abort -> POST /api/session/{sessionID}/interrupt
- POST /session/{sessionID}/summarize -> POST /api/session/{sessionID}/compact
- GET|POST /session/{sessionID}/message -> GET message and POST prompt `/api` handlers
- POST /session/{sessionID}/prompt_async -> POST /api/session/{sessionID}/prompt

The existing POST /tui/show-toast local sink remains served. The nine genuine gaps stay explicit:
PUT /auth/{providerID}, POST /log, GET /config, both provider OAuth routes,
GET /session/status, PATCH /session/{sessionID}, GET /session/{sessionID}/children, and
GET /session/{sessionID}/todo. No new auth/config/log/status/update/children/todo/OAuth behavior
was introduced.

Actual coverage is measured=20, served=11, unbacked=9, redirected=0. These values are asserted
against `v1_coverage()`, which derives served routes from `V1_BACKENDS`, the same registration
source used to choose router handlers. `V1_SURFACE.backing` remains a frozen declaration and the
named router witness fails if it disagrees with actual registration.
