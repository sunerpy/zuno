Create a durable goal only when explicitly requested by the user or higher-priority instructions. Do not infer a goal from ordinary work. Preserve the requested objective without narrowing it. Record concrete success_criteria when the request defines them; they are immutable to the model after creation. A goal that changes the workspace needs success criteria, because completing it means closing each one by citing the receipt id printed by the tool result that verified it; without criteria it cannot be completed at all. The result assigns each criterion a short id, such as c1, to cite later. An unfinished goal cannot be replaced. Set token_budget only when the user explicitly requested a positive budget.
