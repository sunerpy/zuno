Read the current goal before changing it and pass its revision as expected_revision. If the revision is stale, read again instead of overwriting concurrent work. `status: in_progress` (or `active`) is only an idempotent confirmation that an already-active Goal is still running; it does not resume a paused or blocked Goal, which requires the user to run `/goal resume`. Model completion cannot close a paused Goal through an independent request; the user can explicitly request native `/goal complete` without resuming it. An optional intent records why the call was attempted. Mark the Goal complete only when authoritative evidence proves every requirement and no required work remains. A user-created Goal with an empty declaration and empty criterion ledger has no implicit checklist, even after changing files; ownership, unfinished work, capability and safety checks still apply. For a declared checklist, close each success criterion in the same call: name it in satisfy_criteria with the receipt id printed by the tool result that verified it, or in waive_criteria with the reason it will not be verified. A goal cannot complete while any declared criterion is still open, and a missing or inconsistent ledger is a contract error. Any edit after a criterion was satisfied invalidates the evidence for it, and the edits the tools report also reopen the criterion, so never read a criterion that stayed closed as still proven: run the check again after your last change and cite the new receipt. Report blocked with a concrete blocking_condition as soon as a true impasse prevents meaningful progress. This stages an observation; the returned Goal remains in its actual state. The host counts completed Goal turns and applies blocked after three matching turns. Do not count three turns yourself before reporting. Repeated calls within one turn do not increase the count; progress or a different condition resets it. Do not use this tool merely because a turn is ending, work is difficult, the budget is low, or more verification remains.

Completion also requires the current native Goal/cycle/actual-turn binding and immutable host snapshot. A fresh expected_revision does not grant authority over an old or unowned Goal, including a blocked Goal left behind by an independent request. Scope checks, criterion changes and completion are atomic; a stale turn cannot waive criteria or complete a different Goal.
