Record what this session believes an external capability can do and how it knows, before configuration that relies on it is written. capability names the feature, such as bedrock:converse:structured_output; subject names what it is claimed about, such as a model id. state is the provenance, not the truth value: documented requires at least one entry in sources naming the vendor document for this exact subject (a URL, a title or a file path); probed requires probeReceiptId, the receipt id printed by the tool result whose request exercised the capability and whose response was observed; inferred means it was concluded from something else, such as a sibling model's documentation; unknown means it has not been checked. Only documented or probed claims may be relied on, and a goal that changes the workspace cannot complete while an inferred or unknown claim recorded under it stands. A write to the workspace retires an earlier probe, so probe again after the last change and record the claim again. Recording the same capability and subject again replaces the earlier claim; record a weaker state when new information retracts one. Never record documented without a citation or probed without a receipt.
