Delegate a self-contained unit of work to the named child `agent` in its own session.
Every call requires five non-empty top-level strings: `agent`, `objective`, `deliverable`, `instructions`, and `success_evidence`. This also applies when continuing with `task_id`.
`intent` is an optional UI label, not the child's objective, and never replaces `objective`. Do not nest the fields under `contract` or use legacy `prompt`, `description`, `subagent_type`, or `load_skills` arguments.

Minimal valid example:
```json
{
  "agent": "explorer",
  "objective": "Locate the tool argument validation boundary",
  "deliverable": "A short report with file and symbol references",
  "instructions": "Trace argument validation without editing files",
  "success_evidence": "Identify the validation entry point and a matching test"
}
```
Choose `agent` from the currently available delegation targets; keep the same five-field shape for other agents. On validation failure, correct the named arguments using the current schema; do not repeat the unchanged call or invent missing outcomes.
Use `scope.include`/`scope.exclude`, `constraints.must`/`constraints.must_not`, and `dependencies` when they materially bound or enable the work.
The child model, reasoning, MCP, Skill configuration, and sandbox inherit from the parent composition and are narrowed by the selected Agent's policy.
The parent retains integration decisions and final verification. Do not duplicate the delegated work in the parent.
Foreground is the default and waits until the child answers. If waiting for that result is the only useful next action, stay foreground; do not detach just to end the parent turn. Use `background: true` only for an explicit parallel split: identify the independent local work you will do while the child runs, then do that work. It returns immediately with a fresh job id, not a completed result. Do not background the sole task and finalize while it runs; keep critical-path work local or use foreground delegation.
Background jobs default to `reportDelivery: "nextStep"`, which adds the terminal report to the parent's next step and wakes it. Use `"quiet"` only when the persisted job result will be inspected separately.
Pass `task_id` from a previous call to continue that same child session instead of starting a fresh one.
Skills are not task arguments; the child can load only skills exposed by its effective Agent capabilities.
Do not create overlapping children unless their `scope` ownership is explicit and non-overlapping.
