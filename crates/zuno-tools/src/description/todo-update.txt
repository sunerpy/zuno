Atomically add, update, or remove durable work items for the current session.
Pass changes as objects tagged with action: add, update, or remove. Updates and removals require the stable id and expected_revision returned by todo_get.
An add may omit id to let Zuno create one. When one atomic batch adds dependent items, assign explicit stable ids to every newly added item before referencing them from parent_id or dependencies; never invent positional ids such as todo_1. Preserve an existing id instead of deleting and recreating an item.
Every referenced parent, dependency, and plan_step_id must exist after the batch. Parent and dependency graphs must be acyclic.
At most one item may be in_progress in a session. Use active_form for the short present-tense activity shown while that item runs.
The whole batch rolls back on any validation or revision error; partial updates are never committed.
This tool changes durable state and is never replayed implicitly after an uncertain failure.
