Executes a command with the configured shell. Commands are parsed with tree-sitter before execution so each constituent command is permission-checked independently. A deterministic destructive-command gate runs before every foreground or background spawn. Confirmable operations such as replacing an existing redirect target require fresh human approval unless the effective permission mode is `allow_all`; catastrophic targets remain hard-denied in every mode. Creating a new static file in the OS temp directory does not require approval. For one-off scripts, prefer interpreter stdin such as `python3 - <<'PY'` over fixed `/tmp` filenames. Every result reports the effective sandbox mode, backend, and network policy. `read-only` and `workspace-write` require a proved OS confinement backend and fail closed when it is unavailable. `danger-full-access` is an explicit trusted choice that runs as the Zuno user with host filesystem, process, credential, and network access, and it makes the effective permission mode `allow_all`; it is never an automatic fallback. Explicit permission denies and catastrophic Shell denials remain terminal without opening an approval prompt. Use workdir instead of changing directories inside the command.

For source changes, prefer native `apply_patch` or structured `edit`, which validate current file bytes or context and report a structured diff. Use `git apply` only for an already-supplied standard unified diff whose provenance and paths you understand: read every affected existing file, run `git apply --check`, and apply it only when that preflight succeeds. Git is not a stale-read or rollback authority. If the check or apply fails, stop, re-read current files, and use a smaller native patch/edit. Do not automatically add `--3way` or `--reject`; never recover with `git reset --hard` or `git checkout --`.
