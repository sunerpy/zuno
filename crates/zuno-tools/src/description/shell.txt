Executes a command with the configured shell. Commands are parsed with tree-sitter before execution so each constituent command is permission-checked independently. A deterministic destructive-command gate runs before every foreground or background spawn. Under approval-bearing permission modes, confirmable operations such as replacing an existing redirect target require fresh human approval; `allow_all` skips that ask, while catastrophic targets remain hard-denied in every mode. Local Git history rewrites (`commit --amend`, a new `rebase`, or forced tag movement) additionally require `expectedGitHead` containing the exact full object id returned by an immediately preceding `git rev-parse HEAD`; execution fails before spawning if HEAD changed. Select that repository with `workdir`: repository-changing Git global options or environment variables are refused for a rewrite. Published history may only be rewritten with an explicit atomic lease such as `--force-with-lease=refs/heads/main:<expected-full-oid>`; bare `--force`, an implicit lease, and `+` refspecs are refused. Creating a new static file in the OS temp directory does not require approval. For one-off scripts, prefer interpreter stdin such as `python3 - <<'PY'` over fixed `/tmp` filenames. Set `backgroundPurpose: "remoteObserver"` when a command only watches work owned by a remote system, such as a CI run or release. Its terminal process state is a durable wake signal, not proof that the remote work succeeded; after wake, inspect output and re-query the authoritative remote state by stable identifier. Every result reports requested and effective sandbox authority, backend, network policy, resolution kind, and any fallback reason. `read-only` and `workspace-write` require a proved OS confinement backend and fail closed by default. A trusted `sandbox.onUnavailable: "run-unconfined"` policy may run a `workspace-write` request with host authority only for a typed platform, launcher-absence, or namespace-availability failure; it never applies to read-only Agents, untrusted launchers, invalid policy or paths, helper/internal failures, or command execution errors. This fallback preserves the configured permission mode, explicit denies, catastrophic-command refusals, background lifecycle, timeout, and cancellation, but requested filesystem and network restrictions are not OS-enforced. `danger-full-access` is a separate explicit trusted choice that skips restricted-backend discovery and runs as the Zuno user with host filesystem, process, credential, and network access. Explicit permission denies, history-rewrite guards, and catastrophic Shell denials remain terminal. Use workdir instead of changing directories inside the command.

For source changes, prefer native `apply_patch` or structured `edit`, which validate current file bytes or context and report a structured diff. Use `git apply` only for an already-supplied standard unified diff whose provenance and paths you understand: read every affected existing file, run `git apply --check`, and apply it only when that preflight succeeds. Git is not a stale-read or rollback authority. If the check or apply fails, stop, re-read current files, and use a smaller native patch/edit. Do not automatically add `--3way` or `--reject`; never recover with `git reset --hard` or `git checkout --`.
