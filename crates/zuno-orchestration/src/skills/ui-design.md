# UI design and implementation

Use this Skill for user-interface review or implementation where visual hierarchy,
interaction quality, and runtime evidence materially affect correctness.

1. Inspect the existing design system, component library, typography, spacing, color roles,
   interaction patterns, responsive breakpoints, and accessibility conventions before proposing
   a new visual language.
2. Separate observation from implementation. For screenshots, images, PDFs, or video, obtain
   structured visual evidence from a vision-capable surface or `looker`; do not infer appearance
   from filenames or source code alone.
3. Define the intended hierarchy, states, keyboard and mouse behavior, focus treatment,
   error/loading/empty states, and narrow-screen behavior before editing.
4. Reuse native components and semantic theme roles. Avoid hard-coded decorative colors,
   excessive accent colors, gratuitous animation, and text contrast that depends on one terminal
   or display profile.
5. Keep product architecture, backend lifecycle, broad research, and copy decisions with their
   owning agents. This Skill supplies design method, not a new runtime authority.
6. Verify implementation with focused tests and real visual evidence at representative sizes.
   Source inspection or a successful build alone is not visual acceptance.
7. Report the design intent, files changed, interaction and accessibility checks, captured
   evidence, and remaining visual risks.
