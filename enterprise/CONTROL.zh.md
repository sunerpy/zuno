# 持久任务取消

`RuntimeControl` 将经过认证的用户取消意图与 Worker 执行权分开。PostgreSQL
在数据所有者中实现接口，API 与 BFF 使用同一服务；浏览器或 ACP 客户端不携带 Worker 租约。

`POST /api/v1/jobs/{job}/cancel`（浏览器使用 `/app/api/v1/...`）接受：

```json
{
  "requestId": "stop-investigation",
  "expectedTurnId": "turn-from-the-job",
  "reason": "不再需要继续这项调研"
}
```

事务重查组织成员、调用应用、资源归属与精确 turn，然后一起记录停止意图、撤销现有
父子任务树的执行权、退役尚未接纳的子任务意图、结算逻辑子结果并安排外部操作取消。
会话锁按父到子的方向获取，与派发一致；遍历期间不能在已处理节点背后追加子任务。
其他会话可以继续调度。

回执中的 `stoppedJobs` 表示逻辑执行权已经撤销，`pendingOperations` 表示仍需网关
核查的外部操作。相同请求取回原回执；复用请求 ID 改变原因、应用或目标会冲突。
`GET /jobs/{job}` 提供 `stopRequested` 和当前仍未确认结束的操作 ID，包含已取消子任务。

已经完成的结果保持完成；原有不确定结果仍为 `Uncertain`，保留保守会话边界。
取消已经完成的父任务会阻止迟到的 `nextStep` 报告，并停止该报告已经接纳的接续 Job；显式用户输入保持独立身份，完成事实仍被保存。
用户可以显式提交新任务，旧 Worker 不能继续提交状态或获取新执行票据。

## 网关执行与回执

网关用独立服务身份领取持久取消队列，只获得分配给自己的不可变操作接纳记录。
读取具体操作时仍应用所有者 RLS；轮询水位让无法确认的环境不会阻塞后续取消。
普通 Worker 票据不开放管理级停止入口。

网关核对本地账本中的操作 ID 和参数，持久记录取消后才请求 Docker 停止。
如果控制面已接纳而网关还未落账，则先保存禁止启动记录，防止迟到提交启动命令。
取消不依赖旧 Worker 租约或原用户成员资格继续有效。

命令先完成时保留真实完成回执，不改写成取消。停止响应丢失后查询原容器；
环境消失或无法核查则保持 `Uncertain`，不会重放副作用。原有完成投递与消费确认机制
保存实际终态并移出待取消列表；重复投递和网关重启不会抹除或重复完成事实。

## 验证与范围

原生测试覆盖运行／排队中的子孙任务、未接纳意图退役、精确 turn、请求去重、跨用户拒绝、
旧租约拒绝、迟到子通知、完成结果保留、撤权与网关重启后的命令停止、以及本地接纳前取消。
PostgreSQL 格式 12 增加作用域控制回执、停止记录、自动接续来源关系和网关投递水位；
固定格式 11 的数据夹具验证数据保留与 marker 更新前的事务回滚。

本批提供 Job／子任务树的逻辑取消。Workflow／Council 协调器控制、管理级排空、
自动撤权策略和审批合并工作区由后续适配器实现，尚未注册相关入口。
企业服务仍仅支持 Linux amd64／arm64；个人客户端保留现有平台范围。
