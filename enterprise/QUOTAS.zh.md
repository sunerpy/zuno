# 企业接纳配额

`QuotaStore` 是数据端的策略接口。PostgreSQL 持久保存租户策略，并分别应用于
每个已鉴权所有者。使用量来自持久 Job 与数据库时间下有效的租约，重启不会重置。

| 资源 | 默认值 | 计数范围 |
| --- | ---: | --- |
| rootSessions | 2048 | 没有父会话的已保留会话 |
| rootJobs | 64 | 尚未完成、失败或取消的用户输入 Job |
| childJobs | 1024 | 已暂存或尚未结束的子 Agent／Workflow／Council Job |
| executions | 8 | 未过期的前台／子任务执行租约 |
| learningJobs | 64 | 排队、运行或不确定的学习 Job |
| learningExecutions | 2 | 未过期的后台学习租约 |

暂停和不确定任务仍占逻辑接纳配额，等待会释放执行容量。子任务使用独立逻辑
限额，父任务等待不会占住子任务执行槽位。持久完成投递不算新的用户请求，
不会因为队列已满而丢失子结果。重复请求先返回原回执，再考虑新接纳配额。

`GET /api/v1/quotas` 返回当前策略及本人使用量。`PUT /api/v1/quotas` 要求
当前有效的组织管理员使用获准审核应用，提交 requestId、expectedRevision 和
完整 limits。策略、审计及幂等回执原子提交。降低配额不会取消已接纳任务或
修改既有预算；新的接纳需等待容量释放。会话计数针对保留的根会话，不代表
自动保留期限或删除策略。

超额返回 HTTP 429 与 quota_exceeded，不消耗输入版本、不创建 Job，也不写入
成功回执。客户端不能机械重放写入，应查看使用量或明确调整／取消任务。SDK
提供 quotas、replaceQuotas，版本以精确十进制字符串传递。

容量检查与执行租约接纳在每个所有者事务中协调，达到上限的用户不阻塞其他
用户。后台学习使用独立持久轮转位置，前台队列为空时仍保持学习领取公平。
学习队列已满时不确认未处理来源水位；已完成提炼可正常结算，维护唤醒留待
容量释放。

PostgreSQL 预览格式 29 增加配额策略／审计和学习轮转位置，迁移时原子补齐已有
组织默认策略，新组织在初始化时生成策略。它补充每 Job 的 token／工具／时间
预算和网关限制，不声称覆盖租户计费、累计存储保留或外部提供商成本上限。
