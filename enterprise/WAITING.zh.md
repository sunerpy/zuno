# 持久调用等待

有界驱动可以通过 `ToolDispatchOutcome::Pending(WaitRef)` 挂起尚未完成的工具阶段。
普通派发仍返回完整的 `ToolDispatchResult`。等待不会写入成功的 `running` 文本，
不会提前结束本 step，也不会先发起下一次模型请求。

这是内部运行时能力。企业启动装配、分布式子任务／Workflow producer、人工审批后的执行、
公共客户端投影仍需分别交付；本次不新增可用 CLI 命令或公共 HTTP 路由。

## 身份与执行

`WaitRef` 绑定稳定等待 ID、原 turn、原调用、规范化参数摘要、等待目标和续接方式。
目标区分审批、用户输入、子 Job、外部操作和数据库时钟定时器。有界驱动消费
`current_turn` 的结果，不会将 `next_turn` 引用静默转换为原轮续接。

检查点 schema 3 保存原模型可见工具声明、编排快照、调用及位置、下一个尚未准备的调用、
等待引用和累计结果影响，同时保留原有提示词、用量、耗时及恢复状态。
不会序列化 Future、提供商对象、取消句柄、租约凭证或控制面目录。

一个派发批次在首次遇到持久等待时停止准备后续调用。前面的独立调用仍并发执行。
后面的调用尚未执行 hook 或申请权限，续接时在当前授权下准备；已经完成的调用不会重新派发。

Producer 负责持久保存准备好的操作、实际参数审批、调用后处理及权威回执验证。
返回一个等待引用本身不具备这些能力。外部操作结果不确定时继续保留核查状态，
不能将其发布成已经确定的完成结果。

## 原子状态转换

1. 工具准备前，模型响应和原始待执行调用已持久化。延期调用保留原 part，不产生工具结果。
2. 驱动将等待标记与检查点一起提交。PostgreSQL 同事务登记归属明确的等待、更新 Job
   检查点及版本、释放执行租约，并将 Job 标记为 `waiting`。
3. 已装配的 `WaitCompletionStore` 发布不可变完成事实。SQLite 和 PostgreSQL 根据
   归属及逻辑等待坐标生成稳定事件 ID。重复通知读取原事件，改变引用或结果则冲突。
4. 登记等待时检查已经到达的完成事实，避免丢唤醒。发布结果后，仅在依赖均已就绪时唤醒
   等待中的 Job。暂停／取消的父任务保留结果而不自动继续。PostgreSQL 定时器采用数据库
   时间和有界的所有者作用域扫描。
5. 下次领取时，驱动准入在同一事务中消费完成事实、按顺序写回原工具结果、推进检查点并释放
   租约。此转换没有模型／工具副作用，因此不单独提交一个中间 `started` 标记。
6. 兼容 Worker 从该检查点继续剩余工具阶段，原 step 完整结束后才可再次请求模型。

完成事实、可发送通知和持久消费是三个不同状态。客户端断线或丢失成功响应不构成消费确认；
下一位 Worker 从 Job 重建已经提交的检查点。

## 恢复与授权

历史修复只保护有效检查点能够完整解释的一组未完成 parts。普通新轮次不能将它们改写为
中断结果或越过有界任务。单独伪造一个等待 metadata 字段不能阻止保守修复。

PostgreSQL 只有在最新驱动事件恰好等于 Job 已提交的检查点、且每个未完成调用都能被解释时，
才允许接管过期领取。出现更新的 `started` 推进、引用变化或无法解释的在途调用时，
继续保留不确定结果。旧租约不能提交新的回合状态；权威完成来源仍可保存真实的迟到结果。

每次接管都会重新检查组织授权，参数审批不会变成租约凭证。原 wall-clock 限额包含等待时间；
执行剩余工具前会再次检查该限额。消费不会新增模型尝试，也不会重置提供商用量、工具次数、
有序上下文刷新和恢复义务。

`WaitCompletionStore` 是宿主服务，不向模型或任意客户端开放；其 provider 必须与回合
存储属于同一事务域。Producer 必须先验证实际操作、子任务或回答。仅增加目标 enum
并不表示人工审批／输入适配器以及取消／恢复 API 已经完成。

## 存储与验证

SQLite 复用有索引的不可变会话事件，稳定核心格式 14 与预览运行时扩展格式 1 分开管理。
PostgreSQL 预览格式 5
增加 `runtime_wait`、强制所有者 RLS、定时器／Job 索引及等待状态；当前 PostgreSQL 格式 8 还保存操作准入／结果、浏览器认证、规范化上下文和输入执行回执，格式 1–7 原子前向迁移。
格式 4 fixture 固定原始回合 DDL 和 source digest，保留消息、签名 metadata、用量、
Job 预算及租约状态。

内核测试覆盖执行器更换、没有提前结果、重复完成和消费响应丢失、原子回滚，以及耗时预算
到期后拒绝剩余工具。真实 PostgreSQL 用例覆盖竞争领取、独立会话、提前完成、定时器、
暂停的父任务、跨所有者拒绝、消费失败后的检查点接管，以及迁移成功／失败。
带认证的 HTTPS 用例通过独立版本化的 Worker 协议（版本 4）传输同一等待及消费。

这些测试尚不能证明独立 Worker 启动、网关与工具装配、分布式子 Agent／Council 编排
或完整企业 UI 已交付。

## 审批就绪

`WaitOutcome::RecheckInvocation` 不携带执行结果或可转交的执行权限，仅适用于审批
目标；审批等待不能发布 `ToolResult`。消费信号时保留原始 pending part 及提供商元数据，
删除等待标记，只恢复最后一个尚未执行调用的准备游标。此前完成的调用保持终态，实际
工具返回结果后才增加工具执行次数。

审批答复与等待登记采用相同的会话锁。答复、请求回执、就绪事实和唤醒在同一事务中提交；
登记时也检查已经答复的审批，避免丢失唤醒。暂停的父任务仍按普通等待规则保留事实。
新 Worker 先消费就绪信号并提交检查点，再按当前权限和预算准备原调用；审批不能恢复
过期或已经被替代的租约。

完成 payload 格式 2 保存类型化 outcome；早期预览的真实工具结果仍可读取、去重，
不重写原事件。旧数据若混淆审批与执行结果则拒绝。Driver 检查点仍为格式 3，Worker
协议版本 4 增加兼容领取与凭证有效期，完成事实的发布属于独立的数据所有者接口。

PostgreSQL 状态所有者与共享 Driver 已接通审批就绪；公共审批端点、生产网关派发、
用户输入适配及取消／恢复接口仍需后续接入。
