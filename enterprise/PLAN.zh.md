## 1. 执行范围与分支发布规则

建设共享 Zuno 内核、可恢复 Agent Worker、独立执行环境及企业 Web，支持根任务、子 Agent、Workflow 节点跨机器执行，并在明确检查点接续。

首期采用 Rust、PostgreSQL、rootless Docker、React＋TypeScript、Entra、HTTP／ACP。Temporal 保留为后续适配器。保留复杂任务、自定义 Agent、Workflow、Council、Goal、Memory 和现有工具语义。

## 2. 架构与公共契约

### 三类运行角色

| 角色 | 职责 |
|---|---|
| 企业控制面 | 认证、授权、审批、状态服务、PostgreSQL 调度、事件投影及 Web 资源 |
| Agent Worker | 运行共享 Zuno 内核、模型请求和有界执行步骤 |
| 执行环境网关 | 管理 Docker 环境、文件与进程操作、输出、取消和回执 |

Agent Worker 与命令执行容器分别管理。执行容器不持有运行数据库凭证、全局模型密钥或 Docker socket。

企业 Worker 通过内部认证的状态 API 访问持久状态；本地模式通过相同接口使用 SQLite。组件由 `HarnessProfile` 装配，共用业务状态机。

### 稳定实体

| 实体 | 含义 |
|---|---|
| `Session` | 长期会话及数据归属 |
| `Turn` | 一轮模型与工具推进 |
| `Job` | 逻辑派发任务，跨 Worker 保持身份 |
| `ExecutionAttempt` | 一次 Worker 领取和推进 |
| `ProviderAttempt` | 一次模型请求及其用量 |
| `Invocation` | 一个逻辑工具调用 |
| `Operation` | 一次实际外部操作 |
| `Environment` | 工作区与执行环境 |
| `WorkflowRun`／`NodeRun` | 固定定义的工作流及节点实例 |

网络请求只携带稳定 ID、逻辑游标、配置快照及资源引用，不传 Rust Future、`Arc`、取消句柄、物理 rowid 或宿主私有路径。

### 核心接口

| 接口 | 责任 |
|---|---|
| `AgentApplication` | 会话、输入、运行控制、审批、历史和订阅 |
| `RuntimeStore` | Job、租约、检查点、等待、完成消费及事件的原子操作 |
| `JobDispatcher` | 派发、路由、容量和公平性 |
| `AgentDriver::advance` | 从检查点推进至下一安全边界 |
| `EnvironmentProvider` | 环境获取、查询、快照、分支和释放 |
| `OperationGateway` | 操作准入、提交、查询、输出、取消和回执 |
| `MemoryPersistence`／`MemoryAuthority` | Memory 状态、原子维护及组织授权 |
| `EventProjector` | 将持久事实和临时进度转换为客户端协议 |

通过 `RuntimeBackendBundle` 装配协调一致的实现。涉及同一事务的能力不能任意跨库混搭。

原有 `ChildTurnHost`、`WorkflowHost` 和完成投递语义继续复用，增加远程派发、持久等待及消费确认，不另建同义任务系统。

## 3. 执行、等待与恢复

### 可恢复驱动

新增有界入口：

```text
advance(ExecutionContext, Checkpoint) -> AdvanceOutcome
```

结果区分推进、挂起、完成、暂停、确定失败和需要核查。

检查点保存执行阶段、配置快照、已消费输入位置、未完成调用及顺序、等待关系、工作区引用、预算累计和执行身份。

定义快照固定，当前组织授权仍需重新检查。Worker 更换不能重置预算，也不能恢复已经撤销的权限。

接续仅发生在明确检查点。无法接管的工具和无有效检查点的旧任务继续采用保守恢复，不自动重放副作用。

### 持久等待与前后台语义

等待类型覆盖人工审批、用户输入、子任务、外部操作和定时器，并明确恢复原 turn 或启动下一 turn。

前台派发：

1. 原子提交子 Job、父调用等待关系和检查点。
2. 父任务挂起，释放 Worker 执行槽位。
3. 子任务持久提交结果。
4. 兼容 Worker 接管父任务。
5. 补齐原始工具调用结果，再继续模型请求。

后台派发仍立即返回 Job 句柄，后续遵循 `nextStep`／`quiet`。前台调用不以 `running` 文本提前结算。

普通工具保留普通结果；持久执行器返回独立的 `Pending(WaitRef)`。历史修复识别有效等待检查点，避免误判遗失结果。

### 执行权与原子边界

分别管理会话执行权、Workflow 协调权和环境写入协调。Workflow 协调锁只用于推进依赖和派发，不锁住全部节点执行。

租约使用数据库时间、Worker 实例身份和递增 epoch。检查点版本、输入版本、策略版本及事件游标分别维护。

必须原子完成：

- 输入接纳、Job／派发记录和事件。
- 任务领取、执行权和 ExecutionAttempt。
- 子任务派发、父等待关系和检查点。
- 挂起／唤醒、等待状态和执行权变更。
- Job 终态、完成信封、父投递记录和 Outbox。
- 父结果消费、工具结果写入和检查点推进。
- Memory 批次、证据、版本、任务结算和维护水位。

外部网络调用不在数据库事务中等待。

### 完成投递

区分：

**结果已提交 → 通知可发送 → 父任务已持久消费。**

网络响应或 inline owner 标记不替代持久消费确认。通知允许重复，消费按稳定完成标识去重。

登记等待时检查已经完成的结果，避免丢唤醒。父任务取消或暂停后仍保存子结果，但不擅自继续执行。

### 外部操作与 Workflow

Docker 网关提供稳定环境 ID、操作提交／查询、输出游标、取消确认、快照和产物引用。`operationId` 不随 Worker 尝试改变，参数改变拒绝复用旧 ID。

旧 Worker 不能提交新操作或覆盖状态；已经准入操作的真实迟到回执仍可记录。

| 故障 | 处理 |
|---|---|
| Worker 丢失，环境仍在 | 重新跟踪原操作 |
| 操作成功，响应丢失 | 查询原回执并补齐结果 |
| 环境丢失 | 恢复可验证文件快照，核查在途操作 |
| 外部效果无法确认 | 保持 `Uncertain` |
| 后端缺少可靠去重／查询 | 不承诺该操作自动恢复 |

Workflow 持久化已展开定义、节点参数、依赖、Job 关联和结果。保留原有并发补位、稳定输出顺序及取消语义。

节点等待释放 Worker 资源，但仍受逻辑节点并发上限约束。父任务等待不能占满子任务所需容量。

写子任务使用独立环境分支，返回补丁或提交，在可审批合并阶段进入父工作区。冲突保留为待处理状态。Council 复用节点调度底座，保留 quorum、期限和综合规则。

同一 Workflow 实例固定一个编排后端；未来 Temporal 实例不再由 PostgreSQL DAG 调度器同时推进。

## 4. 企业边界、Memory 与客户端协议

### 身份与审批

主体、租户、所有者、调用应用及能力范围贯穿 Job、检查点、子任务、Memory 和外部操作。Worker 服务身份与最终用户身份分别验证。

Web 使用 Entra／OIDC 与同源 BFF；外部 API 验证本服务 access token；内部 API 使用服务认证及 Job 范围授权。

审批绑定稳定调用、参数、资源版本、主体和策略版本；执行凭证另外绑定当前租约。Worker 更换不重复申请有效批准，也不扩大原批准范围。

企业默认保留：

- 授权工作区内读取、列目录、搜索的最小白名单。
- 普通命令和修改由发起人确认。
- 高权限和敏感资源操作由指定审批人处理。
- 越权和明确禁止直接拒绝。
- ACP 回复不能替代权威审批。
- 隔离后端不可用时拒绝执行。

### Memory 与数据

复用 v0.10.29 的自动提取、独立维护、证据、版本和撤销机制。

文档、候选、证据、维护水位、学习 Job、缓存及 supervisor 全部作用域化。企业私有自动维护需要独立授权；共享 Memory 写入需要组织审批。`ManagedMemory` 不绕过该边界。

来源失效立即影响召回；关闭未来生成不等于遗忘。Skill 评测及应用保持独立审核。

PostgreSQL 保留格式 12 的原子语义；SQLite 迁移保留已支持旧格式的数据。预览环境迁移不触及正式数据库。

### enum 与 UI

保留六组公共类型：

- `SessionItem`：消息、思考、调用、审批、Plan／Goal、压缩、产物和后台活动。
- `InvocationAction`：文件、进程、Web、Memory、Agent、Workflow 和通用工具。
- `InvocationSource`：内置、MCP、扩展、提供商和外部 Agent。
- `InvocationState`：排队、等待、执行、成功、失败、拒绝、取消和不确定。
- `ContentBlock`：文本、代码、Diff、终端、结构化数据、图片和资源引用。
- `UiAction`：查看、审批、回答、中断及授权恢复。

补充类型化等待、执行位置、隔离事实、拒绝原因、MCP 暴露状态和规范化用量。动态工具与 Agent 名称保持为经过验证的数据。

Rust 生成 Schema 和 TypeScript。公共客户端协议与内部 Worker 协议分开，租约凭证和敏感快照不进入 Web DTO。

继续分离 `CommittedFrame` 与 `LiveFrame`，支持分页、游标补读、去重和快照恢复。

React Web 提供会话工作台、Agent／Workflow 运行图、队列、审批、执行详情、产物、Memory／学习及管理审计。TUI、Web、ACP 共用语义投影；远端命令默认留在企业执行环境。

思考仅展示提供商允许展示的内容，默认折叠；加密块和签名仅用于服务端续接。

### P5 实时进度实施补充

### P4 Workflow 实施补充

Workflow 继续使用原生子 Job、完成信封和等待消费。协调 Job 不进入模型／Worker 队列，控制面短事务推进依赖；当前适配器先准备同网关协调工作区及各节点独立分支，准备过程仍占原父 Worker 槽位，之后前台激活与原等待检查点原子提交。依赖结果作为有来源摘要的数据进入节点实际输入，本地与远端共用图决策。Worker 协议更新至 9，PostgreSQL 预览格式更新至 15；个人 SQLite 核心格式 14 不变。节点视图和审批使用 Rust 生成的公共 enum。分布式 Council、审批合并及剩余 P5–P6 范围仍保留。

### P4 Council 后端实施

Council 已接入原生 `council_run`、Workflow 协调和子 Job，固定配置控制席位、
quorum、逻辑容量、格式修正及模型专用综合。初始席位保留独立工作区；格式修正不能
重放工具，也不能更换模型绑定。队列、审批和修正共享席位期限，综合期限在总期限内
预留，领取与续租不能扩张期限。外部取消回执未确认时保留 `uncertain`，合法迟到回执
不自动恢复父任务。公共 enum 增加 Council 类型、阶段、席位状态和精确期限。

PostgreSQL 预览格式为 16，Worker 协议为 10，检查点 schema 4、网关协议 3 与个人
SQLite 格式不变。精确格式 15 迁移与回滚、格式修正耗尽、quorum、席位／综合超时、
等待释放 Worker、取消、迟到操作回执、替换 Worker 和原调用消费已有本地验证。
原生四角色用例完成两次独立命令审批、一次无工具格式修正和一次无工具综合。

本地共享 gates 已通过，仍需当前提交的预览 CI，尤其 Linux amd64／arm64 原生证据。
原生 review 证据绑定、审批合并、跨网关传输及其他 P5–P6 能力继续按计划实施。
App 设计和 UI 交付继续暂停，后续先使用 Penpot。仅接口及 SDK 随后端交付，
实验 UI 的检查须显式启用，预览归档不打包实验工作台。

### P4 工作区合并实施

已接通原生 `workspace_merge`、来源链检查、人工批准、后台执行及原调用的持久等待。
三方条目比较保留父方独立变化，冲突通过明确选择重新绑定批准；复制到新卷并读回校验后，
卷引用、版本与回执原子发布。网关重启与回执确认丢失不重复应用。取消先到可形成不可启动
的墓碑，不抢占其他操作的槽位。Root metadata 通过隔离 helper 恢复，避免 Docker 对
`.` 条目跳过元数据导致权限变化。

审批前可通过公共 API 查看类型化清单、流式读取前后文本及二进制；独立只读票据检查
当前查看权限，不依赖活跃 Worker 租约，也不能执行工具。SDK 与公共 enum 已更新，
网关后台并发和私有 CA 由配置控制。PostgreSQL 预览格式 17、网关日志格式 4、
Worker 协议 11、网关协议 4；检查点 schema 4 和个人 SQLite 格式保持不变。

本地验证覆盖真实四角色人工审批闭环、二进制查看、跨用户拒绝、未变更路径拒绝、
快照／权限／链接保留、发布回滚、后台恢复、确认丢失重投、迁移与回滚，以及共享 gates。
当前提交仍需预览 CI 的 Linux amd64／arm64 原生证据。来源无法证明的旧／续接子任务
保守拒绝合并；跨网关传输、远程产物存储、卷代次／快照保留、完整恢复与 P5–P6 其余能力
继续实施。UI 维持暂停，整体计划尚未完成。

### P6 归档产物验证

预览发布不再调用不存在的 CLI `smoke`，改为检查 GNU 归档结构、ELF 架构、
归档／二进制 SHA 和版本，再用解包二进制启动隔离控制面、网关与两个 Worker。
原生 fixture 检查四个进程的实际 executable，并在完整执行成功后输出证据。
每平台 `.smoke.json` 绑定源码、产物和工作流 run；seal／promotion 检查归档内的
二进制摘要和运行证据，发布相同产物，不重新构建。

本地 x86_64 release 归档已通过真实角色闭环和 40 次测试模型请求；共享 gates、
16 项归档／发布边界测试和工作流检查通过。Linux arm64 及当前提交的 CI 仍需验证。
这是发布链路修复，不表示 P6 全部完成；发布开关保持关闭，其他运行时验收继续实施。

### P4 初始工作区导入

已接通空根会话的归档声明、流式上传、初始化回执和首轮输入仲裁。用户需通过当前审批
应用发起，控制面固定所有者、配置和目标环境；独立上传票据不能变成执行或读取凭证。
原始字节校验后规范化 UID／GID 为运行用户，保留内容、普通权限及安全链接，复用持久
分叉恢复。上传／初始化未完成时不接纳 Job；就绪环境不能静默重建为空。

相同请求、并发上传及完成后重试返回相同结果，不同参数或字节冲突。初始化开始前可取消，
开始后通过相同归档重试或查询状态恢复。类型化导入视图、SDK 和 artifact 投影已更新；
PostgreSQL 预览格式 18 通过固定格式 17 fixture 验证迁移及回滚。扩展归档头有独立大小
限制，拒绝 sparse 条目。导入操作不批准随后执行的命令。

本地真实角色、迁移、SDK 和共享 gates 已通过，当前提交仍需预览 CI 的两种 Linux 架构
验证。当前导入固定初始化配置，跨网关传输、远程存储、保留／配额／恢复及其他 P5–P6
能力继续实施。UI 仍暂停，未启用预览发布。
