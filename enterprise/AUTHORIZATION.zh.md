# 组织授权与持久审批

身份适配器验证调用者身份；组织策略、资源访问、人工审批和执行权分别校验。
`zuno-permission::enterprise` 提供策略计算，`OrganizationAuthority` 发布存储接口，
`PostgresOrganizationStore` 实现数据所有者侧的原子操作。

这是存储／服务层实现。HTTP／BFF、网关资源解析、Driver 持久等待和唤醒仍需接入；
本次不注册可运行的企业服务器、网关或审批端点。

## 三份应用名单

- `allowedApps`：通过身份验证后，允许访问组织 API 的应用。
- `autoReadApps`：可自动批准最小原生文件／Memory 读取的应用子集。
- `approvalApps`：允许提交人工决定或管理员变更的可信应用，通常为自有 BFF。

普通 API 应用不能拿用户委派令牌自动批准自己发起的请求。白名单应用的命令、修改、
网络操作和外部工具仍需 HITL。MCP 注解及 UI 展示信息不能作为权限依据。

资源越权、明确禁止、文件／进程隔离不可用或未生效会直接拒绝。普通操作由发起人
确认；敏感操作和自动化主体请求必须由另一位当前 Approver／Administrator 确认。
管理员不能绕过隔离，也不能自己批准敏感请求。

策略输入 `PreparedEffectFacts` 没有网络反序列化能力。实际资源访问、版本和隔离事实
必须由网关或已注册处理器解析，不能相信 Worker／模型传来的布尔字段。

## 绑定与执行

批准绑定原生 Job／会话／turn、逻辑 invocation／operation、参数摘要、资源与版本
摘要、发起人和策略版本。Worker attempt／epoch 与这份稳定批准分开。

接纳时校验当前会话租约和组织状态，再原子保存决定与事件。同一操作的相同请求复用
批准；改变参数或资源后复用旧 operation ID 会冲突。人工回复重新核对当前成员身份、
审批应用、策略、审批对象和有效期，并把答案、幂等回执和审计一起提交。并发重复
回复只写入一次决定。

执行前，经过服务认证的网关携带当前事实调用 `check_execution`。数据所有者复核
绑定、发起人和审批人的当前权限、策略、批准有效期和租约。期限来自数据库，不信任
请求中复制的值。有效批准可跨 Worker 复用，但不能授权过期租约或变化后的操作。

`CheckedApproval` 只是状态服务的校验结果，不是 Bearer 执行凭证；网关不能接受
Worker 自己提交的副本作为证明。内部服务认证、操作准入和真实回执仍需网关接入。

过期、拒绝、失效的决定不会自动变成新授权。当前过期请求需用户输入后重新准备
invocation，不宣称支持自动续批。此存储只记录回复，不自行恢复暂停或取消的 Job；
等待关系、唤醒和原工具结果消费由 Driver 集成完成。

## 初始化与管理

`bootstrap_organization` 要求 schema 所有者凭证，只创建一次组织。重复运行不会
恢复已撤销的管理员，也不覆盖策略。管理员稳定身份由部署配置明确给出，不把首位
浏览器访客提升为管理员。

`update_member`、`update_policy` 要求当前管理员通过可信审批应用调用。它们使用
预期版本 CAS，将成员／策略、版本、请求回执和组织审计一起提交。审计失败会回滚
整个变更；重复请求返回原版本，不重复修改。已撤销主体不能借回执重放恢复访问。

组织策略／审计按租户做 RLS；成员、批准和回答回执按所有者做 RLS。用户和 Worker
不持有 SQL 凭据。公开控制器必须先认证并调用这些服务；序列化 scope／lease 不能
作为认证。固定只读函数只解析审批 ID 的路由坐标，不暴露参数，且撤销 PUBLIC 执行。

## 持久化与验证

PostgreSQL 预览格式 3 原子迁移格式 1、2。真实旧格式 fixture 验证会话、输入、事件、
回执，以及带预算字段、输入版本、attempt 历史和 lease epoch 的原生 Job 检查点均保留。
完成 DDL、回填、约束和权限后才更新格式标记。

运行 `python3 scripts/check_enterprise_postgres.py` 验证隔离数据库上的真实 TLS／RLS。
用例覆盖原子成员／策略管理、重复回复、应用边界、指定审批人、过期／撤销、绑定
变化、Worker 交接和两种旧格式升级。策略测试为 `cargo test -p zuno-permission`。

[English](AUTHORIZATION.md) 和[实施状态](STATUS.md)。
