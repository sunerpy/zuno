# 有界 Agent Worker 宿主

`zuno-worker::runtime::WorkerRuntime` 管理执行槽位、兼容任务领取、凭证续租和排空。
`WorkerServiceFactory` 为每个 Job 提供固定配置、ProviderRegistry、模型／Agent
解析器、工具派发器、共享 `AgentDriver`、预算策略及执行环境可见目录。
运行时调用已有 `AgentDriver::advance`，继续使用原有循环和任务身份。

`zuno-enterprise` 已将此组件与原生提供商和网关工具装配为独立进程，见[部署](DEPLOYMENT.zh.md)。
个人 TUI／ACP 的平台支持范围不变，详见[平台边界](PLATFORMS.zh.md)。

## 领取与有效期

内部 Worker 协议 9 要求每次领取携带协议版本和有界、非空的配置引用集合。
PostgreSQL 在取得会话执行权前，匹配配置 ID、版本和 SHA。配置不兼容的 Worker
不会抢走任务，旧协议也会在领取前被拒绝。配置匹配只负责路由，工作负载认证、
租户和当前组织授权仍需独立检查。

凭证响应携带剩余有效期。Worker 在发出 HTTP 请求前启动单调时钟计时，保守扣除
响应延迟；续租间隔最多为剩余有效期的三分之一。服务初始化、输入物化和模型推进
全部处于续租保护内。等待续租响应期间仍推进当前 Future；过期或续租失败即停止。
失败 POST 不机械重发，失去执行权也不产生虚假的成功结果。数据库时间及当前 epoch
继续决定每次持久写入是否有权提交。

同一领取的续租与最终检查点／finish POST 串行执行。检查点事务先释放数据库租约，
HTTP 响应才返回；并发续租不能把这段正常交还误判为丢失执行权。收到校验通过的确认后，
本地领取退休，不再续租。提交响应未知或失败仍不授权重放。

进入最终 POST 后，本地同时关闭新的状态与网关操作准入。如果确认晚于旧凭证期限返回，
Worker 最多等待 30 秒接收这一条响应。该等待不延长执行权：内核的模型／工具片段已结束，
数据库提交仍在事务内校验期限。收不到响应时保留“边界未确认”，不重复 POST。

根输入携带数据库接纳时间和稳定 ID，Worker 更换后复用相同时间与 part 标识。
历史已记录和模型已应用仍是两个独立持久事实。检查点 schema 4 区分未提交与已提交等待，
schema 3 仍按未提交状态兼容读取，累计预算不重置。

内部 finish 路由仅接受受租约约束的失败、取消或不确定状态。成功必须由共享内核的
原子结算路径提交，不能通过该路由直接构造。

## 容量、排空与恢复

每次领取的有界推进占用一个槽位。共享内核提交推进或等待检查点后释放槽位；
其他兼容 Worker 可以继续，持久等待不要求原 Future 常驻。

停止时不再领取新任务，并可中断正在等待的领取请求；已开始的推进在配置期限内排空。
超过硬期限后中止剩余 Future，保留持久 started／operation 记录供保守恢复。
停止进程不会自动重放外部副作用，也不会声称副作用已经完成。

临时事件属于当前执行尝试，历史事实从状态服务读取。UI 连接的快慢或断开不能决定
Worker 的权威生命周期。Observer 回调只进行非阻塞入队，不等待网络。Profile 持有
事件发送端不会延长已提交推进的生命周期；结束时只对已缓冲的临时事件进行有界排空。

## 验证与剩余装配

`python3 scripts/check_enterprise_postgres.py` 通过真实 PostgreSQL 和校验证书的 HTTPS
运行两个 WorkerRuntime 实例。配置加载和模型响应均超过初始租期，测试验证续租、
检查点接续、原输入和工具恰好一次、领取前的协议／配置拒绝，以及续租失败后不再派发。
两个实例仍在同一测试进程中，这不是独立进程部署证据。

Docker runner 另外验证真实控制面、网关与两个独立 Worker 可执行进程，通过真实模型传输
完成审批／回执链。远程取消与其余 P3–P6 验收仍需继续完成，预览发布保持关闭。
